### 业务效果上的保留意见

三点如实说明，不粉饰：

1. **换手率 45% 是描述性数字，不是"变好"的证据。** 它只说明排序确实变了。
   变得更好的依据是上面那三个方向性指标，不是换手率本身。
2. **首屏类型数没变（6 种）。** 改造前已经是 6 种，这一项没有增量。真正的
   增量在筛选器——用户现在能主动按类型筛，而不是被动接受混排结果。
3. **分类仍有个例错误。** 例如「美法院推翻特朗普关税并改征新税」被标成
   🪙加密（应为 macro_policy）。这是 LLM 分类的个例误差，不是系统性偏差，
   本期没有专门治理。

## 三、交付内容

### 打分模型：从五因子加权改成两段式

```
BaseScore  = 0.26·M + 0.16·B + 0.16·T + 0.14·I + 0.10·H + 0.10·A + 0.08·Q
FinalScore = BaseScore × (1 + 同向加成 + 反转加成)      // 合计封顶 +50%
```

新增两个基础因子：

- **B 广度**：LLM 出五档枚举（跨市场 1.0 / 大盘指数 0.8 / 板块 0.6 /
  多资产 0.35 / 单一标的 0.15）后映射。不让模型直接打 0-1——枚举的判据能
  写清楚、能复核，连续分只会得到一堆 0.7。
- **I 冲击力**：0.65×数值幅度 + 0.35×权威共振，**纯计算零 LLM 调用**。
  原始描述里的"对社会经济重大影响"刻意没做——已被 M 和 B 覆盖两遍，
  再单列就是三重计分。

两个加分项是**查询时的外层倍率，绝不写回 `importance_score`**：它们依赖每天
都在变的大盘情绪，写进库会让跨天的分不可比，而 `importance_score` 是策略
实验室、去重、历史分析共同依赖的口径。两个系数都调 0 即退回纯基础排序，
这也是验证它们真实贡献的 A/B 对照方式。

**反转加成的 tier ∈ S/A 硬约束**是它成立的前提：没有这个约束，大盘单边时
所有反向噪音都会被扶上来，反而更乱。只有"重大且与大盘反向"才是真信号。

### 处理优先级队列

P0 权威大盘媒体 → P1 dxFeed 大盘 ETF → P2 加密头部 → P3 其他 → P4 dxFeed 个股。
消费按 `ORDER BY priority ASC, fetched_at ASC`，CNBC 这类内容不再排在几千条
积压后面。批量 400 → 800/轮。

### 新闻类型标签与筛选器

`market_scope` 对外正名为「新闻类型」：加密 / 美股 / 港股 / 日股 / 韩股 /
经济政策 / 社会信号 / 综合。前端 chip 带实时计数，卡片上"未标注"清零。

「社会信号」按确认的边界实现：地缘冲突、自然灾害、社会事件，**只收有明确市场
传导路径的**（油路、供应链、风险偏好、制裁、央行反应）。明星八卦、体育赛果
不收——低信息量内容，无论听起来多戏剧化都判 D 档。

### 策略实验室

- 滑杆分两组：**基础因子**（归一化 100%）与**加分项**（外层倍率上限）。
  刻意没有复用同一个组件——归一化和不归一化混在一起，会让"拖高同向 →
  其它因子被稀释"这种完全错误的反馈出现在界面上。
- 点任意一行**展开正文 + 逐因子明细**。因子表三列：原始分、权重、
  **加权贡献**——只给原始分用户还得自己心算乘权重，贡献值才直接回答
  "这条是被哪个因子推上去的"。底部显式写出两段式算式。

### tab07 监控看板

24h 抓取量 / 待处理积压 / 处理速度 / 最老待处理年龄 / 失败率；已入库量与
S+A 有效量按**整体 / 加密 / 非加密**三档拆开；另有按优先级的积压表与最近轮次表。

## 四、过程中发现并修掉的四个真实缺陷

这一节是本报告里最该看的部分——它们都不是"新写的代码有 bug"，而是**已经在
线上跑着、但没人发现**的问题。

### 1. 87% 的排序分是用废弃公式算的（影响最大）

按当前公式给全库反算并比对：新七因子吻合 402 行、旧五因子吻合 1865 行、
两者都不吻合 907 行。**3174 行里只有 13% 的分是按现行公式算的。**
前端按 `importance_score` 排序，等于把三个公式算出来的分放在一个列表里比大小。

这件事如果不先修，本期"排序变好了吗"的业务测试就是假的——测出来的差异有
很大一部分只是"哪些行碰巧被新公式重算过"。

`scripts/rescore_factors.py` 三阶段修复：LLM 回填 breadth_level（2776 条，
唯一花钱的一步，约 $6）→ 离线重算 score_punch → 重算 importance_score。
**刻意不重算 T 和 H**：它们依赖"现在几点"，离线重算会把历史事件的时效分
统统刷成"很旧"，制造出本期改动之外的新变化，让对比失去干净的对照。

修完：3168/3168 全部吻合当前公式，广度零缺口。

根因也修了：跨轮归并的 UPDATE 刷新了 `score_punch` 却漏了 `score_breadth`，
导致老行永远补不上广度，在实验室重算时按最低档 0.15 计——一个 0.16 权重的
因子被静默打到地板。改成 `COALESCE(旧值, 新值)`，只填空不覆盖。

### 2. A 股关键词黑名单，一天漏了三次

- 裸的 `上证` 漏网 →「亚太股市重挫 上证失守3800」排到策略实验室**第 1 名**
- `A股` 带 IGNORECASE **误杀美股**——任何以字母 a 结尾的公司名 + "股" 都命中，
  实测打掉「Meta股价财报前跌近10%」「Cathie Wood买入Meta股票」
  「GE Vernova股价目标」。**美股偏少恰恰是本期要解决的问题**
- 裸的 `创业板` 漏网 →「创业板半日重挫5.37%」排到主站首屏**第 3 名**

结论是穷举措辞这条路走不通。改成双闸：关键词退回 LLM **前**的省钱粗筛
（补全简称 + 加前瞻断言修误杀），新增 `market_scope = cn_a_share` 做 LLM
**后**的语义闸。给 A 股一个正确的名字再整类丢掉，比把它从枚举里拿掉、
逼模型塞进 general 更可靠。实测：创业板/上证 → cn_a_share，日经 → jp_stock，
恒生 → hk_stock（港股没被误伤）。

另外，`filter_a_share` 查的是**原始标题**，而 LLM 会改写标题——
「A股低开，长鑫跌7.7%」的原文是 BlockBeats 关于长鑫存储的快讯，
一个"A股"都没有，是模型自己写出来的。所以 LLM 后必须有一道闸。

### 3. 关水龙头不等于清管道

币安广场（无发布时间，是之前陈旧新闻事故的源头）已经关了抓取开关，但
staging 里还压着 119 条历史存货，流水线照常把它们捞出来送进 LLM 并入库，
QA 红线因此重新亮红。消费端加 `DISABLED_SOURCES` 黑名单，两头都堵。

### 4. 前端 10 处过时文案

tab01 上还写着"每 2 天 1 次自动运行"（实际每小时）和"五因子重要性打分"
（实际七因子 + 两加分项）。这类文案不是装饰——它是对外讲方案时的依据。

## 五、已知限制

1. **分类个例误差**：`market_scope` 偶有错标（如关税新闻标成加密）。个例，
   非系统性，未专门治理。
2. **社会信号量少**（19 条）：类型已经跑通，但召回侧还没有针对性的 query
   在找这类内容，目前全靠其他渠道顺带带回来。
3. **首屏类型数没有增量**：改造前后都是 6 种。增量在"能主动筛"，不在"更多样"。
4. **积压仍在消化**：待处理约 2400 条，按每小时 800 条约需 3 小时追平。
   优先级队列保证高优先内容先出，不影响首屏质量。
