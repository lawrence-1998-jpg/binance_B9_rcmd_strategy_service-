# 对《b9-llm4rec 推荐结果评测报告（2026-08-02）》的评审

**评审范围**：仅文档级。`src/llm4rec/` 代码与 `r1785668259755` 那一轮的 active set 都不在手上，
所以下面只做两件事——**复算报告自己表格里的数**，以及**检查结论强度与证据强度是否匹配**。
凡是我复算过的，都标了出处；凡是我无法验证的，明确写"无法验证"。

**一句话总评**：方法论透明度值得肯定（开篇就声明没有 ground-truth、正文还自我更正了一处误判），
但**汇总表那 5 个 ✅ 的结论强度远超它的证据强度**，其中 3 个 ✅ 是给"没跑的组件 / 降级路径 / 没算的指标"打的。
按现状，这份报告**不能作为"上线没问题"的依据**。

## 一、先说三个可复算的硬错误

### E1　sector 数数错了：不是 13/15，是 **11/17**

报告正文两处写"13 个有内容的 sector，15 个空"（§1 开头、总结表第一行）。
按它自己那张 28 行汇总表逐行数：

| | satisfied | empty_valid |
|---|---|---|
| 报告声称 | 13 | 15 |
| **实际** | **11** | **17** |

satisfied 的 11 个是：AI、Gaming、Infrastructure、Layer1_Layer2、Meme、Payments、defi、
mining-zone、pow、stablecoin、tCommodities。§1 那张"相关性"表本身也只列了 11 行，
**表和正文自己就不一致**。

影响：空板块占比不是 54% 而是 **61%**。这个数字是全报告最重要的信号，被低估了 7 个百分点。

### E2　汇总说"无 ROUNDUP 混入"，但它自己的表里有 2 条

总结表：`Genre suppression | 启发式判断无 PROMO/ROUNDUP 混入 | ✅（目测）`

而明细表里 `genre_hint` 实际命中（按去重事件计）：

| genre_hint | 事件数 | 具体 |
|---|---|---|
| PRICE_NOISE? | 3 | OpenAI Astra／存储芯片股泡沫／**ANSEM 下降楔形突破指向60%上涨空间** |
| ROUNDUP? | 2 | 本周财报季六大科技巨头市值波动／Bitdeer 出售本周开采的全部 271.3 枚 BTC |

"无 ROUNDUP 混入"与自己表里的 2 条 ROUNDUP? 直接矛盾。

### E3　§问题1 与结论互相打架

- §问题1（🟢）："defi rank1/2/3 是三条完全不同的新闻…**defi 干净**。"
- 结论最后一句："**defi 的重复**是 Fix B 待生效的预期（发版后解决）。"

这是典型的**上一版草稿的结论没跟着更正一起改**。正文已经推翻的判断，在结论里还活着。
（建议流程上加一条：任何一处更正，必须回头扫一遍摘要/结论段。）

## 二、结论强度 vs 证据强度：5 个 ✅ 里有 3 个站不住

### C1　**整轮评的是降级路径，不是主路径** ← 最要命的一条

28 个 sector + macro，**无一例外**都是 `fallback_level: 2, stale: True`。
也就是说 L1 全部没命中、全部落到 L2 authority 且超出 fresh window。

**这意味着这份报告的每一个 ✅，都是打给 fallback 输出的**，不是打给线上主路径的。
报告把它放在 🟡问题4，一句"发版后看是否变 fresh"带过——**这个应该是标题，不是第 4 条小注**。

在 fallback 路径上"排序合理、相关性好"，推不出主路径也好；反过来也推不出主路径更差。
**这轮数据对主路径的信息量是零。**

### C2　6 个 rubric 指标一个都没算，却给了 5 个 ✅

报告开篇（和 §人工评判的告示）都明确写了：NDCG / relevance_gate_precision /
empty_correctness / supply_FP / genre_suppression / duplicate_rate **都需要标注样本才能算，
这里只是目测**。

诚实，值得肯定。但接着那张总结表用的是 ✅ 这种"通过/不通过"符号——
读的人（尤其转手第二遍之后）会把它当成"指标过了"。
**没算出来的指标，正确写法是 N/A + 阻塞原因，不是 ✅（目测）。**

### C3　genre_scorer 这轮**根本没跑**（`genre_scored_events=0`），却给了 Genre suppression ✅

报告自己在 §问题5 写了这一条。抑制器没执行，就不存在"抑制得好"这回事。
这一格必须是 **N/A（组件未执行）**。

## 三、最大的信号，被当成优点写掉了

### F1　61% 板块空 + 槽位填充率 30% + 全图只曝光 21% 的库存

我按明细表复算：

| 指标 | 值 |
|---|---|
| 空板块 | **17 / 28 = 61%** |
| sector 槽位填充率 | 25 / (28×3) = **30%** |
| 全图去重后曝光的事件数 | **28 条**（active set 135）→ **21%** |

报告把它记成 ✅「正确返回 empty_valid（宁缺毋滥）」。

**问题在于"空得对不对"恰恰就是 empty_correctness——报告自己承认没算的那个指标。**
把一个未测量的量断言为"正确"，是这份报告最实质的方法论问题。而且直觉上很可疑：
在 135 条加密新闻的池子里，**Solana、RWA、NFT、newListing、Launchpad 颗粒无收**，
更像是**打标/召回覆盖不足**，而不是"确实没有相关内容"。

这条不改，"宁缺毋滥"和"根本没召回到"在报告里长得一模一样。

### F2　`satisfied` 名不副实，正是 supply_FP 想抓的东西

11 个 satisfied 里 **6 个没填满 3 条**：Gaming(1)、tCommodities(1)、Infrastructure(2)、
Meme(2)、mining-zone(2)、pow(2)。

而且 5 条分数 <0.30 的条目照样进了榜：

| 场景 | rank | score | 标题 |
|---|---|---|---|
| Infrastructure | 2 | **0.1355** | DFK Chain 停运 |
| Payments | 3 | 0.1948 | AI 钱包代理需要支出政策 |
| Layer1_Layer2 | 3 | 0.2288 | DFK Chain 停运 |
| Meme | 2 | 0.2375 | ANSEM 下降楔形突破… |
| tCommodities | 1 | **0.2891** | OPEC+ 增产配额 |

`satisfied` 实际语义是"≥1 条过了硬门"，不是"这一屏填好了"。报告照单全收，还替
0.1355 那条辩护说"不算 FP"。**一个 0.1355 也能过的硬门，需要说明它到底门在哪里**——
要么阈值远低于分数量纲，要么就是在拿弱条目凑数。这正是 supply_FP 指标的用武之地。

### F3　两个板块**呈现内容完全相同**

复算各 sector 的事件列表：

- `mining-zone` ≡ `pow` → 两者都是 `[3aca5123, 575a2dd9]`，**完全相同**，分数也几乎一样（0.4231/0.4230、0.3545/0.3467）
- `Infrastructure` ⊂ `Layer1_Layer2`（2/2 重合）
- `Gaming` 唯一那条也同时在 Infrastructure 和 Layer1_Layer2 里

报告 §问题3 用"macro 全量合成无准入，跨场景是设计预期"解释了跨场景重复——
**这个解释对 macro↔sector 成立，但对 sector↔sector 不成立**。
用户翻 mining-zone 和 pow 两个板块，看到的是一字不差的同一批内容。
这该是产品问题（板块定义重叠 or 需要板块间打散），不是"设计内"。

### F4　一条真的 PRICE_NOISE 被当成误标丢了

§问题5 解释启发式误标时，只谈了 macro rank3（OpenAI Astra）和 rank6（存储芯片股泡沫）——
这两条判为误标我同意。

**但 Meme@r2 的 `2306f840` 从头到尾没被讨论过**：

> ANSEM转入BitGo冷钱包提振乐观情绪，**下降楔形突破指向60%上涨空间**

"下降楔形突破指向 60% 上涨空间"是标准的技术形态价格预测，这是 PRICE_NOISE 的**真阳性**。
报告用"没有明显的 PRICE_NOISE/PROMO 混入"一句把三个 flag 一起盖过去了，
其中两个是误标，第三个不是。

方法论上还有一层：**用一个自己刚宣布不可靠的启发式去证明"不存在"**——
过报（false positive）说明它松，但完全没检查漏报（false negative）。
不可靠的检测器，它的"没报警"不能当证据。

## 四、rubric 覆盖不到、但更该有人拍板的一条

**macro rank 1 是「6.76 亿美元从与伊朗关联的交易所流入币安，迪拜此前已对该交易所处罚」。**

在币安自家产品的宏观榜**首位**，挂一条关于币安自己涉制裁关联资金流的报道。
报告给的是 ✅「重大资金流 + 合规」——**从相关性维度看没错**，
但这是**产品/合规/公关决策**，现有 rubric 六个维度里没有任何一维能表达它。

不是说必须撤掉（真新闻该不该压，本来就有两派意见），而是：
**这类"关于自家平台的负面/敏感报道"应该有明确的处置口径**，
由产品/合规拍板，而不是让排序分默默决定它在首位还是第十位。
建议在 rubric 里补一维（比如 `self_reference_risk`），至少让它可见、可审。

## 五、还缺的两块（方法论）

1. **N=1**。只有 `r1785668259755` 一轮。没有方差、没有趋势，任何"整体好"都是单点观测。
2. **没有事件时间列**。`stale` 说的是**缓存新鲜度**，不是**内容新鲜度**，两者极易混淆
   （这个坑我们自己踩过：聚合器伪造发布时间导致旧闻上首屏）。
   没有 event_time / age 列，报告在结构上就检测不出"旧闻被排上来"这个失败模式。

## 七、报告做得好的地方（不要在返工里丢掉）

- **开篇就声明没有 ground-truth，且反复重申**。这比很多"看起来很量化"的报告诚实得多。
- **自我更正了 defi 的误判**（§问题1），并写清了误判是怎么来的（把跨场景的 `8d99edbe` 记成了 defi 内重复），
  还附了 event_id 和 evidence_post_ids 让人能复核。这是很高标准的做法。
- **🟢/🟡 分级**、`empty_reason` 透传、跨场景重复单列一节 —— 结构本身是对的，
  问题出在"结论比证据走得远"，不在框架。

把上面第 1、2 项补上之后，这份报告的框架足以支撑一次真正的上线判断。
