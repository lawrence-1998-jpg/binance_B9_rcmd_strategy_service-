# Skill：Macro Insight 宏观热点新闻推荐 · 完整排序方案（v1）

> **模块定位**：给定全市场候选新闻池，AI 对每条内容**打标签 → 打分 → 超重去重 → 体验混排**，最终召回对整个加密市场最重要、信噪比最高、不重复的新闻流。
> **版本**：v1 · 五因子纯加权 · 无相关性因子 · 无硬门 · 连续打分 · 语义去重（cosine≥0.82，实测标定）· 保底 3 条
> **输出体验**："看宏观 → 抓全市场最重要且不重复的信号"
> **与 Sector Insight 的关系**：同一 widget 的姊妹 Tab。Sector Insight 回答"这条新闻和板块相关吗"；Macro Insight 回答"这条新闻对整个市场重要吗"。前者是相关性驱动（硬门+乘子），后者是**纯重要性驱动（无硬门、加权求和）**。

---

## ★ 首要原则：按重要性排序，而非按时间强排

**线上核心病因：候选池仅按发布时间倒排，导致大量不重要信息（人事变动、公关软文、重复报道）占据头部位置。**

1. 排序的唯一目标是"**这条新闻对整个加密市场的重要程度**"。时间只是衰减因子（时效 T），不是排序主键。
2. Macro Insight 是全市场新闻流，**不做相关性硬门**——所有进入宏观候选池的内容默认具备"加密市场相关"资格（候选池准入由上游内容库负责），排序层只解决"谁更重要"。
3. **保底出条**：与 Sector Insight 的"宁缺毋滥（0~3 条合法）"不同，Macro Insight 是主新闻流，**每个刷新周期至少出 3 条**；候选不足时按 Score 顺位放宽 Quality 次序阈值补足，但去重规则永不放宽（重复比低质更伤体验）。
4. 产品依据：线上截图显示 K25.ai 融资一事以 3 个信源出现 3 次、且"某负责人离职创业"类弱重要性新闻排在头部——按时间强排 + 无去重是两大病根，对应本 skill 的"重要性主排序 + 激进去重"两大主设计。

## v1 设计说明（基于 2026-07-23 线上截图 badcase）

| 线上 badcase 类型 | 典型案例 | v1 对应设计 |
|---|---|---|
| 同事件重复（1 事 2~3 条） | K25.ai 完成 A 轮融资 ×3（MarsBit/ChainCatcher/PANews 三源三条，其中两条仅大小写差异） | 激进去重：标题归一化 + 三元组无条件归簇 + embedding cosine≥**0.82**（2026-07-26 实测标定，见第三章）+ 输出前自检断言 |
| 未按重要性排序 | "混元多模态负责人离职创业"（人事变动、非加密核心）排第 1，BitMEX 正式关闭（交易所级事件）排第 5 | 市场影响面 M 为最高权重主因子（0.35），事件级别锚点：监管/宏观政策/交易所级 > 项目级 > 人事变动 |
| 标题党/软文噪音 | 融资通稿式标题、公关措辞 | 新增信噪质量因子 Quality（0.15）：AI 检测标题党、公关软文、语义空洞，低噪音干货给高分 |
| 弱加密相关的泛科技新闻 | AI 公司人事新闻出现在加密宏观流 | M 因子内置"加密传导强度"子信号：无明确加密市场传导路径的泛科技事件 M≤0.25 |

## 〇、打分公式（本 skill 的核心）

**纯加权求和，无硬门、无外层乘子**：

```
Score = 0.35×影响面M + 0.20×时效T + 0.15×热度H + 0.15×权威A + 0.15×质量Q
```

**后置去重**：同一事件只留 1 条（三元组精确归簇 + cosine≥0.82 语义兜底）→ 体验混排 → 按 Score 输出，**至少 3 条**（上限由前端容器决定，建议 ≤10 条）。

权重记忆：**影响面 0.35 独大**（重要性主因子）> 时效 0.20 > 热度 0.15 = 权威 0.15 = 质量 0.15，合计 = 1.0。

### 为什么不做硬门、不做相关性因子？

- Macro Insight 的候选池已经是"全市场加密新闻"，准入资格由上游内容库解决，排序层不重复设卡。板块页需要回答"配不配"，宏观页只需要回答"排多前"。
- 硬门的代价是空输出风险。Macro Insight 是 widget 的主新闻流，必须稳定供给（保底 3 条），做硬门与产品定位冲突。
- 但**去重不妥协**：宏观流内容量大、信源多，同一事件多源报道概率远高于板块页，所以去重必须做满四层。注意召回由 DC-2 三元组精确匹配保障，向量阈值反而要偏高保精度（0.82，实测标定见第三章）。

### 为什么影响面给 0.35 独大？

- 用户看宏观新闻流的核心诉求是"今天市场发生了什么大事"，重要性 = 排序的第一性原理。线上按时间强排的病根就是没有任何因子度量"重要"。
- 0.35 大于任何其它两个因子之和的一半，保证重大事件（M≈0.9）即使时效稍旧也能压过新鲜但琐碎的内容（M≈0.2）。

### 为什么新增质量 Q 因子（Sector Insight 没有）？

- 宏观流候选池未经板块相关性过滤，标题党、公关软文、语义重复的"水文"密度远高于板块页。Sector Insight 用体裁标签（genre）做前置过滤即可；宏观流不能硬淘汰（保底供给），所以把"信噪质量"做成连续因子参与排序——低质内容不淘汰但沉底。

## 一、因子总览

| 因子 | 角色 | 打分方式 | 数据来源 | 核心作用 | 常见误判 |
|---|---|---|---|---|---|
| 影响面 M | 🔑 主因子 0.35 | 连续 0~1，事件级别×市值规模×传导强度 | 事件类型库 + CMC/CoinGecko 市值 + 历史波动 | 度量"对整个加密市场重要不重要" | 泛科技事件误判高分、微型项目事件虚高 |
| 时效 T | 0.20 | 连续 0~1，指数衰减 e^(-λΔt) | 真实发布时间戳 | 新鲜度，防旧闻霸屏 | 旧闻被转发误判为新事件 |
| 热度 H | 0.15 | 连续 0~1，log 压缩 | 社交互动 + 独立信源数 | 传播广度，市场关注度 | 刷量伪热度 |
| 权威 A | 0.15 | 连续 0~1，信源分级×验证 | 媒体分层库 + 官方域名校验 | 可信度，砍谣言 | "权威词汇"诱导 |
| 质量 Q | 0.15 | 连续 0~1，AI 检测标题党/软文/语义密度 | LLM 质量判别器 | 信噪比，干货沉浮 | 深度长文被误判为"啰嗦" |

## 二、因子详解

### 2.1 影响面 M（Market Impact，权重 0.35，主因子）

**定义**：这条新闻对**整个加密市场**的影响广度与深度。注意是全市场维度，不是板块维度——一条对某小板块很重要的新闻，如果对全市场没有传导，M 不应高。

**M 由三个子信号构成，取加权融合（0.4/0.3/0.3）**：

**子信号 1：事件级别 EventTier（0.4）**

| 级别 | 事件类型 | EventTier 锚点 |
|---|---|---|
| S 级 | 主权级监管/立法（美 SEC/国会法案、主要经济体全面禁令或开放）、美联储利率决议、头部交易所倒闭/关停/被诉、BTC/ETH 协议级重大事件、ETF 通过/否决 | 0.9 ~ 1.0 |
| A 级 | 大型机构进出场（主权基金/上市公司建仓）、头部稳定币异动（USDT/USDC 脱锚/增发异常）、Top10 币种协议升级/安全事故、交易所重大产品/规则变更 | 0.7 ~ 0.85 |
| B 级 | 中型项目融资/上线/升级（市值 Top11~100 或融资 ≥5000 万美元）、知名机构研报与预测、国家级但非主要经济体的政策 | 0.4 ~ 0.65 |
| C 级 | 小型项目动态（市值 Top100 外、融资 <5000 万美元）、KOL 观点、数据周报 | 0.2 ~ 0.35 |
| D 级 | 人事变动（除头部交易所/基金会一把手外）、公司内部组织调整、非加密的泛科技动态 | 0.05 ~ 0.2 |

> **判例（线上 badcase）**："混元多模态理解负责人胡瀚离职创业"——人事变动 + 泛 AI 而非加密，EventTier 落 D 级 0.1；即使时效满分，Score ≈ 0.35×0.15 + 0.20×1.0 + … ≈ 0.45，排不进头部。线上它排第 1，就是没有 M 因子的直接后果。
> **判例（反向）**："BitMEX 将于 9 月 23 日正式关闭"——头部衍生品交易所关停，S 级 0.9。线上排第 5 位于人事新闻之后，属于严重的重要性倒挂。

**子信号 2：受影响市值规模 ScopeFactor（0.3）**

继承 Sector Insight v5.1 的"先查市值再打分"铁律，但换成全市场口径：打分前**必须**查询事件主体的市值（CMC/CoinGecko/币安行情）与直接受影响资金规模，估算 `affected_capital_usd`。

| 受影响规模 | ScopeFactor |
|---|---|
| 全市场级（BTC/ETH/稳定币/宏观政策，>$100B 敞口） | 0.9 ~ 1.0 |
| 大盘股级（Top10 币种、头部交易所，$10B~$100B） | 0.7 ~ 0.85 |
| 中盘级（Top11~100，$1B~$10B） | 0.4 ~ 0.65 |
| 小盘级（$100M~$1B） | 0.2 ~ 0.35 |
| 微型（<$100M） | ≤ 0.15 |

> **判例（继承 BC-5.3）**：微型稳定币 Balance Coin 被攻击归零——事件戏剧性强，但受影响资金仅百万美元级，ScopeFactor ≤0.15，M 整体被压至 ≤0.3。宏观流同样适用：戏剧性 ≠ 重要性。

**子信号 3：加密传导强度 TransmissionFactor（0.3）**

事件到"加密资产价格/流动性/合规环境"的传导是否明确：

| 传导路径 | TransmissionFactor |
|---|---|
| 直接传导：事件主体就是加密资产/交易所/协议，或政策直接约束加密行业 | 0.8 ~ 1.0 |
| 一层传导：宏观流动性事件（美联储、美元指数、美股大盘）→ 加密风险偏好 | 0.4 ~ 0.7 |
| 弱传导：泛科技/AI/其他行业事件，需要 ≥2 层推理才能触达加密市场 | ≤ 0.25 |

> **防御规则**：泛科技新闻（Web2 AI 融资、大厂人事）没有明确加密传导路径时 TransmissionFactor ≤0.25，这会把 M 整体压到 ≤0.25——不淘汰（无硬门），但天然沉底。

### 2.2 时效 T（Timeliness，权重 0.20）

**定义**：基于**事件真实发生时间**（非抓取时间、非转发时间）的指数衰减。

```
T = e^(-λ·Δt_hours)，λ = ln2/24（半衰期 24h）
```

| 事件距今 | T 值 |
|---|---|
| <1h | ≈1.0 |
| 6h | ≈0.84 |
| 24h | 0.5 |
| 48h | 0.25 |
| 96h | ≈0.06 |

**规则细节**：以事件首次报道时间为准，转发/二次报道不重置时钟（防"旧闻新炒"）；持续发酵型事件（如听证会多日进行）以最新实质进展时间计；预告类事件（"将于 9 月 23 日关闭"）以官宣时间计，不因事件在未来而扣时效。

> **设计权衡**：宏观流权重给 0.20 而非 Sector 的 0.25，因为宏观页刷新频率更高、供给更足，时间本身已经通过候选池窗口约束（如近 48h），不需要在排序层再给高权重——否则会退化回"按时间强排"的老病。

### 2.3 热度 H（Hotness，权重 0.15）

**定义**：事件的市场关注度，由社交互动量与独立信源数融合，log 压缩防刷量。

```
H = 0.6×log 归一(社交互动) + 0.4×min(独立信源数/8, 1)
```

**规则细节**：社交互动取 X/币安广场的转发+评论+点赞去重合计，log10 压缩后除以基准（当日 P95）；独立信源数只计**独立采编**的信源（转载/翻译稿不计），8 家以上封顶。注意：**独立信源数是热度信号，不是重复出条的理由**——同一事件多源报道在去重层归簇，只在 H 因子里加分。

### 2.4 权威 A（Authority，权重 0.15）

**定义**：信源可信度分级 × 一手信息验证。

| 信源层级 | A 锚点 |
|---|---|
| 官方一手（监管机构官网/官推、交易所公告、项目官方渠道） | 0.9 ~ 1.0 |
| 头部媒体独立采编（Bloomberg、Reuters、CoinDesk、The Block） | 0.75 ~ 0.9 |
| 中文头部加密媒体（BlockBeats、Odaily、PANews、ChainCatcher、MarsBit、Foresight） | 0.6 ~ 0.8 |
| 二手转载/编译、聚合号 | 0.35 ~ 0.55 |
| 匿名爆料、无信源截图、社区传言 | ≤ 0.3 |

**规则细节**：正文含"据传/知情人士/未经证实"等措辞时 A 打 7 折；官方否认过的传言 A≤0.2；标题借用权威名义（"美 SEC 或将…"）但正文无官方信源支撑的，按实际信源层级打分，不被标题措辞诱导。同一事件多源竞争时，去重归簇后**保留 A 最高的信源版本**。

### 2.5 质量 Q（Quality & Cleanliness，权重 0.15）★ 本方案新增因子

**定义**：AI 检测标题党、公关软文及语义重复度，低噪音干货给高分（0.0~1.0）。这是 Macro Insight 独有因子——宏观候选池无板块相关性过滤，水文密度高，用连续因子让低质内容"沉底而不淘汰"（保底供给约束下不能硬删）。

**Q 由三个扣分维度构成，从 1.0 起扣**：

| 维度 | 检测信号 | 扣分 |
|---|---|---|
| 标题党 clickbait | 悬念钩子（"惊人内幕""你绝对想不到"）、夸张情绪词、标题与正文不符、感叹号堆砌 | -0.2 ~ -0.5 |
| 公关软文 PR | 通稿式措辞（"荣获""强强联手""赋能""里程碑"）、单一利益相关方视角、无独立信息增量、融资通稿无业务实质 | -0.2 ~ -0.4 |
| 语义密度低 low-density | 正文信息可压缩为一句话却写了十句、复述旧闻无新增量、"或将/可能/预计"堆叠的空推测、AI 生成感套话 | -0.1 ~ -0.4 |

**加分锚点**：含独家数据/一手图表 Q≥0.85；含明确数字、时间、主体、影响量化的干货简讯 Q≥0.8；中性转述基本事实 Q≈0.6。

> **防误伤**：深度长文不等于低密度——判断标准是"信息增量/篇幅比"，不是绝对长度。分析类内容只要有独立观点与数据支撑，Q 正常打分。

## 三、超重去重（四层管线，cosine≥0.82）

**线上最刺眼的 badcase：K25.ai 完成 A 轮融资一事出现 3 条**（MarsBit "a 轮"/ChainCatcher "A 轮"仅大小写之差，PANews 加前缀"预测市场"）。宏观流信源密度高，同事件多源报道是常态而非例外，四层必须做满。

**四层去重管线（顺序执行，任一层命中即归簇）**：

**DC-1 标题归一化精确匹配**：小写化、全半角统一、去标点/空格/emoji、数字格式归一（"2 亿美元"="200,000,000 美元"="$200M"）后，标题编辑距离 ≤10% 视为同条。K25.ai 的 "a 轮"vs"A 轮" 在这一层就会被拦截。

**DC-2 事件三元组无条件归簇**：抽取（主体, 动作, 关键数值/日期）三元组，完全一致则**无条件**归簇，不看标题差异。K25.ai 三条的三元组均为（K25.ai, 完成A轮融资/估值2亿, Amber Group），PANews 加"预测市场"前缀也逃不掉。

**DC-3 embedding 语义聚类**：标题+summary 拼接向量化，**cosine≥0.82 即归簇**，同簇要求事件时间差 ≤48h。

> **⚠️ 阈值修订（2026-07-26，实测标定）**：v1 初稿写的是 0.65，实现后在 855 条真实事件（28 万配对）上分档抽样验证，发现 0.65 会严重过度合并——把"主题相近"当成"同一事件"：
>
> | 相似度档 | 实际含义 |
> |---|---|
> | ≥0.85 | 全部真重复（"BitMEX将于9月23日关闭" vs "…2026年9月23日关停"） |
> | 0.80–0.85 | 多数真重复 |
> | 0.75–0.80 | **开始混入不同事件**（"Dango 8月13日关闭" vs "Dango 7月29日停交易"） |
> | 0.65–0.70 | 基本都是不同事件（"AI开支担忧压制科技股" vs "特斯拉周跌18%"） |
>
> 13 组人工标注配对上，"应合并"最低 0.859、"应分开"最高 0.761，中间有 0.098 的干净空隙，0.78~0.85 区间错误率均为 0。**取 0.82**。
>
> 初稿把阈值调低的理由是"宏观流同事件多源报道是常态，去重要更激进"——方向对，但落点错了：召回应该由 DC-2 的事件三元组精确匹配来保障（不受阈值影响），向量层的职责是抓指纹漂移的漏网之鱼，该往**精度**方向调。两层同时往召回调，代价是把两件真实事件合并成一件——那比漏一条重复严重得多。

**DC-4 输出前自检断言**：对最终输出集两两跑一遍 DC-1~DC-3，任何一对命中即回退重排。输出 JSON 中每条附 `cluster_id` 与 `merged_sources` 字段留痕。

**簇内保留规则**：优先保留 A（权威）最高的版本；A 相同保留信息完整度（数字/主体/影响俱全）最高者；`merged_sources` 记录被合并的其余信源，可供前端展示"N 家报道"角标（反哺 H 因子的信源数信号）。

**去重永不为保底让路**：候选不足 3 条时，宁可放宽 Q 排序顺位补足，也不得拆簇放出重复内容。重复是比低质更严重的体验事故。

## 四、保底出条规则（与 Sector Insight 相反的设计）

| 对比项 | Sector Insight | Macro Insight |
|---|---|---|
| 出条哲学 | 宁缺毋滥，0~3 条合法 | 保底供给，**至少 3 条** |
| 原因 | 板块页硬门保证相关性，错配伤害大于空缺 | 宏观页是主新闻流，空流 = 产品失效 |
| 补足手段 | 不补足，空输出附 empty_reason | 按 Score 顺位向下取，可放宽 Q 但不放宽去重 |
| 上限 | 3 条 | 前端容器决定（建议 ≤10 条） |

补足优先级：先取 Score 次高的未出条内容 → 仍不足则扩大时间窗（48h→96h）重拉候选 → 极端情况（全市场无新闻）允许出 A 级机构研报/数据周报类常青内容垫底，并标记 `fallback: true`。

## 五、工作流（5 Steps）

| Step | 环节 | 动作 |
|---|---|---|
| 1 | 实体 & 事件提取 | 抽取实体（主体/机构/人物/金额/日期）→ 判定事件类型（映射 EventTier 五级表）→ 查询主体市值与受影响资金规模（CMC/CoinGecko/币安行情，防戏剧性虚高）→ 判定加密传导路径层数 |
| 2 | 标签生成 | 逐条生成五因子结构化 JSON（M/T/H/A/Q 及子信号）+ 一句话 summary + 事件三元组指纹；M 分前先查 market_cap_usd / affected_capital_usd |
| 3 | 纯加权打分 | Score = 0.35M + 0.20T + 0.15H + 0.15A + 0.15Q，无硬门，全量打分排序 |
| 4 | 激进超重去重 | DC-1 标题归一化 → DC-2 三元组无条件归簇 → DC-3 embedding cosine≥0.82 + 48h 时间窗 → 每簇留 A 最高 1 条 → DC-4 输出前两两自检断言 |
| 5 | 体验混排 + 保底输出 | 多样性（同一主体 ≤2 条、同一事件类型 ≤3 条连排）、头部保证（Top3 内至少 1 条 EventTier≥A 级）、保底 ≥3 条（放宽 Q 不放宽去重），输出附 cluster_id/merged_sources/fallback 标记 |

## 六、输出格式规范

每条输出 = **标题 + 总结**（与线上卡片一致），并附结构化标签：

```json
{
  "title": "≤40字，完整不截断，含主体+动作+关键数值",
  "summary": "80~120字：事实（数字/主体/时间）→ 对市场的含义 → 风险或反面提示",
  "source": "保留信源（A 最高者）",
  "published_at": "事件真实时间 ISO8601",
  "scores": {"M": 0.0, "T": 0.0, "H": 0.0, "A": 0.0, "Q": 0.0, "final": 0.0},
  "event_tier": "S/A/B/C/D",
  "event_fingerprint": ["主体", "动作", "关键数值或日期"],
  "cluster_id": "去重簇 ID",
  "merged_sources": ["被归簇合并的其他信源"],
  "fallback": false
}
```

**文案规范**：标题禁止悬念钩子与感叹号；summary 首句必须是可验证事实；禁止"或将利好整个市场"式空洞外推；数字保留原文精度；主体名称用官方名（防 K25.ai 式大小写混乱）。

## 七、设计原则 Cheat Sheet（11 条）

1. **重要性主排序**：时间只是衰减因子，不是排序主键；线上按时间强排是第一病根。
2. **无硬门纯加法**：宏观流不设相关性硬门，候选池准入由上游负责，排序层只解决"谁更重要"。
3. **无相关性因子**：Macro Insight 不问"相关吗"，只问"重要吗"；与 Sector Insight 形成职责分离。
4. **影响面独大（0.35）**：EventTier×市值规模×传导强度三子信号，人事变动/泛科技天然沉底。
5. **先查市值再打 M**：继承 v5.1 铁律，全市场口径；微型项目戏剧性事件 ScopeFactor≤0.15。
6. **传导强度防泛科技**：无明确加密传导路径的事件 TransmissionFactor≤0.25。
7. **质量因子沉底不淘汰**：标题党/软文/低密度靠 Q 连续扣分沉底，兼容保底供给约束。
8. **四层去重**：三元组无条件归簇保召回，向量层 cosine≥0.82 保精度（实测标定）；两层互补，不可同时往召回方向调。
9. **簇内留最权威**：保留 A 最高版本，merged_sources 留痕反哺热度信号。
10. **保底 ≥3 条**：补足可放宽 Q 顺位，**永不放宽去重**；极端情况出常青内容并标记 fallback。
11. **时效不重置**：转发/二次报道不重置时钟，防旧闻新炒。

## 附：公式字符版（便于复制，无乱码）

```
打分：Score = 0.35×影响面M + 0.20×时效T + 0.15×热度H + 0.15×权威A + 0.15×质量Q（无硬门，纯加权）
影响面：M = 0.4×事件级别 + 0.3×市值规模 + 0.3×传导强度（打分前必查市值）
去重：标题归一化 + 三元组无条件归簇 + Embedding(cosine≥0.82, 48h窗) → 同簇留权威最高 1 条
召回：去重后按 Score 排序，体验混排，保底 ≥3 条（放宽Q不放宽去重），上限由前端容器决定
```
