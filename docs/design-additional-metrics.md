# 设计笔记：新增打分/评测维度

> 响应用户要求"全面扫描目前提供的标签和评测指标，要多想一下必要的打分维度
> （也不用硬凑）"。2026-07-26。

---

## 一、现有维度盘点

**生产打分（Macro Insight v1，`crawler/scoring.py`）**：
```
Score = 0.35×M(影响面) + 0.20×T(时效) + 0.15×H(热度) + 0.15×A(权威) + 0.15×Q(质量)
```

**内容标签**（`crawler/pipeline.py` NEWS_SCHEMA）：`sector_tags`（相关度+锚点）、
`entities`（结构化实体）、`sentiment`+`sentiment_score`（方向性影响）、
`impact_horizon`（影响生效的时间尺度）、`coin_metrics`（市值/BTC倍数/档位）。

**真实性校验**（`crawler/verification.py`）：`verification_status`/`score`/
`reason`/`flags`、`independent_source_count`。

## 二、逐个对照"用户真正想知道但现在没覆盖的"

想过的维度，包含最终采纳和放弃的，都记录下来（放弃的也要留痕，避免以后重新
纠结同一个问题）：

### 采纳：动量 Momentum（对应用户说的"热门冲击感"）

**和现有 H 的区别**：H 是热度的**快照值**（当前互动量 + 信源数），不区分
"30分钟内互动从0冲到1000"和"稳定在1000好几天"——这两种情况现在打分完全一样，
但对用户的价值感知完全不同。Momentum 度量的是**变化率/加速度**，是 H 的导数，
不是重新定义 H。

**可计算性**：现有数据能算——用互动量 / 发布至今时长做速度近似
（`social_interactions / hours_since_published`），或者更精细地，在多轮
pipeline 之间比较同一事件的互动量增量（跨轮归并时事件会被更新，可以在
`storage.merge_with_existing` 里顺手记录"上一次看到时的互动量"，算出增量）。

### 采纳：叙事新鲜感 Narrative Novelty（对应用户说的"新鲜感"）

**和现有 T 的区别**：T 是发布时间戳的指数衰减，不区分"这是这个话题第一次被
报道"和"这是这个话题这周第5次被报道"——CLARITY 法案本周每次投票进展都是
"新发布"（T满分），但对用户来说信息增量在递减。Novelty 度量的是**同一叙事
的信息增量**，不是发布时间的新旧。

**可计算性**：可以用 embedding 比对——查同一 `event_subject` 在更长回看窗口
（比如 30 天）里有没有相似的历史事件，复用 `crawler/dedup.py` 已有的 embedding
和相似度计算逻辑，只是把"归并阈值 0.82"换成"新鲜感判定阈值"（这个阈值需要
重新标定，不能直接照抄归并阈值——归并阈值判定的是"是不是同一件事"，新鲜感
判定的是"是不是相似的叙事脉络"，语义不同，标定方法应该参照 `crawler/dedup.py`
里"实测标定，不要照抄文档数字"的方法论）。

### 放弃：舆论分歧度 Controversy

想法：有些新闻引发对立反应（多头空头同时活跃解读），本身是重要性信号。

**放弃原因**：现有数据算不准。`sentiment_score` 是单一均值，要算分歧度需要
细粒度的、按信源/按KOL区分的情绪数据，现在的 pipeline 没有采集这个粒度。
硬要算的话样本量太小（一个事件平均 1-2 个信源）统计意义存疑，是典型的
"为了有而做"，不采纳。

### 放弃：交易可操作性 Actionability

想法：有些新闻给出明确可执行的交易信号（具体价位/资产/时间），有些是背景
分析类内容，前者对交易者更有用。

**放弃原因**：和现有 `impact_horizon`（影响生效的时间尺度）重叠度较高，
且"可操作性"本质上更贴近**内容体裁**（价格播报 vs 深度分析 vs 政策解读），
这个 skill 文档（Sector Insight v5.1）里已经有 `content_genre` 体裁标签的
设计（虽然本项目还没实现），属于"该做但不是这里该做"，先不重复造轮子。

## 三、实现范围（本轮）

**先只加进评测工具的评分维度，不动生产 `scoring.py` 的排序公式。**

理由：Momentum 和 Novelty 虽然设计上站得住，但改动生产排序公式是会直接影响
线上推荐结果的决策，需要用户明确拍板（已记入 `docs/OPEN_QUESTIONS.md`）。
先在评测工具（LLM评测室、AB对比）里作为**参考维度**展示出来，让用户看到实际
效果后再决定要不要正式纳入 Macro Insight 公式。
