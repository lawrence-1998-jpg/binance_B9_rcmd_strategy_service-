B9 推荐指标体系

设计原则只有一条：先立核心逻辑，再从逻辑长出指标。 体系是一条乘法链——四个环节相乘等于产品价值，任何一环为零则全链为零。 老板周报只看 1 个北极星 + 4 个主指标；其余全部是诊断指标，只在主指标异动时下钻。

零 · 核心逻辑：一条乘法链

这个产品做的事情是：把市场发生的重要事，及时、准确、按对的顺序，送到会在意的人眼前。价值在四个环节上逐层兑现——

L1 · 供给捕得全S/A 事件召回率市场发生的重要事，进库了吗
×
L2 · 分发排得对头部命中率 @K进库的重要事，上位置头部了吗
×
L3 · 质量说得准内容准确率上头部的内容，是对的吗
×
L4 · 消费有人看位置 CTR对的内容，用户买账吗

北极星 = S/A 级事件有效触达率：站外基准池中的 S/A 级事件，在事发 6 小时内出现在任一上线位置头部、且内容抽检合格的比例。 它就是四个因子的乘积——北极星跌了，看四个因子哪个跌，即可归责到「爬虫 / 排序 / 内容理解 / 端上」四个可干预环节之一。 凡是不能归责到一个环节的指标，不进这个体系。

为什么锚在「S/A 级事件」而不是「全部新闻」：候选池是百~千级（LLM4Rec 架构选型的前提），拼数量没有意义； 早午报的历史事故（美股大涨没出来、边缘小币刷屏）本质都是 S/A 级事件的漏与错。把整个体系锚在同一个稀缺对象上，四层才能真正相乘。

一 · L1 供给：捕得全（召回）

指标定义（分子 / 分母）口径要点频率归责
S/A 事件召回率@6h ★主 基准池当日 S/A 事件中，6h 内在我方库中有对应事件的条数 / 基准池 S/A 总数 基准池：CNBC·Bloomberg·CoinDesk·TheBlock·金十 每日头条快照的并集（事件级去重）。匹配用事件指纹（主体+动作+日期）或 URL，禁止关键词反查——LLM 意译标题曾把 70% 召回误判成 45% 日 爬虫/信源
召回漏斗量表 raw 抓取 → 去重后 → LLM 结构化 → 入库事件 → 其中 S/A 数，五级留存 老板要的「召回量（整个漏斗）」。看的是环比变化而非绝对值——任何一级突然缩量，都在北极星跌之前预警 日 全链路
分市场召回率 同主指标，按 crypto / 美股 / 宏观 拆分 早午报 P0 事故（美股行情缺失）的直接哨兵。聚合召回率会掩盖单市场塌方——报总数必须同时报三个分项 日 爬虫/信源
首报时延 P50 / P90 事件在基准媒体最早发布时间 → 我方入库时间 召回率的时间维度。P90 控尾部：一条 S 级晚 12 小时入库，等于没召回 周 爬虫/管线
独家事件数 我方库中有、基准池没有的 S/A 事件数（抽检确真后计入） 召回率的对偶指标：防止团队为刷召回率而退化成「只抄基准媒体」。也是 AI 挖掘扩源（+211% 实证）价值的直接度量 周 爬虫/AI挖掘

二 · L2 分发：排得对（排序）

同一套逻辑，三个位置三个落法——位置形态不同，「头部」的定义不同，但都在回答同一个问题。

指标定义口径要点频率归责
头部命中率@K ★主 我方位置头部 K 条中属于「当期应出集合」的条数 / K 「应出集合」= 基准池 S/A ∪ 我方独家 S/A。三个位置的 K：早午报=入选条数（全部）；Macro=Top10；Sector=每板块 Top3 日 排序策略
S 级倒挂率 库里已有、但没进对应位置头部的 S 级事件占比 主指标的对偶：命中率看「上去的对不对」，倒挂率看「该上的漏没漏」。BTC 破位排第 74 位那类事故的哨兵 日 排序策略
头部重复率 头部 K 条中互为同一真实事件的条数 / K 「1 事 3 条」历史 P0 问题；跨轮归并失效时第一个冒头的就是它。红线 = 0 日 去重/聚类
Sector 相关性精度 Sector 位展示条目中，人工/Agent 判定「与板块真相关」的占比 Sector Insight 的 P0 问题（相关性严重不足）专属。配套空结果率：宁缺毋滥的代价要可见，两者一起看 周 相关性策略
头部新鲜度 头部条目的事发时间年龄分布 P50 时效因子是否被其他因子淹没的哨兵 周 排序策略

三 · L3 质量：说得准（准确率）

指标定义口径要点频率归责
内容准确率 ★主 抽检合格条数 / 抽检条数。每周 50 条，按头部曝光加权抽样 四项全对才算合格：事实成立 / 数字无误 / 时间正确 / 归因不夸大。人工 + Agent4Rec 双评，分歧仲裁。抽样偏向头部——错在头部的代价远大于错在长尾 周 内容理解
头部可信结构 头部条目中 VERIFIED / PROBABLE / UNVERIFIED / DISPUTED 的分布 已有 verification 体系的直接复用。红线：DISPUTED 与 is_rumor 进头部 = 0 条 日 校验管线
幻觉/误读率 抽检中「数字/幅度被误读」类错误占比 冲击力幅度误读（54% 那次）的常设哨兵；独立列出是因为它是 LLM 链路特有的失败模式 周 内容理解
纠错时延 错误被发现 → 从线上头部消失的时间 错误不可能为零，纠错速度是第二道防线 按例 运营/管线

四 · L4 消费：有人看（点击与行动）

指标定义口径要点频率归责
位置 CTR ★主 点击 / 曝光，三个位置分开报，不合并 数据源：神策埋点（$AppViewScreen/$AppClick + 位置 pagename/module，需端上确认三个位置的埋点 ID）。三个位置的 CTR 没有可比性，禁止排名——日报是推送打开、Macro 是信息流、Sector 是上下文卡片 日 排序+端上
有效阅读率 点击后停留 ≥3s 的占比 CTR 的诚实性检验：标题党能骗到点击，骗不到停留 周 内容质量
看后行动率 点击新闻后 30 分钟内访问对应标的行情页 / 下单的占比 连接价格敏感度研究的桥：内容消费 → 交易意图。这是「新闻推荐对交易业务有什么用」的最终答案，也是给老板讲故事的终点 周 全链路
负反馈率 关闭 / 不感兴趣 / 举报 / 长期不点击同类 「吵杂感、营销感」（协同一致文档里的底线问题）的量化出口 周 排序+频控

五 · 制衡设计：每个主指标都有一个对角指标看着它

不堆砌指标的另一面，是不让任何单一指标被优化到荒谬。四个主指标各配一个天敌，谁被刷坏，天敌先报警：

召回率 ↑ 的作弊路径

放宽入库标准灌水。天敌：S/A 占比 + L3 准确率——灌进来的边缘内容会立刻稀释这两个数。

命中率 ↑ 的作弊路径

直接抄基准媒体头条。天敌：独家事件数 + 首报时延——纯跟随者两个数都会难看。

CTR ↑ 的作弊路径

标题党、夸大幅度。天敌：有效阅读率 + 幻觉率 + 负反馈——三个都在等它。

准确率 ↑ 的作弊路径

只发绝对安全的旧闻。天敌：头部新鲜度 + 召回率——保守化会先在这两个数上现形。

六 · 护栏红线（不进 KPI，触发即告警）

红线头部出现 DISPUTED / rumor 条目 = 0 容忍；出现即告警并自动降位。
红线管线健康：距上次产出 ≥1.5h 预警、≥3h 判停摆（现有 verdict 机制直接复用）。
红线头部重复（同一真实事件 ≥2 条同屏）即告警。
红线单位事件成本超预算 50% 连续 3 天（现有 llm_gate 计量复用）。

七 · 落地：从明天开始的三步

阶段做什么依赖产出
第 1 周 基准池上线：每日定时抓 5 家 TOP 媒体头条快照落表（现有爬虫框架加一个 job）；事件指纹匹配脚本；L1 召回率 + 漏斗量表先跑起来 无外部依赖，全部自有 每日召回率数字 + 漏斗表
第 2 周 L2/L3 接入：三个位置的头部快照落表（API 侧已有数据）；命中率/倒挂率/重复率脚本；周抽检 50 条流程建立（评测室 + Agent4Rec 双评） Sector 位需研发确认线上 TopK 接口 四层主指标全部有数，第一份周报
第 3-4 周 L4 打通：与端上确认三个位置的埋点 ID（pagename/module 取值）；CTR/停留/看后行动率从神策表出数；北极星开始按周发布 唯一外部依赖：端上埋点 ID 清单（Colson/Fosal/winnie 侧确认） 北极星 + 4 主指标周报模板固化
数据源盘点：曝光点击 = 神策全端埋点表（已有权限，1 年）；头部快照 = 我方 API；基准池 = 新增每日爬取 job； 抽检 = 评测室 + Agent4Rec（Confluence 评估章节 @yikai 的 case review 机制正好挂在 L3）。 整个体系只有一个新增采集项（基准池）和一个外部依赖（埋点 ID），其余全部复用现有资产。

八 · 周报的样子（就这 5 个数）

指标本周上周环比异动下钻
