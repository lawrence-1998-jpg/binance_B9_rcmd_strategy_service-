# PRD-03：热度氛围营造 —— 处理优先级 + 排序因子扩展 + 新闻类型标签

> 状态：**需求规划中，未进开发**（Lawrence 2026-07-29：「先梳理好需求，规划好，我们下一步再进开发」）
> 关联：[PRD-01 数据抓取](PRD-01-数据抓取.md)、[PRD-02 聚类与理解](PRD-02-聚类与理解.md)、WORKLOG #61/#62

## 一、问题陈述

B9 首屏缺少 CNBC 那种「市场大事扑面而来」的热度感与氛围感。产品同事对照
CNBC 首页提出这个差距，老板要求排序上营造市场事件在头部的氛围。

**但根因不是「扫得不够多」。** 2026-07-29 实测数据（本 PRD 的立论基础）：

**事实 1 —— 抓取不是瓶颈，处理才是**

| 信源 | 已抓取 | 已处理 |
|---|---|---|
| dxFeed（付费） | 99 | 5 |
| NikkeiAsia | 51 | 0 |
| SCMP-Business | 51 | 0 |
| CNBC-TopNews | 35 | 1 |
| MarketWatch | 24 | 2 |

301 条已抓回，仅 8 条进过 LLM。**在队列打通之前，任何增加抓取量的动作都只是
让队列更长。**

**事实 2 —— 数量不少，是构成不对**

`us_stock` 已有 207 条事件（仅次于 crypto），但 **D 档 99 条（48%）+ C 档 74 条
（36%）= 84% 是低价值内容**：

- 我们抓回的：「Argus更新涵盖多只美股」「分析师比较联合太平洋与诺福克南方」
  「JFrog被指AI进展提振动能」——**个股/分析师级**
- CNBC 首屏：「Dow rallies 600 points」「chip stocks get clobbered」
  「Corning tumbles 16%」——**大盘/板块级**

**事实 3 —— 打分系统本身没有歧视非加密内容**

| 市场 | S/A 档占比 |
|---|---|
| kr_stock | 30.0% |
| jp_stock | 20.0% |
| macro_policy | 11.8% |
| crypto | 3.1% |
| us_stock | **1.9%** |

日韩宏观进来的是「日经暴跌」「KOSPI熔断」「全球债券收益率创2008年新高」，
系统准确判成了 S/A。**说明只要喂进去的是大盘级内容，现有逻辑能正确识别。**

**结论**：这是一个**处理吞吐 + 内容构成 + 排序表现力**的三段式问题，
不是召回量问题。

## 二、目标

1. **权威大盘内容的入库时延**从「排在数百条个股噪音后面」降到**当轮即处理**
2. 首屏（前 20 条）中 `market_scope ≠ crypto` 且 tier ∈ S/A 的条目占比
   从当前 **约 8%（4+8+3+1 / 66）** 提升到 **≥25%**
3. 排序具备**方向性表现力**：大盘单边行情时首屏能明显感知到氛围，
   同时**不牺牲反转信号的可见性**
4. 全部新因子**可在策略实验室独立调节**，Lawrence 可自行寻优
5. 提供一套**独立于加密板块**的新闻类型标签，让非加密内容不再显示「未标注」

## 三、非目标

| 非目标 | 理由 |
|---|---|
| 增加新爬虫 / 提高搜索强度 | 队列已积压 293 条未处理，加抓取无法转化为可见内容 |
| 更换 dxFeed 取数范围 | Lawrence 明确：个股大盘都拉，靠**优先级**而非**过滤**解决（保留大底池） |
| 追平 CNBC 的分钟级时效 | 属架构问题（当前每小时一轮），本期不做，见 P2 |
| 自动调参 / 寻优算法 | Lawrence 明确要自己在实验室里调，我们只需保证因子可调、可解释 |
| 情绪因子写回 `importance_score` | 必须保持库内分数与展示分数分离，否则历史不可比（见 WORKLOG #61） |

## 四、需求详述

### R1（P0）处理优先级队列 + 产能提升

**用户故事**：作为策略产品负责人，我希望 CNBC 这类权威大盘媒体的内容一抓回来
就被优先处理，这样重大市场事件不会因为排在个股噪音后面而延迟数小时才可见。

**设计**：`raw_items_staging` 增加 `priority TINYINT`，`fetch_staged_items`
改为 `ORDER BY priority ASC, fetched_at ASC`。

| 优先级 | 内容 | 判定方式 |
|---|---|---|
| **0** | 权威大盘媒体 | 信源 ∈ {CNBC-*, MarketWatch, NikkeiAsia, Reuters, Bloomberg, SCMP-GlobalEcon} |
| **1** | dxFeed **大盘/ETF** symbol | 命中 {SPX, DJI, IXIC, RUT, VIX, SPY, QQQ, DIA, IWM} |
| **2** | 加密头部媒体 + 行情异动 | 现有 authority ≥ 4 的加密源 |
| **3** | 其他 RSS / 搜索召回 | 默认 |
| **4** | dxFeed **个股** symbol | 命中单一公司 ticker |

> ⚠️ 依赖：`crawler/dxfeed_news.py` 当前**不记录**条目由哪个 symbol 命中，
> 需补一个字段才能区分大盘/个股。这是 R1 的前置工作项。

**产能**：
- 单轮上限 `B9_PIPELINE_BATCH` 400 → **逐步上调**（建议 800 起步，观察单轮
  时长后再加；硬约束是单轮必须 < 60 分钟，否则 flock 会让下一轮空转）
- 结构化模型 `gpt-5.6-sol` → **`gpt-5.4`**

  实测对比（同一条 CNBC 新闻、同一 schema）：

  | 模型 | 耗时 | 单条成本 | 分类结果 |
  |---|---|---|---|
  | gpt-5.6-sol | 10.9s | $0.0441 | us_stock / B / M=0.52 |
  | gpt-5.4 | 9.5s | $0.0153 | us_stock / B / M=0.48 |

  结论支持 Lawrence 的判断：**分类一致，5.4 成本仅 1/3**。按 800 条/轮、
  每小时一轮估算，日成本从约 $850 降到约 $294。速度差异不大（9.5s vs 10.9s），
  真正的吞吐瓶颈是网关 30 RPM 硬限，不是模型。

**验收标准**：
- [ ] CNBC/MarketWatch 类信源的条目，抓取后**同一轮**即被处理
- [ ] dxFeed 大盘 symbol 条目优先于个股 symbol 条目
- [ ] 单轮处理量提升后，单轮耗时仍 < 60 分钟
- [ ] 积压总量呈**单调下降**趋势（连续 3 轮观察）

### R2（P0）广度因子 Breadth

**用户故事**：作为读者，我希望「芯片股集体重挫」排在「某公司高管减持」前面，
因为前者影响我的整个持仓，后者只影响一只股票。

**这是最关键的缺失维度**——当前系统里没有任何字段区分「影响一个指数」和
「影响一只股票」，而这正是我们与 CNBC 内容质感差异的根源。

**定义**（LLM 新增 schema 字段 `breadth_level`，映射为 0-1 因子值）：

| 值 | 层级 | 判据 | 例 |
|---|---|---|---|
| 1.00 | 跨市场 | 同时影响多个国家/资产类别 | 美联储决议、全球债市抛售、战争 |
| 0.80 | 单市场大盘 | 影响一个市场的主要指数 | 日经跌4%、KOSPI熔断、道指涨600点 |
| 0.60 | 板块级 | 影响一个行业/赛道全体 | 芯片股集体重挫、DeFi 板块普跌 |
| 0.35 | 多标的 | 明确点名 2-5 个标的 | AMD/美光/英伟达同步下跌 |
| 0.15 | 单标的 | 单一公司/单一代币 | 某公司财报、某代币上线 |

**验收标准**：
- [ ] LLM schema 增加 `breadth_level` 必填枚举
- [ ] 抽样 30 条人工核对，分级准确率 ≥ 85%
- [ ] 「AMD/美光/英伟达延续跌势」应判为 0.35–0.60，非 0.15

### R3（P0）冲击力因子 Impact

Lawrence：「比如跌xx%、涨xx%、多个权威媒体报道、对社会经济可能产生重大影响的
事件……描刻能够影响用户资产价格、影响用户情绪的感觉。具体的定义可以先拓展梳理。」

**⚠️ 先讲一个必须避开的坑：这个因子极易与现有 M/H/A 重复计分。**

拆解 Lawrence 提到的三个成分，逐个判断是否已被覆盖：

| 成分 | 现状 | 结论 |
|---|---|---|
| **数值幅度**（跌18%/涨600点/16%） | **完全没有捕获** | ✅ 真新增，这是本因子的核心 |
| 多家权威媒体报道 | H 因子含 `min(信源数/8,1)`，但被社交互动稀释；A 因子只看单一最高权威 | ⚠️ 部分覆盖，需**权威共振**子项补强 |
| 社会经济重大影响（如美联储加降息） | M（影响面）+ R2 广度已覆盖 | ❌ 不再单列，否则三重计分 |

**因此本因子定义为**：

```
Impact = 0.65 · 数值幅度分 + 0.35 · 权威共振分
```

**数值幅度分**（正则从标题/摘要提取，零 LLM 成本）：

| 提取到的幅度 | 分值 | 说明 |
|---|---|---|
| ≥ 15% 或「暴跌/崩盘/熔断/涨停」 | 1.00 | 铠侠跌18%、KOSPI熔断 |
| 8–15% | 0.75 | SK海力士跌11% |
| 4–8% | 0.55 | 日经跌4%、费半跌5% |
| 2–4% | 0.35 | 纳指跌2.5% |
| < 2% 或无数字 | 0.10 | — |

> 金额类（$7亿清算、$500亿合作）与点数类（道指600点）需单独的量纲映射表，
> 建议 v1 先只做**百分比**，金额/点数放 P1——百分比覆盖了绝大多数「有冲击力」
> 的标题，且量纲统一、误判风险最低。

**权威共振分**：

| 条件 | 分值 |
|---|---|
| ≥3 家 authority≥4 的独立机构报道 | 1.00 |
| 2 家 | 0.65 |
| 1 家 authority=5 | 0.45 |
| 其他 | 0.15 |

**验收标准**：
- [ ] 「日经225跌4% 铠侠跌18%」的幅度分 = 1.00
- [ ] 「Argus更新涵盖多只美股」的 Impact < 0.2
- [ ] 数值提取不误伤：「2026年」「第57期」不得被当成幅度

### R4（P0）情绪同向 boost（加分项）

**用户故事**：作为读者，当整个市场在暴跌时，我希望首屏能真实反映这种氛围，
而不是把利好利空平均成一片没有感觉的内容。

```
bonus_sentiment = k_s × |mood_score| × |event_sentiment| × [方向一致]
```

- 仅在**方向一致**时生效（反向不加也不减）
- `k_s` 实验室可调，默认 **0.25**（当前硬编码 0.15，本期提高并开放）
- 大盘中性（|mood| < 0.15）时自动趋近于 0，避免无意义扰动

---

### R5（P0）反转信号 boost（加分项）

**这是本期最重要的风险对冲设计。**

单独的同向 boost 会制造回音室：大盘悲观 → 集体放大负面 → 而此时
「美联储可能提前降息」这类**真正该被看到的反转信号**恰恰被压到看不见。
金融产品里放大情绪 = 放大追涨杀跌，真正伤害用户的不是内容平，
是**在该看到反转信号时看不到**。

```
bonus_reversal = k_r × |mood_score| × |event_sentiment| × [方向相反] × [tier ∈ S/A]
```

- **只对 S/A 档生效**——这是关键约束。低档位的反向噪音不该被扶上来，
  只有「重大且与大盘反向」才是真信号
- `k_r` 默认 **0.20**，实验室可调
- 两个 boost **互斥触发**（方向一致走 R4，方向相反走 R5），不会叠加

**验收标准**：
- [ ] 大盘 mood ≤ -0.3 时，一条 bullish 的 A 档事件排名应高于同分的 C 档 bullish
- [ ] `k_r = 0` 时行为退化为纯同向放大（可用于 A/B 对比证明该因子的价值）

### R6（P0）策略实验室改造

**用户故事**：作为策略负责人，我需要在实验室里分别调节基础因子和加分项，
并且点开任意一条内容就能看到正文和它每个因子的得分，才能判断排序为什么是这样。

**评分模型改为两段式**（正常因子与加分项分离，对应 Lawrence 的「稍微分开」）：

```
BaseScore  = w_M·M + w_T·T + w_H·H + w_A·A + w_Q·Q + w_B·Breadth + w_I·Impact
             （权重归一化到 1.0）
FinalScore = BaseScore × (1 + bonus_sentiment + bonus_reversal)
             （加分项合计封顶 +50%）
```

**建议初始权重**（Lawrence 明确「排不对也没关系，我自己调」，此处只给起点）：

| 因子 | 建议权重 | 理由 |
|---|---|---|
| M 影响面 | 0.26 | 仍是主因子，但从 0.35 让出空间给新因子 |
| **B 广度** | **0.16** | 新增，直击「大盘 vs 个股」的核心差异 |
| T 时效 | 0.16 | 略降，因为 Impact 已部分承担「热」的表达 |
| **I 冲击力** | **0.14** | 新增 |
| H 热度 | 0.10 | 降权，其信源数成分已被 Impact 的权威共振吸收 |
| A 权威 | 0.10 | 降权同理，避免与权威共振重复 |
| Q 质量 | 0.08 | 保留但不再是主要区分度 |

> 加分项：`k_s = 0.25`、`k_r = 0.20`，UI 上与上述 7 个基础因子**分区展示**。

**实验室 UI 增强**：
- [ ] 因子滑块分两组：「基础因子（权重归一化）」/「加分项（独立倍率）」
- [ ] 点击任意条目展开：**正文**（`description_long_zh`）+ **每个因子的原始分与
      加权贡献值** + 两个 boost 的实际倍率 + 最终分的计算过程
- [ ] 后端 `event_card()` 需补 `description_long_zh` / `description_short_zh`
      （当前只有标题，是「不够好用」的直接原因）

### R7（P0）新闻类型 Category 标签 + 筛选器

Lawrence：「就一套独立的新闻类型 category 标签。加密/美股/日股/韩股/经济政策/
社会信号 等等」

**⚠️ 这里有一个必须先拍板的设计冲突：与现有 `market_scope` 高度重叠。**

| Lawrence 要的 | 现有 `market_scope` | 关系 |
|---|---|---|
| 加密 | `crypto` | 完全一致 |
| 美股 | `us_stock` | 完全一致 |
| 日股 | `jp_stock` | 完全一致 |
| 韩股 | `kr_stock` | 完全一致 |
| 经济政策 | `macro_policy` | 完全一致 |
| **社会信号** | — | **缺失** |
| （未列） | `hk_stock` / `general` | 已有 |

**我的建议（方案 A）**：不新建第四套分类，而是**把 `market_scope` 扩充并
正名为对外的「新闻类型」**——

1. 枚举新增 `social_signal`（社会信号：影响市场情绪的社会/地缘/政策外事件）
2. 前端把它做成**显眼的 chip 筛选条**（不是藏在下拉里），并在事件卡片的
   「板块/币种」列，对非加密事件显示该标签，**消除「未标注」**
3. 加密板块（DeFi/MEME/Layer1…）保持独立，两套不混

**理由**：系统里已经有三套分类（`news_type` 事件性质 / `market_scope` 市场归属 /
`sectors` 加密板块），再加第四套只会让下游和自己都搞不清用哪个。而 Lawrence 说的
「独立」，本意是**独立于加密板块**——`market_scope` 已经满足这一点，缺的只是
**没被好好展示出来**。

> 若 Lawrence 坚持要全新一套（方案 B），需同步决定 `market_scope` 是废弃还是
> 保留，不能两套并存。**这是本 PRD 唯一的阻塞性决策点。**

## 八、风险

| 风险 | 影响 | 缓解 |
|---|---|---|
