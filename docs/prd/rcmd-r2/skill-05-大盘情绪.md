# Skill 04 · 大盘情绪与两个加分项（market_mood）

> **一句话**：单条内容的情绪解决不了"氛围"——氛围是一个**全局量**。
> 但放大氛围的同时必须留一条反向通道，否则金融产品里的"氛围感"就是"追涨杀跌放大器"。

---

## 1. 需求来源

> 「如果整个市场都是悲观大新闻，那么就要大悲观，反过来就要大乐观」
> 「排序结果尤其是首几刷要有冲击力」「内容很平，没有感觉」

日韩股市大跌当天，PM 在群里问：
> 「目前 B9 与我相关页的内容……尚未传出这个关键信息与氛围」

---

## 2. 大盘情绪怎么算

```
mood_score = Σ(sentiment_score × w) / Σw          范围 [-1, 1]

样本 = 近 24 小时内，event_tier ∈ {S, A} 且 sentiment_score 非空 的事件
权重 w = importance_score × market_multiplier × freshness_multiplier
```

| mood_score | 标签 | 前端配色 |
|---|---|---|
| ≥ 0.50 | 极度乐观 | green |
| ≥ 0.15 | 偏乐观 | green |
| ≥ -0.15 | 中性 | neutral |
| ≥ -0.50 | 偏悲观 | red |
| < -0.50 | 极度悲观 | red |

同时返回**贡献最大的 3 条**作为证据链（前端横幅直接引用，用户能一眼验证这个判断是否合理）。
取的是"与大盘同向 且 |情绪|×权重 最高"的三条，**必须用与 mood_score 同一套权重排序**——
否则会出现"横幅说偏悲观、但列出的理由并不是真正把它拉悲观的那几条"这种自相矛盾。

---

## 3. 🔴 门槛必须用 `event_tier`，不能用 `importance_score`

**这是上线当天就发现并改掉的真实错误，请不要重犯。**

最初用 `importance_score >= 0.35` 当门槛。实测 48 小时窗口里：

- **782 条 D 档事件**（LLM 判定"次要"）的 importance_score 均值高达 **0.317**，部分个体轻松超过 0.35
- 原因：importance_score 是加权总分，影响面虽然被夹在 D 档区间（0–0.14），但**时效/热度/权威/质量四个因子不受 tier 约束**，单独拉高照样能把总分推过门槛

**后果**：

| | 用 importance ≥ 0.35 | 改用 tier ∈ S/A |
|---|---|---|
| 样本量 | 460 条 | **18 条** |
| KOSPI 熔断当天算出的 mood | **-0.009** | **-0.154** |
| 前端显示 | 「中性」 | 「偏悲观」 |
| 用户反应 | **"这样大跌还是中性？"** | —— |

"重要性分蒙混过关的次要事件"占了情绪样本的大多数，把两条真正的 S 档崩盘事件**稀释成了统计噪音**。

> **口径的本质**："大盘情绪"该问的是「**最近发生的大事整体是什么方向**」，
> 不是「所有沾边的内容加权平均是什么方向」。
> `importance_score` 仍然用作**样本内部的权重**（越重要的 S/A 事件影响力越大），
> 只是不再兼任"够不够格参与计算"的门槛。**这两件事必须分开。**

---

## 4. 样本权重必须和排序层用同一套倍率

上线时权重只用了 `importance_score`，结果实测情绪横幅的三条驱动因素**清一色是韩股**
（韩国 KOSPI 跌 7% / KOSDAQ 熔断 / 韩股暴跌后外资观望），
而首屏排序在市场重要性上线后已经是**美股为主**——

> **同一个产品的两块界面在讲互相矛盾的故事。**

根因和市场重要性是同一个（tier 相对"自己所在市场"判定，小市场 S/A 档率被系统性抬高），
排序层修了、情绪层当时没跟着改。

**"我们认为哪个市场更重要"和"多久以前的事还算数"这两个判断，不该在排序和情绪两处给出不同答案。**

## 5. 两个加分项

```python
MOOD_ALIGN_BOOST    = 0.25    # k_align
MOOD_REVERSAL_BOOST = 0.20    # k_reversal
REVERSAL_TIERS      = ("S", "A")
BONUS_TOTAL_CAP     = 1.00    # 与交易实体加成共用同一个封顶

def sentiment_align_bonus(s, mood, k=0.25):
    if s is None or mood is None:            return 0.0
    if (s >= 0) != (mood >= 0):              return 0.0      # 反向 → 交给 reversal
    return k * abs(mood) * abs(s)

def reversal_bonus(s, mood, tier, k=0.20):
    if s is None or mood is None:            return 0.0
    if (s >= 0) == (mood >= 0):              return 0.0      # 同向 → 交给 align，两者互斥
    if tier not in REVERSAL_TIERS:           return 0.0      # ← 硬约束
    return k * abs(mood) * abs(s)

bonus = min(align + reversal + tradable, cap)
multiplier = 1.0 + bonus
```

### 5.1 为什么必须有第二个（反转加成）

单独的同向放大会让「大盘暴跌 → 首屏全是坏消息」，
而此时一条「美联储可能提前降息」的反转信号**恰恰被压到看不见**。

> 🔴 **金融产品里放大情绪 ＝ 放大追涨杀跌。**
> 真正伤害用户的不是内容平，**是该看到反转时看不到。**

### 5.2 反转加成的 `tier ∈ S/A` 硬约束（老板确认"加的对"）

没有这个约束，大盘悲观时**所有反向的噪音**都会被扶上来，反而更乱。
只有「**重大 且 与大盘反向**」才是真信号。

### 5.3 加成有方向性，但不是单向放大

反向或大盘接近中性时**不加成也不减成**。
这样"大悲观时段"里少数逆势乐观的消息不会被排序打压到看不见——
用户仍然能看到"情况没有那么糟"的信号，只是不会被推到最前面。

> 乘积形式 `k × |mood| × |sentiment|` 自带一个好性质：
> **大盘接近中性时两项自然趋近于 0**，"没有氛围的时候不要硬造氛围"是公式的性质，不是补丁。

---

## 6. 必须提供「手动指定情绪方向」

语义：

- 参数为 `null` / 缺失 / `"auto"` → 用池子现算的实时情绪
- 参数是 `-1..1` 的数字 → **人工指定，覆盖实时值**

**它的价值不是运营干预，是反事实推演**：
实时情绪是什么样，取决于最近恰好发生了什么，**不可控**；
而「**如果此刻大盘极度悲观，我这套权重会把什么顶上首屏**」才是产品决策真正要回答的问题。
没有这个控件，就只能干等到市场真的崩一次才能验证策略。

> 实验室里算情绪时，**刻意不复用生产的缓存值**：实验室是探索工具，用户可能把窗口调成 30 天，
> 那时的"大盘情绪"应当是**这个池子的情绪**，而不是生产固定窗口的那个值。
> 口径跟着用户选的池子走，结果才可解释。

---

## 7. 绝对不能做的一件事

**两个加分项绝不写回 `news_events.importance_score`。**

它们依赖 `mood_score` 这个**每天都在变的全局量**。写进库会让跨天的分数不可比，
而 `importance_score` 是策略实验室、去重、历史分析共同依赖的口径。

加分项只在**查询/展示时**作为外层倍率生效，可随时把系数调 0 退回纯基础排序
——**这也是验证它们真实贡献的 A/B 对照方式**。

---

## 8. 验收断言

- [ ] 情绪样本门槛用 `event_tier IN ('S','A')`，不是 `importance_score >= x`
- [ ] 样本权重 = `importance × market_multiplier × freshness`，与排序层完全一致
- [ ] 同向与反转**互斥**：构造一条同向事件，`reversal_bonus` 必须返回 0
- [ ] B 档反向事件 `reversal_bonus == 0`（tier 硬约束生效）
- [ ] `mood_score = 0` 时两项加成均为 0，最终分退回 `BaseScore × market × freshness`
- [ ] `k_align = k_reversal = 0` 时排序与纯基础排序**逐条 id 一致**
- [ ] 手动指定 `mood = -0.9` 后，首屏负面情绪内容占比显著上升（可反事实验证）
- [ ] 横幅列出的 3 条驱动因素，确实是按同一套权重排出来的 Top3
- [ ] `importance_score` 在开启/关闭加分项前后**逐行不变**（没有被写回污染）
