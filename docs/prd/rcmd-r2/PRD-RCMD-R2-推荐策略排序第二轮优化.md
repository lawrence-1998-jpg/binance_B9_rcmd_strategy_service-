## 0. 一页速览

第一轮排序解决的是「有没有分」，这一轮解决的是**「分排出来像不像一个懂市场的人在排」**。

老板与 PM 的四条反馈，指向四个结构性缺陷：

| 反馈原话 | 现象 | 缺的是什么 |
|---|---|---|
| 「韩国的都排在了上面，其实我们美股才是最重要的」 | 韩股供给量只有美股 1/15，却占了 2 倍的 Top30 席位 | 排序是全局的，但事件分档是「相对自己所在市场」判的——**缺一层全局市场校正** |
| 「这个热度感和 CNBC（友商参考）完全不同」 | 我们首屏是个股级研报，友商首屏是「道指涨 600 点」 | **缺「这件事影响多宽」这个维度**——指数级与个股级在旧公式下拿到相近的分 |
| 「排序结果尤其是首几刷要有冲击力」「内容很平，没有感觉」 | 大跌当天首屏读不出大跌的氛围 | **缺大盘情绪这个全局量**，也缺一个把「市场动了多少」量化的因子 |
| 「刺激标的物交易的感觉不足」 | 一半以上内容落不到用户能买的标的上 | **缺交易实体识别**，也缺保证版面结构的**混排能力** |

本轮交付 **7 块原子能力**（第 1 章表格），合成一条可解释的最终分公式（第 2.1 节），
并把全部参数做成可配置、可实验、可回滚。

> **本文的定位**：这不是从零设计。7 块能力已在 B9 demo 全量实现、实测并交付，
> 本文是把**已验证的口径、参数、踩过的坑**移交给算法团队落到生产链路。
> 每一条判定标准都写成了「可写断言」的形式，不是描述性的。

## 1. 原子能力（积木）

> 阅读顺序：先看这张表建立全貌，再按 `skill/prompt` 列去读对应的单卡文档（每块能力一个 MD，含完整判定规则、参数、反例与验收断言）。
> **备注列是重点**——里面写的都是我们已经踩过、并且付出了线上代价的坑。

| 需求点 | 问题 | 策略 | skill/prompt | 备注 |
|---|---|---|---|---|
| **1 · 市场重要性倍率**<br>`market_weight` | **用户真正在交易的是美股和加密，首屏却长期被韩股 / 日股的本地新闻占住。** 一件"对韩国是大事"的新闻被当成"对所有人是大事"推到所有人面前——实测韩股供给量只有美股的 1/15，却占了 2 倍的 Top30 席位。老板原话：「韩国的都排在了上面，其实我们美股才是最重要的」 | ① 内容理解阶段打 `market_scope` 标签（8 类：美股/加密/宏观政策/社会信号/综合/港股/日股/韩股）<br>② 排序时按市场乘一个**全局相关性倍率**（美股 ×1.20 … 韩股 ×0.55）<br>③ **跨市场豁免**：`breadth_level = cross_market` 的事件不打折（倍率下限 1.00） | [`skill-01-市场重要性.md`](skill-01-市场重要性.md) | ⚠️ **不要试图靠"更聪明的因子"解决**。实测「韩财长为杠杆 ETF 致歉」与「KOSPI 跌 8% 熔断」在 tier / breadth / 冲击力 / 幅度**全部因子上完全一致**，市场内部找不到判据。<br>⚠️ 豁免必须用 `max()` 做下限保护，不能直接赋值——否则美股 1.20 会因为跨市场被压回 1.00。<br>⚠️ 倍率**不写回** `importance_score`：那是"事件本身多重要"，掺运营偏好就污染了跨天可比性。 |
| **2 · 广度因子**<br>`breadth` / `B` | **我们首屏是"分析师比较联合太平洋与诺福克南方"，CNBC 首屏是"道指涨 600 点"**——一个是个股级、一个是指数级，而在旧公式下两者能拿到相近的分。用户读不到"今天市场整体发生了什么"，这就是老板说的「这个热度感和 CNBC（友商参考）完全不同」的直接来源 | 内容理解阶段输出 `breadth_level` **五档枚举**，映射成分值：<br>`cross_market` 1.00 / `market_index` 0.80 / `sector` 0.60 / `multi_asset` 0.35 / `single_asset` 0.15<br>在七因子里占 **16%** 权重（仅次于影响面 26%）；缺失或无法判定一律按 `single_asset` | [`skill-02-广度因子.md`](skill-02-广度因子.md) | ⚠️ **用枚举，不要让模型直接给 0–1 分。** 模型在"这是板块级还是多标的级"上，比在"该给 0.55 还是 0.6"上可靠得多；枚举把判断收敛到封闭集合，可复现、可断言、可抽查。<br>⚠️ **缺失时往窄了算，不给中位数。** 给 0.5 等于让判不出来的内容白捡一个中等广度分，噪音会被系统性抬上来。<br>🔴 **这个字段同时是市场重要性"跨市场豁免"的判据**（`cross_market` → 不打折），判宽判窄会**同时影响两处**，抽查时重点看这一档。<br>⚠️ **不能被影响面 M 吸收**：M 问"这件事多重要"（对当事人），B 问"影响多宽"（覆盖多少市场参与者）。缺 B 就会出现"对少数人极重要的事占住多数人的首屏"。 |
| **3 · 时效性衰减**<br>`freshness` | **用户打开看到的是 2–3 天前、而且事态已经反转的旧新闻，压在当天真正的大事前面。** 实测首屏 #11 / #13 是「美伊缓和致油价跌 16%」，而当天真实新闻是「美军完成对伊朗打击、油价涨 8%」——产品在讲一个已经过期、且方向相反的故事 | 时效改为**查询时**计算的倍率：48 小时半衰期指数衰减，地板 0.15。<br>`0h→1.00 / 24h→0.71 / 48h→0.50 / 72h→0.35 / 120h→0.18` | [`skill-03-时效性衰减.md`](skill-03-时效性衰减.md) | ⚠️ **"这条新闻有多新"不是事件的固有属性，是"你什么时候看它"的函数**——写进库就必然过时，靠 cron 重算只是把过时粒度从"永远"缩小到"一个周期"。<br>⚠️ 半衰期取 48h 不是 24h：24h 下昨天的内容只剩 0.25 倍，会把仍在发酵的大事直接打没。<br>⚠️ 衰减**不归零**（地板 0.15）：归零等于"从排序里删除"，那是展示窗口该做的决定。 |
| **4 · 冲击力因子**<br>`punch` / `I` | **首屏读不出"市场现在动得多厉害"。** 而且这个因子第一版口径没定义清，把标题里任何百分数都当成涨跌幅——「征收 100% 二级关税」被读成 100% 暴涨顶到首屏第 5，「央行购金增 62%」冲到 #4，「Upbit 份额升至 67.4%」排到首屏第 2。占权重 14% 的因子有一半以上的幅度信号是错的，等于**首屏一半位置被误判的内容占着** | ① **由 LLM 在内容理解阶段直接输出结构化语义字段** `price_move {is_price_move, move_pct, move_horizon}`，回答"这个数字是不是价格变动"<br>② 冲击力 = 0.65 × 幅度分（分档）+ 0.35 × **权威共振**（几家 authority≥4 的独立机构在报同一件事）<br>③ 正则口径保留为**存量兜底**，不删除 | [`skill-04-冲击力.md`](skill-04-冲击力.md) | 🔴 **本轮最重要的一条经验：这是语义判断，不是模式匹配，正则表有结构性天花板。**<br>我们用「正则 + 排除词表」做了四轮，每轮都在漏（关税→同比/购金→税/覆盖/超预期/目标价→opt-in 反转口径），仍然漏「市占率升破 58%」。<br>**原因**：百分比能表示的东西是**无穷集合**（支持率/市占率/覆盖率/税率/收益率/波动率/市值占 GDP 比…），而**涨跌动词不是判据**——"份额**升**至""支持率**降**至""渗透率**涨**到"，升降涨跌可以修饰任何指标。<br>✅ 改用 LLM 语义字段后：真实网关 **12/12**；存量回填 400 条抽样，**243 条（60%）原本被误判**。<br>⚠️ prompt 里必须写那句 **"a rise/fall verb next to a number does NOT make it a price move"**——第一版没写，LLM 把"收益率**升至** 5.26%"这个**水平值**当成了变动幅度。<br>⚠️ 兜底不能删：存量数据没有新字段，删了会让它们冲击力集体归零 = 一次无声的全库降级。 |
| **5 · 大盘情绪与两个加分项**<br>`market_mood` | **大盘暴跌当天，产品页面读不出任何氛围，"内容很平，没有感觉"。** 用户感受不到"市场现在出事了"，也就不会产生交易冲动。老板原话：「如果整个市场都是悲观大新闻，那么就要大悲观，反过来就要大乐观」；日韩股市大跌当天 PM 在群里问："B9 尚未传出这个关键信息与氛围" | ① **大盘情绪** = 近 24h **仅 S/A 档**事件的加权平均情绪，权重 = 重要性 × 市场重要性 × 新鲜度<br>② **同向加成** `k_align=0.25`：事件情绪与大盘同向时放大 —— 造氛围<br>③ **反转加成** `k_reversal=0.20`：事件情绪与大盘**反向且 tier ∈ S/A** 时放大 —— 防回音室<br>④ 两者**互斥**，同一条只可能拿到其中一个 | [`skill-05-大盘情绪.md`](skill-05-大盘情绪.md) | 🔴 **门槛必须用 `event_tier`，不能用 `importance_score`。** 上线当天的真实事故：最初用 `importance_score ≥ 0.35` 当门槛，48h 窗口里 782 条 D 档事件的均分高达 0.317，轻松过线——因为总分里 T/H/A/Q 四个因子不受 tier 约束。结果 KOSPI 熔断当天算出的情绪只有 **-0.009**，前端渲染成"中性"，用户直接质疑"这样大跌还是中性？"。改用 tier 后样本从 460 条收窄到 18 条，情绪变成 **-0.154（偏悲观）**。<br>🔴 **反转加成的 `tier ∈ S/A` 硬约束是它成立的前提**（老板确认"加的对"）。没有它，大盘悲观时所有反向噪音都会被扶上来，反而更乱。<br>⚠️ **为什么必须有第二个加分项**：单独的同向放大 = 大盘暴跌就首屏全是坏消息，而此时"美联储可能提前降息"这条恰恰被压到看不见。**金融产品里放大情绪＝放大追涨杀跌**，真正伤害用户的不是内容平，是该看到反转时看不到。<br>⚠️ 情绪样本权重要和排序层用**同一套倍率**。上线时只用了 importance，结果情绪横幅三条驱动因素清一色韩股、而首屏已经是美股为主——**同一个产品的两块界面在讲互相矛盾的故事**。 |
| **6 · 交易实体加成**<br>`tradable` | **「刺激标的物交易的感觉不足」——用户读完一条新闻，不知道这跟自己能买的东西有什么关系。** 根因是占池一半的美股内容根本没有标的物字段：实测近 5 天 us_stock 4163 条中只有 32 条有标的（**0.8%**），全池覆盖率仅 7.5% | **三级取数阶梯，先免费后付费**：<br>① `staging.matched_symbols` 直通（Benzinga 编辑部自标 ticker，覆盖率 98.1%；dxFeed 95%）——零成本、零 prompt 改动<br>② `coin_metrics[].binance_spot == true` 校验加密标的<br>③ 标题品牌名匹配（中英双语）<br>加成**分档**：1–4 个标的 `+0.06`，≥5 个 `+0.02` | [`skill-06-交易实体.md`](skill-06-交易实体.md) | 🔴 **数据一直有，一直在被丢掉**——`matched_symbols` 早就躺在 staging 表里，只被拿去做优先级路由，从没进过事件表。**接一个已有字段的收益，远大于让 LLM 多抽一次。**<br>🔴 **必须分档，不能一刀切**：实测 Benzinga「盘前综述」一条挂 7 个 ticker（DJI/IXIC/SPX/SPY/QQQ/IWM/MSFT），那恰恰是**最没有交易指向性**的内容；真正刺激交易的是"NVDA 财报炸了"这种单主标的事件。不分档会把泛泛综述系统性顶上去，与需求意图正好相反。<br>⚠️ "能买到"必须是**可验证的硬判据**，不能拍脑袋：加密看 `binance_spot`，美股看大盘蓝筹白名单（老板裁决：只标用户认得出的），**日韩港一律 `tradable=false`**（币安用户买不到，标了是噪音）。<br>⚠️ 没有标的物 → 加 0，**不惩罚**。 |
| **7 · 混排策略**<br>`mix` | **即使加了实体加成，用户每天打开看到几条"能买的东西"仍然是随机的。** 加分是连续倾向，分数分布一变比例就变，做不到"打开就一定看得到能买的东西"这个确定性的版面承诺。老板要的是版面结构上的保证，不是概率上的倾向 | 在排序**之后**加一层版面重排：<br>① **实体配额**：每 10 条窗口内至少 X 条有可交易标的（X 可调 0–10），不足则从后面借最高分实体条目、换掉窗口内最低分的非实体条目<br>② **置顶实体**：强制 Top1 / Top3 为实体内容（用插入而非交换，被顶下去的整体后移）<br>③ 两者叠加时**先配额、后置顶** | [`skill-07-混排策略.md`](skill-07-混排策略.md) | ⚠️ **混排是结构性配额，不是又一个加分项**——实时情绪取决于最近恰好发生了什么，不可控；配额是"版面必须长这样"的硬约束。<br>⚠️ 每次搬运必须写 `mix_reason` 字段回卡片（"配额提升（每10条保底N条实体）"/"置顶实体（强制TopN）"）。**被搬上来的条目必须能解释自己为什么在这里**，否则"为什么这条在这"就变成了不可解释的黑箱。<br>⚠️ 整池没有实体内容时**不硬凑**——宁可不满足配额，也不能把无关内容伪装成交易机会。<br>⚠️ 不足一窗（尾部 < 10 条）不强求，否则尾部会被反复搬运。 |

## 2. 关键规则与判定标准

> 这一章是给实现和 QA 看的。每一条都写成**可写断言**的形式。

### 2.1 最终分公式（唯一口径）

```
FinalScore = BaseScore × MarketWeight × Freshness × (1 + Bonus)

BaseScore = 0.26·M + 0.16·B + 0.16·T + 0.14·I + 0.10·H + 0.10·A + 0.08·Q
            影响面   广度    时效    冲击力   热度    权威    质量
            （七项权重合计 100%，可在实验室调，系统按滑杆比例自动归一化）

Bonus     = min( 同向加成 + 反转加成 + 交易实体加成 , cap )
            同向与反转互斥，单条只可能拿到其中一个

最后再过一层 混排（配额 / 置顶），产出最终版面
```

**四条硬规则，任何一处违反都会让这套体系失效：**

| 规则 | 为什么 |
|---|---|
| **R1. 三个查询时倍率（市场 / 新鲜度 / 情绪加成）绝不写回 `importance_score`** | `importance_score` 是"事件本身有多重要"的口径，被去重、策略实验室、历史分析共同依赖。掺进"今天的情绪""我们更关心哪个市场"这些每天都在变的量，昨天的分和今天的分就不可比了 |
| **R2. 改公式必须同时把 `SCORING_VERSION` +1，并重算存量** | 真实事故：全库 3174 行里只有 402 行（13%）是按当时现行公式算的，1865 行停在五因子时代，907 行是某个中间版本。**前端按这个字段排序，等于把三个公式算出的分放在同一个列表里比大小。**<br>最难受的是**这个故障在构造上就是隐形的**：错的分仍然是 [0,1] 浮点数、仍然能排序、页面照常渲染、不报错不告警 |
| **R3. 实验室与生产必须共用同一份排序代码** | 真实事故：新鲜度衰减当天先加进了生产排序，实验室漏了——**同一套权重在两个界面算出不同排名**，生产首屏是当天内容、实验室把 2 天前的旧闻排在前面。实验室的全部意义在于"我在这里调的就是线上跑的那套" |
| **R4. 加分项 cap 是硬封顶，新增加分项必须纳入既有 cap** | 否则叠加起来会突破策略配置里声明的上限，让"封顶"这个概念失效 |

### 2.2 冲击力（I）判定标准

**幅度分档**（`_magnitude_score`）：

| 条件 | 幅度分 |
|---|---|
| 命中极端词（熔断/崩盘/暴跌/闪崩/circuit breaker/rout…） | **直接 1.00**（不看百分比） |
| pct ≥ 15% | 1.00 |
| pct ≥ 8% | 0.75 |
| pct ≥ 4% | 0.55 |
| pct ≥ 2% | 0.35 |
| 其余 / 无幅度 | 0.10 |
| `move_horizon = long_term`（年内累计 / 半年） | 按无幅度处理（0.10） |

**权威共振分档**（`_resonance_score`）——只数**机构媒体/通讯社/一手 API**：

| 条件 | 分 |
|---|---|
| ≥ 3 家 authority≥4 的独立机构 | 1.00 |
| = 2 家 | 0.65 |
| 有 1 家 authority≥5 | 0.45 |
| 其余 | 0.15 |

> ⚠️ **社交源（social）、网页搜索、行情信号、日历一律不计入共振。** 此前一个 5 分的 X KOL 和 CNBC 在这里完全等价，老板裁决"不合理"。**个人影响力 ≠ 机构编辑权威**：转推一条消息的 KOL 再多，也不构成"多家独立编辑室分别核实过"这个信号。

**`price_move` 语义字段判定标准**（这是给 LLM 的判据，完整 prompt 见 skill-04）：

| `is_price_move` | 判据 | 例 |
|---|---|---|
| `true` | 数字是**某个可交易资产的价格 / 指数点位实际移动了多少** | "比特币跌 8%"、"日经 -4.2%"、"Tesla shares surge 12%" |
| `false` | 其余一切，**哪怕旁边就是涨跌动词** | 市占率/dominance、税率/利率/支持率/波动率、覆盖率/占比、财报超预期、分析师目标价、历史统计与季节性、资金流量与持仓、协议治理投票率 |

两个必须写进 prompt 的陷阱：

1. **水平值 ≠ 变动值**。"30 年期美债收益率**升至** 5.26%"——5.26 是它现在**在哪**，不是它**动了多远**，`move_pct = null`。只有"上升 **了** x%"才给 `move_pct`。
2. **有变动无幅度时，`is_price_move` 仍为 true，但 `move_pct = null`**，**绝不允许从文中借一个不相关的数字来填**（"TLT 跌至 10 个月低点"、"黄金创历史新高"）。

### 2.3 大盘情绪判定标准

```
mood_score = Σ(sentiment_score × w) / Σw   ，其中 w = importance × market_weight × freshness
样本 = 近 24 小时内 event_tier ∈ {S, A} 且 sentiment_score 非空 的事件
```

| mood_score | 标签 | 前端配色 |
|---|---|---|
| ≥ 0.50 | 极度乐观 | green |
| ≥ 0.15 | 偏乐观 | green |
| ≥ -0.15 | 中性 | neutral |
| ≥ -0.50 | 偏悲观 | red |
| < -0.50 | 极度悲观 | red |

**两个加分项：**

```
同向加成 = k_align    × |mood_score| × |event_sentiment|    仅当方向相同
反转加成 = k_reversal × |mood_score| × |event_sentiment|    仅当方向相反 且 tier ∈ {S, A}
```

> 两者的乘积形式意味着：**大盘越极端、事件情绪越强，加成越大**；大盘接近中性时两项自然趋近于 0，
> 不需要额外的开关——"没有氛围的时候不要硬造氛围"是公式自带的性质，不是补丁。

**必须提供「手动指定情绪方向」的能力。** 理由不是运营干预，是**反事实推演**：
实时情绪取决于最近恰好发生了什么，不可控；而"**如果此刻大盘极度悲观，我这套权重会把什么顶上首屏**"
才是产品决策真正要回答的问题。没有这个控件，就只能干等到市场真的崩一次才能验证策略。

### 2.4 交易实体判定标准

| 资产类别 | `tradable = true` 的判据 |
|---|---|
| 加密 | `coin_metrics[].binance_spot == true`（币安现货在架） |
| 美股 | ticker ∈ 大盘蓝筹白名单（约 130 支，按 staging 真实出现频次筛出） |
| 指数 ETF | ∈ INDEX_ETF（SPY / QQQ / DIA / IWM / SOXX / XLK / XLE / GLD / IBIT…） |
| 指数本身 | SPX / DJI / IXIC / RUT → **识别但 tradable=false**（买不了 SPX，只能买 SPY） |
| 日 / 韩 / 港股 | **一律 false** |

加成分档：`1 ≤ n ≤ 4 → +0.06`；`n ≥ 5 → +0.02`；`n = 0 → 0`（不惩罚）。

### 2.5 市场重要性默认倍率

| market_scope | 倍率 | 说明 |
|---|---|---|
| `us_stock` 美股 | **1.20** | 全球用户真正关注的市场。显式提到 1.20 而不是留在 1.0——要的是"大大提高"，让界面上也看得出是被**主动提权**的，而不是"别人降了所以它相对高了" |
| `crypto` 加密 | 1.00 | 主场业务，基准 |
| `macro_policy` 宏观政策 | 1.00 | 跨国宏观，天然全球相关 |
| `social_signal` 社会信号 | 0.85 | 地缘冲突 / 自然灾害 / 社会事件，有市场传导路径但间接 |
| `general` 综合 | 0.70 | 归类不明确；也是未知 scope 的兜底值 |
| `hk_stock` 港股 | 0.65 | |
| `jp_stock` 日股 | 0.60 | |
| `kr_stock` 韩股 | 0.55 | 当前问题最集中 |

> **跨市场豁免**：`breadth_level = cross_market` 时倍率不低于 1.00。
> 这是老板那句「日韩是在剧烈波动和大事件（比如芯片暴跌，且这个也会比较大影响美国市场的）的时候才会是大部分用户关心的新闻」的直接编码：
> 「油价飙升拖累 KOSPI 跌 7%」→ 不打折；「韩财长就单一杠杆 ETF 致歉」→ ×0.55。

### 2.6 参数默认值与可调范围（配置表 schema）

```json
{
  "base_weights": {"M":26,"B":16,"T":16,"I":14,"H":10,"A":10,"Q":8},
  "bonus":  {"k_align":0.25, "k_reversal":0.20, "k_tradable":0.06,
             "k_tradable_broad":0.02, "cap":1.00},
  "market_weights": {"us_stock":1.20,"crypto":1.00,"macro_policy":1.00,
                     "social_signal":0.85,"general":0.70,
                     "hk_stock":0.65,"jp_stock":0.60,"kr_stock":0.55},
  "freshness": {"halflife_hours":48, "floor":0.15, "enabled":true},
  "mood":  {"lookback_hours":24, "manual_override":null},
  "mix":   {"min_tradable_per_10":0, "pin_tradable_top":false}
}
```

| 字段 | 范围 | 校验规则 |
|---|---|---|
| `base_weights.*` | 0–100 | 合计必须 > 0；**存库前归一化到 100** |
| `bonus.k_*` | 0–1.0 | |
| `bonus.cap` | 0–2.0 | **`max(k_align, k_reversal) + k_tradable ≤ cap`** |
| `market_weights.*` | 0–2.0 | 上限 2.0 给运营留"某个市场临时置顶"的空间 |
| `freshness.halflife_hours` | 1–720 | |
| `mood.lookback_hours` | 1–720 | |
| `mood.manual_override` | -1.0–1.0 或 `null` | `null` 是合法值，语义是"用实时计算值" |
| `mix.min_tradable_per_10` | 0–10 整数 | |

> 🔴 **cap 校验校的是「单条事件实际可能拿到的最大加成」，不是三项之和。**
> 我们最初写成三项相加，那对应一个**永远不会发生**的场景（同向与反转互斥）。
> 直接后果是加了交易实体之后 `0.25+0.20+0.06 = 0.51 > 0.50`，**连默认配置都存不进去**，
> "存为基线"整个功能挂掉。

> ⚠️ **超界一律拒绝，不要夹紧。** 夹紧会让"我明明填了 500"静默变成 200，
> 用户以为生效了其实没有，**比报错更难查**。

### 2.7 配置读写的宽严原则

**读要宽**（任何失败都退化成代码里的默认值，绝不抛异常）：表不存在 / 表是空的 / payload 不是合法 JSON / 缺字段 / 类型不对 / 数据库连不上 → 一律返回 DEFAULTS。
排序是产品主路径，配置表是它新增的一个依赖——**依赖越多，坏掉的方式越多**。

**写要严**（拒绝任何不认识的键、越界的值、对不上的归一化）。
一份坏配置一旦置为 active，影响面是全站排序。**校验必须在写入这一侧，前端那份只是体验优化。**

## 3. 需求详述与验收标准

### P0 —— 不做就等于没做这一轮

#### P0-1 内容理解阶段产出三个新字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `market_scope` | enum(8) | 美股/加密/宏观政策/社会信号/综合/港股/日股/韩股 |
| `breadth_level` | enum(5) | cross_market / market_index / sector / multi_asset / single_asset |
| `price_move` | object | `{is_price_move: bool, move_pct: float\|null, move_horizon: enum(4)}` |

**验收：**
- [ ] 三个字段进 JSON schema 的 `required`，缺一个就让这次理解失败重试（不允许静默缺失）
- [ ] `price_move` 走真实模型跑一遍第 2.2 节的全部反例，**通过率 = 100%**（我们的实测基线是 12/12）
- [ ] 用「收益率升至 5.26%」和「TLT 跌至 10 个月低点」两条专门校验：都必须 `is_price_move=true` 且 `move_pct=null`
- [ ] 存量数据（没有 `price_move` 的行）走正则兜底，冲击力**不为 0**
- [ ] 加列后做**写入-读回往返验证**，不能只看返回码

> 🔴 **最后一条是血的教训**：我们加列时占位符少写了一个（41 个 `%s` 对 42 列），
> 写库**全部失败但不抛异常**（异常被 catch 住、只打 warning、返回 0），
> 表现是日志里一行 `wrote/updated 0/4`——**如果不是盯着这个数字，会被当成"本轮没新事件"混过去**。

#### P0-2 排序改为四段式，且实验室与生产共用同一份代码

**验收：**
- [ ] 生产排序与实验室重排走**同一个函数**，传入不同配置
- [ ] QA 断言：同一组参数下，两条路径的 Top20 **逐条 id 相同**
- [ ] `SCORING_VERSION` 与存量对拍断言：全库存量分与"按当前公式重算"逐行比对，对不上直接红
- [ ] 关掉全部加分项（系数调 0）能干净退回纯基础排序 —— 这也是验证加分项真实贡献的 A/B 对照方式

#### P0-3 策略配置表 + 存为基线 + 版本回滚

**验收：**
- [ ] 第 2.6 节全部字段可读可写，校验规则逐条生效
- [ ] 存默认配置能成功（cap 校验按 2.6 的口径，不是三项之和）
- [ ] 配置表删表 / 清空 / 塞脏 JSON / 断连 —— 四种情况下排序都**不挂**，退回默认值
- [ ] 回滚不复制成新版本，`version` 号保持线性可读

#### P0-4 交易实体识别与展示

**验收：**
- [ ] 三级取数阶梯全部接通，`matched_symbols` 从 staging 一路透传到事件表
- [ ] 覆盖率从 7.5% 提升到 **≥ 40%**（demo 实测口径）
- [ ] 日韩港标的 `tradable=false`，SPX/DJI/IXIC `tradable=false`
- [ ] **Top10 实际命中数与全库覆盖率一起报**，不能只报聚合数字

> ⚠️ 上一次我们报过"美股覆盖涨 18 倍"，而**首屏 0/10 有标签**——聚合覆盖率会掩盖首屏。

### P1 —— 强烈建议同期做，晚一个迭代也能接受

- **P1-1 混排策略**（第 1 章 #6）。验收：配额从 0 调到 6，Top10 实体条数确实从 N 变成 ≥6；置顶开启后 Top1/Top3 必为实体条目；每条被搬运的都有 `mix_reason`
- **P1-2 策略实验室**：七因子滑杆 + 加分项滑杆 + 市场倍率滑杆 + 情绪方向控件 + 混排开关，两版本并排对比。验收：**每一个控件调了都必须让排序真的变**
- **P1-3 卡片可解释性**：每条展示 `factors`（原始分）、`contributions`（加权贡献值）、`bonus` 明细、`market` 明细（含是否命中跨市场豁免）、`mix_reason`

> 🔴 **P1-2 的验收断言不是形式主义。** 我们真的出过：`k_tradable` 滑杆完全是死的——
> 请求解析那一层有一份**手写的**参数白名单没有加这个键，滑杆调到 0 和调到 0.20 排序**完全一样**。
> **根治办法是所有参数名单从配置 DEFAULTS 渲染出来，不允许任何地方手写第二份。**
>
> 同族的坑我们**在这个项目里踩了五次**：取数 SQL / 计算 / 请求解析 / 响应序列化 / 界面渲染
> 是**五个独立环节，漏哪一处都不报错**。加一个因子必须五处一起改。

### P2 —— 本轮不做，但架构上要留出口子

- **召回池退热**：S/A 档事件与高点击事件生命周期延长到 7 天，其余 2 天（当前是全量 5 天硬闸）。依赖点击事件流回传，**目前尚未接入，架构图上是目标态**
- **LLM 直接抽取交易实体**：覆盖长尾 RSS / 搜索来源。改 prompt 会让整个理解缓存失效，需单独排期
- **效果度量闭环**：曝光/点击回传 → 后验标签 → 反哺排序。**这是所有策略的前提**，没有它，上面所有参数都只能靠人眼判断好坏

## 5. 非目标（本轮明确不做）

| 不做 | 为什么 |
|---|---|
| **不做个性化排序** | 本轮解决的是"全局默认排序像不像一个懂市场的人排的"。个性化是另一个量级的工程，且没有默认排序的基线就无法度量个性化的增益 |
| **交易实体不做可点击跳转** | 老板裁决"纯展示不可点，先这样"。一旦可点就涉及行情页跳转、标的合规校验、买入引导，是独立需求 |
| **不新增"社会经济重大影响"因子** | 已被 M（影响面）+ B（广度）覆盖两遍，再单列就是**三重计分** |
| **不给冲击力做金额/点数提取** | 只做百分比。金额要处理亿/万/M/B 多种量纲，点数要知道指数基数才有意义，而百分比已覆盖绝大多数有冲击力的标题，量纲统一、误判风险最低 |
| **不给单一信源开后门** | 曾经为 CNBC 做过"硬覆盖"（权威分抬到 1.0 + 总分 +0.05）。那是对"prompt 媒体名单与权威表不同步"的补丁，**根治方案是单一事实源 + 名单动态渲染进 prompt**，补丁随病根一起拆掉 |

## 7. 排期建议

**不要按"能力"切分迭代，按"能不能验证"切分。** 建议三段：

| 阶段 | 内容 | 为什么这么切 |
|---|---|---|
| **第一段：能看见** | P0-1 三个字段 + P0-3 配置表 + P1-2 策略实验室 | 没有实验室就没法验证任何参数。**先建尺子，再量东西** |

**依赖**：第一段的 `price_move` 会让内容理解的缓存整体失效，需要一次全量重跑，请与数据工程 Scout 对齐重跑窗口与配额。
