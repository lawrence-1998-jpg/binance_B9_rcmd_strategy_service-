Executive Summary

00结论先行

上一版 PRD 你说没问题，只要把重心从「币安那个咨询项目」换成你本人—— 咨询顾问和字节产品经理两个身份，加上和老公的生活、国庆规划。这一版就是那个改法， 并且已经写完了。

四个 tab + 一个速记键

今日 · 工作 · ⊕ 速记 · 生活 · 复盘。 工作里分「咨询 / 字节」两条线，生活里分「我们俩 / 国庆」两块。速记在正中央凸起。

你保留的那条反指标

日均打开超过 15 次 = 设计失败。它变成了一个会让你刷的 app， 而不是工具。这条留着，并且它约束了下面每一个设计决定：没有红点、没有逾期计数、 没有推送、没有智能推荐。

三处最花心思的地方

① 今天的重心是全屏唯一的深色反底块，一天只允许写一句；
② 四条线用四个色相，但颜色只出现在 3px 细条和小圆点上，卡片永远是中性米白；
③ 复盘屏的文案写「今天挺好」而不是「你还差 1 件」，没做完的自动顺延、排在完成项后面。

数据在你自己手上

没有后端，没有账号，不上传任何地方。全部存在浏览器本地， 设置里能导出 / 导入 JSON。包括「我们俩」那部分——它不该出现在任何服务器上。

关于把它放在这个仓库里

代码在 desk/，构建产物在 web/desk/。这是你自己的 GitHub 仓库， 不是公司组织下的，所以放这儿没问题。但如果以后要把仓库分享给同事， 建议先把这两个目录拆到一个私有仓库——里面有你的生活内容。

Research

01调研：先搞清楚什么会失败

做工作台最容易犯的错，不是功能少，是把桌面看板等比缩小：模块一个不删，字号一路缩到 11px，最后自己都不打开。下面四条是这次调研里对我们最有约束力的结论。

A. 信息密度有硬上限

一份覆盖 75 项研究的综述里，信息过载是仪表盘的头号问题，影响 46.7% 的用户；实验显示模块数量到 9 个以上 人就开始被压垮，而人的工作记忆一次只能拿住 3–5 项。

落到设计上

首页模块数 ≤ 6；首屏（不滚动）里需要你做决定的东西 ≤ 3 条。今日三件事就是三条，不是三十条——多出来的沉到「稍后」。

B. 拇指决定了导航长什么样

单手握持时，拇指的舒适弧区大约是屏幕下方 40%。底部导航建议 3–5 项，4 项是甜点；触控目标不小于 44–48px；正中央那一格最省力（这也是 iOS 相机把快门放中间的原因）。

落到设计上

4 个 tab + 正中央一个凸起的速记键。所有高频操作（勾选、速记、复制 prompt）全部落在屏幕下半部；标题和状态可以放上面，因为那些是读的，不是点的。

C. 「智能」在 2026 仍然不值得赌

上下文感知（根据时间 / 会议 / 最近访问自动换内容）在 2026 年多数仍是实验性的：系统猜错的频率高到用户干脆把功能关掉。

落到设计上

只做确定性的时间切换：18:00 后首页底部把「晚间收尾」提上来，仅此而已。不做智能排序、不做「猜你想看」。你自己定的今日重心，永远压过任何算法。

D. 好用的日程工具赢在「情绪」而不是功能

Sunsama 这类产品被反复称赞的点是：它让你感到平静，而不是让你感到落后——会在你排太满时警告你、有明确的每日收尾仪式、界面极简。而不是列出你欠了多少。

落到设计上

三条硬规矩：不显示逾期总数；不用红点角标；今日三件事的上限就是三件，想加第四件必须先挪走一件。稀缺感由界面来强制。

E. 视觉趋势正好站在 Organic 这边

2026 的主流方向是编辑设计（editorial / print）影响下的柔和界面：低饱和中性色打底、小面积强调色、用层次和阴影而不是颜色做层级，排版占更大权重。你仓库里那套米白纸感 + 赤陶 + 鼠尾草，本来就在这条线上——这次不需要换风格，只需要换尺度。

唯一一条与趋势相悖的选择：v1 不做深色模式（82% 的用户偏好深色）。理由见 PRD 的「非目标」。这不是忘了，是排了序：深色版要把整套色阶的对比度重调一遍，属于一整轮设计工作，不该挤掉 v1 上线。

Product Requirements

02PRD

2.1 用户只有一个人，这是特权

使用者是你。不做权限、不做协作、不做引导教程、不做偏好设置、不考虑首次使用体验。 每砍掉一个通用性，就换来一份锋利。

但也带来一个真实风险：自建工具的死法不是「不好用」，是「三周后没人维护」。 所以 v1 砍到五个屏、三个运行时依赖、零后端——小到你不会嫌麻烦。

2.2 六个瞬间：功能是从场景里长出来的

手机和电脑的区别不是屏幕大小，是你在什么状态下拿起它。 这六个瞬间就是全部需求来源。

#瞬间你心里大概在想入口
1早上通勤今天最重要的是哪件事今日 · 重心 + 三件事
2客户会前两分钟这个项目现在卡在哪来着工作 · 咨询
3字节的会议间隙那个需求评审排到哪天了工作 · 字节
4灵光一闪 / 他随口说了句什么赶紧记下来，别忘了⊕ 速记

以后任何一个想加的功能，如果不能被指回上面某个瞬间，就不加。 这是防止工作台长成四不像的唯一有效办法——包括你自己想加的时候。

2.3 目标与非目标

目标

  • 五秒定位：打开到知道「现在该干嘛」，不超过五秒、不需要滚动。
  • 零摩擦捕捉：从想记一件事到记完，一次点击 + 打字，不需要选分类。
  • 两条线不混：咨询和字节是两种节奏、两种语言，界面上一眼分得开。
  • 生活不是附属品：它和工作平级，占一个完整的 tab，不是塞在角落的小卡片。

非目标（写下来是为了以后不反悔）

  • 不做全功能编辑器。手机上只写「一句话」，长文永远回电脑。
  • 不做多人 / 分享。包括不做「和老公共享清单」——那需要账号和服务器， 而「我们俩」那部分的内容不该离开你的设备。想让他看，截图给他。
  • 不做推送通知。通知是留存的毒药也是解药，先证明你自己会主动打开。
  • 不做深色模式（v1）。这套 Organic 是纸感体系，深色版要重调整套色阶对比度， 属于一整轮设计工作。token 已经在文档里备好，想要的话一天能上。
  • 不做日历同步。会议靠手填。接飞书 / Google 日历需要 OAuth 和后端， 先看你会不会用，再决定值不值得。
  • 不做智能推荐 / 自动排序。见调研 C。

2.6 数据：一行都不上传

全部存在浏览器本地

键 deskside.v1，存在 localStorage。没有后端、没有账号、没有任何网络请求。 「我们俩」那部分尤其不该出现在任何服务器上——这是不建后端最实在的理由，不只是图省事。

一个 store 文件挡在中间

所有屏只跟 src/lib/store.ts 打交道。以后真要加同步，只改这一个文件， 五个屏一行不用动。先分层，再写界面。

数据按「来源」隔离，这是唯一的坑

file:// 打开的单文件、localhost 服务、手机上的地址， 三者的数据互不相通。选定一种用法就一直用；要换，先导出 JSON 再导入。

每周导出一次

清缓存、换设备、换浏览器都会丢。设置里一键导出 JSON。 这条不是客套——本地存储真的会没。

Design System

03UI 规范：Organic 的移动重构

不换风格，换尺度。桌面那套 Organic 的色相、字体、药丸形态全部保留；改的是三件事：卡片的明度关系、字号阶梯、以及排版的中西分工。

3.1 六条设计原则

一屏一问句

每个页面必须能一句话说出「它回答什么」。说不出来的页面砍掉，说得出但答得慢的页面重排。

先摘要，后细节

状态先用形态表达（点 / 环 / 方块），数字是第二眼的事。一眼扫过去应该只看到「绿了还是没绿」。

拇指优先

可点的东西尽量往下放，读的东西可以往上放。行高 ≥48px，图标热区 ≥44px，相邻可点元素间距 ≥8px。

平静优先于完整

宁可少显示，不制造焦虑。没有红点、没有逾期计数、没有"你还有 27 项未完成"。

捕捉与整理分离

记的时候不要求分类，分类是复盘时的事。任何在捕捉环节加一步的设计都是错的。

手机不做危险事

破坏性 / 影响线上的操作，在手机上一律降级成「标记」，回桌面再执行。

3.2 色板

纸感米白打底不变。变化在于：这版工作台要同时装下四条互不相干的人生线，所以在 Organic 原有的赤陶 + 鼠尾草之上，扩了两个色相，并新增一个语义色。

一条硬规则，不然整屏会炸

四个色相同屏出现，很容易变成「每样东西都在喊」。所以：领域色只允许出现在 3px 标识条、小圆点、chip 和分区头的色块上，绝不做卡片底色、绝不做大面积填充。 卡片永远是中性的米白，颜色只负责「这是哪条线」，不负责「这很重要」。

语义色和领域色分开

鼠尾草 #7a8a5e 只表示「正常 / 完成」，砖红 #b3402c 只表示 「阻塞 / 破坏性操作」。它们不属于任何一条线——一个咨询项目卡住了， 卡点那行字是砖红，不是赤陶。这样扫一眼就知道「哪条线」和「什么状态」是两件事。

砖红全站出现频率应低于 1%。它一出现就该扎眼。

与桌面版的关键差异：卡片比底色亮，不是暗

桌面 Organic 里卡片 #ebddc5 比页面底 #f5ead8 暗。手机上必须反过来——卡片 #fdf8ef 比底色亮，#ebddc5 降级为「内嵌槽」（进度条底、输入框底）。

为什么改

手机会在户外强光下用。屏幕反光会整体抬高黑场，暗卡片和暗底色会糊成一片，层级消失。让卡片比底色亮，在阳光下依然能看出「这是一块」。这是移动端特有的物理约束，不是审美偏好。

3.4 间距与网格

4pt 基准，只用 4 / 8 / 12 / 14 / 18 / 24 / 32 七个值。屏幕左右安全边距 15px（在 iPhone 上让 344 宽的内容区左右各留一指），卡片内边距 14px，卡片间距 9px，分区间距 18px。

底部必须处理刘海机安全区：

/* index.html 的 viewport 必须带 viewport-fit=cover */
<meta name="viewport" content="width=device-width,initial-scale=1,viewport-fit=cover">

/* tab bar 垫上系统 home indicator 的高度 */
.tabbar{ padding-bottom: calc(6px + env(safe-area-inset-bottom)); }
/* 顶部同理，standalone 模式下状态栏会压上来 */
.appbar{ padding-top: calc(10px + env(safe-area-inset-top)); }

3.5 状态编码：不靠颜色单打独斗

色盲用户、强光、截图转灰——任何一种情况下颜色都可能失效。所以三种状态同时用形状区分：

正常 实心圆 · 鼠尾草 注意 空心环 · 赤陶 故障 方块 · 砖红

另外：只有「正常」有脉动动画。故障状态静止不动——反直觉但正确，动的东西看起来像还在运转，静止的方块才像死掉的进程。

3.7 动效

场景时长缓动

两条来自你自己踩坑记录的红线，这次照抄

一、不要用毛玻璃 backdrop-filter，尤其不要用在含无限循环动画的容器上——脉动绿点 + 高斯模糊会让浏览器每帧重算，整页闪烁。案头的顶栏和 tab bar 一律不透明纯色。
二、固定定位的 tab bar 加 transform:translateZ(0) + contain:layout paint，防止部分机型滚动撕裂。
另外全局加 @media (prefers-reduced-motion:reduce) 兜底。

3.8 无障碍与手感底线

  • 正文对比度 ≥ 4.5:1，大字 ≥ 3:1。#6b6255 在纸底上是 5.9:1，#9a9083 只有 2.9:1——三级文字只能用于装饰性信息，不能承载唯一信息。
  • 触控目标 ≥ 44×44，相邻间隙 ≥ 8px。
  • 状态不只用颜色表达（见 3.5）。
  • :focus-visible 用赤陶 2px 描边，不留浏览器默认蓝框。
  • 所有图标按钮带 aria-label；勾选框用真的 <input type="checkbox"> 而不是 div。
  • 动态字号：用 rem 而不是 px 定字号，尊重系统放大设置。

How to run it

05怎么把它放到桌面上

三种用法，挑一种就好。先说最重要的一句：数据按「来源」隔离， file://、localhost、手机上的地址，三者数据互不相通。 选定一种就一直用它；要换，先导出 JSON 再导入。

① 桌面 · 最省事（推荐先用这个）

双击 web/desk/deskside-standalone.html。

这是一个自包含单文件：JS、CSS、图标全内联进一个 HTML， 不需要任何服务器，断网也能用。想要 Dock 图标，把这个文件拖到 Dock， 或者在 Chrome 里「⋮ → 投放、保存和共享 → 创建快捷方式」。

为什么要单独做一份

Vite 正常构建出来的是 ES module，浏览器不允许从 file:// 加载外部 module （CORS 限制），双击打开会白屏。所以单文件版把脚本内联进 HTML——内联 module 不走网络请求， 就绕开了这条限制。这一条是实测出来的，不是想当然。

② 桌面 · 真的 App 窗口

# 零依赖，只要有 python3
cd desk && ./run.sh

浏览器打开 http://localhost:5173 → Chrome 地址栏右侧的安装图标 → 装到桌面。 装完有独立窗口、独立图标、Dock 里单独一个位置，离线也能开（service worker 会缓存）。

③ 手机

把 web/desk/ 部署到能访问的地址（现有 Flask 站点直接就能托管，路径 /desk/）， 手机 Safari 打开 → 分享 → 添加到主屏幕。启动后没有地址栏，和原生 app 一样。

工程结构

desk/
├─ run.sh                    本地起服务（python3，零依赖）
├─ vite.config.ts            正常构建 + PWA
├─ vite.config.single.ts     单文件构建（双击即用的那个）
├─ scripts-gen-icons.py      生成 PWA 图标，纯标准库
└─ src/
   ├─ styles/tokens.css      ← 改配色/字号/间距只改这里

   ├─ lib/                   types · date · seed · store
   ├─ components/            ui · icons · TabBar
   └─ screens/               Today · Work · Life · Capture · Review · Settings

依赖只有三个

react · react-dom · vite（加两个构建插件）。 没有 UI 组件库、CSS-in-JS、图表库、日期库、图标库、路由库。

没装什么为什么
UI 组件库Organic 这套形态（药丸、大圆角、纸感）跟任何现成库都对不上，改库比自己写慢
路由库五个屏不值得。hash 路由三十行搞定，而且 file:// 下能用——这点决定了单文件方案成立
状态库useSyncExternalStore + 一个 Set 的订阅者，四十行
图表库就一根分布条和几个进度条，CSS 就够
日期库Intl 和 Date 够用；中文日期（「九月二日 · 周二」）自己写了十行
图标库需要十二个图标，手写 SVG，总共不到 2KB

结果：59KB gzip，首屏几乎瞬开。

改动时别踩的线

  • 配色只改 tokens.css，组件里不许写死颜色。
  • 领域色只做 3px 条 / 小圆点 / chip，绝不做卡片底色。
  • 不要用 backdrop-filter——页面上有无限循环的脉动点， 毛玻璃会让浏览器每帧重算，整页闪烁（这是你仓库里已经踩过的坑）。
  • 固定定位元素保留 transform:translateZ(0) + contain:layout paint。
  • 状态不能只靠颜色：正常=实心圆、注意=空心环、阻塞=方块。
  • 今日三件事的上限就是 3，这个摩擦是故意的。
开发过程中真实修掉的四个 bug

记在这儿是因为它们都是「写完看不出来、跑起来才发现」的那类：
① CSS 类名撞车：.focus-v.empty 被空状态组件的 .empty （display:flex; text-align:center）盖掉，重心那句话被居中了；
② 标题和副标题连成一行：span 默认 inline，忘了给 display:block；
③ 图标撑满整屏：SVG 没给默认尺寸；
④ 勾选点不动：把「点标题展开菜单」塞进了 label 里，preventDefault 把勾选吃掉了——这条是设计错误，不是实现错误，最后把次要操作拆成了独立的 ⋯ 按钮。

How to

06怎么自己设计出这样的界面

这一节是方法，不是这个项目的内容。学会了下次做别的界面也能用。

6.1 五步法：颜色是最后一步

定人和瞬间，不是定功能

先写清楚「谁、在什么时刻、拿着手机想干什么」。本文档 2.2 的六个瞬间就是这一步的产物。跳过这步直接列功能，做出来的一定是四不像。

把每屏写成一个问句

「现在该干嘛？」「我卡在哪？」「我以前怎么做的？」。一个屏答不出一个问句就砍掉。这一步能砍掉 60% 的伪需求。

排层级：这屏最重要的是哪一件事

每屏挑出唯一一个「最重要的东西」，其它全部让位。今日屏是「今天的重心」，所以只有它用了深色反底。选出两个就是没选。

画灰度稿

只用黑白灰摆块，不碰颜色。灰度稿里层级清楚，上色只是加分；灰度稿里层级不清，再好看的配色也救不回来。这是整个方法里最值钱的一条。

最后上色，且只上一处重色

色板早就定好了（用现成设计系统就更省事）。上色时把最饱和的那个颜色只给「最重要的那件事」，其余用中性色。

三个阶段长这样

阶段一 线框 · 只管有什么
阶段二 灰度 · 只管层级
阶段三 上色 · 只管一处重色

注意阶段二：那块最深的灰就是「今天的重心」。层级是在灰度阶段建立的，颜色只是把它说得更清楚。如果你把阶段三的色块全部去饱和，会得到跟阶段二几乎一样的图——这就是对的。

6.2 五条随时能用的判断法则

法则怎么用
先灰度任何界面卡住了，就截图转灰度看。层级消失说明你在用颜色掩盖结构问题。
一屏一重点全屏最亮 / 最深 / 最大的东西只能有一个。数一数，超过一个就降级。
间距靠系统只用 4 的倍数。凭手感调出来的 13px、17px、23px 是界面显廉价的头号原因。
状态别只用颜色颜色 + 形状 + 文字，至少两样。截灰度图还能分辨才算过。
删到不能删先狠删，删到界面缺信息了再加回一样。加出来的和删剩的，是两种质量。

6.3 反面教材：同样的信息，两种做法

✕ 常见做法
六个等大的指标格 + 四种互相竞争的颜色。每样东西都在喊，等于没有东西在说话。而且这是把桌面 KPI 看板直接搬到手机的典型结果。
✓ 案头做法
一个深色重点 + 一块状态 + 一块列表。三层，一眼就知道先看哪里。信息量其实没少，少的是"同时要求你注意"的东西。

6.4 你 review 设计稿时用的四个测试

眯眼测试

眯起眼睛看到糊，还能看出哪块最重要 → 层级过关。看到一片均匀的灰 → 层级失败。

五秒测试

盯五秒后合上，说出你看到了什么。说不出来，说明首屏信息组织有问题，不是你记性差。

单手测试

单手拿手机，拇指够不到的地方放了高频操作 → 打回。这条最容易在设计稿上被忽略，因为你在电脑上用鼠标看稿。

断网测试

飞行模式打开。白屏或者转圈不停 → 三态没做。这是最能区分「做完了」和「做好了」的一测。

6.5 你已经有的优势

仓库里那套 Organic 设计系统（docs/design_source/organic-styles.css）已经把最难的部分做完了：色阶是在 OKLCH 上统一明度生成的，意味着赤陶的 500 和鼠尾草的 500 视觉深浅一致。这种东西手调是调不出来的。

所以你做新界面时，永远从那份变量表开始，而不是从取色器开始。设计系统的价值不是好看，是让你不用每次重新做一遍这些决定。
