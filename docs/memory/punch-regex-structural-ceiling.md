2026-07-31 B9 全系统检修：冲击力因子(I)误读统计数字为涨跌幅（税率20%/占比72%/
EPS超预期30.67%/目标价上调5.1%全被当成价格波动）。没有照抄审计 finding 的
修复建议原文，先把 8 个抽样案例的**真实** title/description 从库里挑出来逐条
推演排除正则（`_PCT_NOT_MOVE_RE` + 窗口）的命中路径，发现失败模式其实有四种、
只有两种能靠"加词/加宽窗口"解决：

1. **纯词表漏词**（"税"/"覆盖"/"收窄"不在黑名单里）→ 加词直接解决
2. **关键词离数字差几个字符超出窗口**（"占比"在词表里，但"占比升至创纪录的
   72%"里修饰语把它推出 5 字符窗口）→ 可以精确算出安全的加宽边界：用一个
   "必须排除"的真实案例和一个"必须放过"的真实反例互相做上下界，两者的交集
   就是安全窗口——这次是 8（不是拍脑袋，是两个真实句子算出来的）
3. **长距离分句分隔**（"较预期3.30美元**高**28.48%"——关键词和数字之间插了
   具体金额；"目标价从175美元上调至184美元…约5.1%"——隔了20+字）→ **任何
   安全窗口都够不到**，因为中间插入的内容长度不固定
4. **开放式短语空间**（"2026年上半年DeFi锁仓…跌38%…跌42%"——半年回顾统计，
   但没有说"同比"或"环比"这两个已在词表里的字面词）→ 这类回顾性表述的
   变体几乎无限，词表永远追不完

英文侧还有第五种：**跨语言同义词歧义**——"占比"对应的英文可能是"share"，
但"share"同时是"股价份额"的常用词（"Tesla shares surge 12%"是真实涨跌），
加入黑名单会把大量真实新闻错杀，属于"能查出来但不能安全修"的情况。

**Why**：模式 3、4、5 不是"词表不够全"，是关键词邻近匹配这种机制本身在
面对"语义关系跨越不定长文本"或"同一个词在不同语境意味不同的事"时的结构性
局限——继续加词只会不断产生新的误伤风险（每加一个词都要重新验证不会误杀
`_EXTREME_WORDS_RE` 类的真实暴涨暴跌案例），边际收益递减、维护成本递增。
这次修复后 8 个抽样案例 4/8 确认修复、4/8 精确定位到天花板，比笼统地说
"改好了"或"改不好"更有价值——4 个具体失败案例可以直接喂给未来的 LLM
`is_price_move` 语义字段设计。

**How to apply**：
1. 遇到"关键词/正则判定语义对不对"类 bug，先用真实数据逐条推演命中路径，
   不要直接照抄审计/finding 报告里的转述文字去改代码——转述会丢失影响
   修复方案的关键细节（这次原始 finding 转述掩盖了"较预期…高X%"这种插入
   任意长度金额的真实句式）。
2. 分类失败案例：纯漏词/窗口边界 → 可以安全打补丁，且要用"必须排除"和
   "必须放过"两个真实反例互相做边界算出安全参数，不是凭感觉放宽。
   长距离分隔/开放式短语/跨语言歧义 → 打补丁已经到收益递减点，如实报告
   "确认仍有缺口，根因是机制局限不是漏词"，推荐升级判定机制（通常是让
   LLM 在 enrich 阶段直接标注语义字段），并把具体失败案例作为设计输入。
3. 不要为了让指标好看而把有歧义风险的词也塞进黑名单（如"share"）——
   宁可承认修不完，也不能引入新的误伤。
