判断"这条内容属不属于某个要排除的类别"时，关键词黑名单单独用**不可靠**，
必须再配一道让模型自己判类别的语义闸。

**Why:** 2026-07-29 在 B9 的 A 股排除上，同一张关键词表一天之内漏了三次，
每次都是同一个错误模式：
1. 写了指数全称"上证综指"漏了简称"上证" → 漏网条目排到策略实验室第 1 名
2. `A股` 加 IGNORECASE 把任何"字母 a 结尾的公司名 + 股"都命中 →
   **误杀** Meta / GE Vernova 等美股，而美股偏少正是当时要解决的问题
3. 写了"创业板指"漏了"创业板" → 漏网条目排到主站首屏第 3 名

穷举措辞这条路本身就走不通：正例的措辞是开放集合，负例（误杀）也是。
每补一次都以为补完了。

**How to apply:** 两道闸分工——关键词表放在 LLM **之前**做省钱粗筛（挡掉最
明显的一批，别指望它完备）；真正的判定交给 LLM 输出的枚举字段，在 LLM
**之后**整类丢弃。要排除的类别也要在 schema 里给一个**正确的名字**
（如 `market_scope = cn_a_share`），不要为了"不想要"就把它从枚举里删掉——
删掉只会逼模型把它塞进 general，反而更难识别。

另外：过滤器查的字段和 LLM 改写的字段要对齐。查原始标题的过滤器拦不住
"模型改写后才出现的措辞"，这不是配置问题，是结构问题。

**2026-07-30 补（双语场景）**：扫拼接双语文本的关键词规则，排除表和窗口都
必须双语各配一套——B9 冲击力幅度误读连修三轮：中文词补齐后英文标题原样漏进；
英文词加了但"5 字符窗口"对英文结构性不足（buying 距 62% 有 12 字符），而放宽
字符窗又会误杀中文。终解：中文窄字符窗 + 英文按词取窗（前后各 3 词），两套
口径并行。教训同根：只修一种语言 = 没修。
