2026-08-02 Lawrence 明确要求：**"后续做功能优化要覆盖全，不要只做一部分或者
漏需求"**。

起因：交易实体（tradable tag + bonus 加分项）我在主站（tab02 数据展示）做完就
报交付了，**策略实验室（tab05）既没显示实体标签、也没有加分调节滑杆**——而
实验室恰恰是他调策略的地方，缺了滑杆等于这个加分项没法调。他当场指出
"评测实验室里面要加上实体标签。和我一开始说的加分调节器呀"。

**Why**：这个项目的同一个能力通常有**多个消费面**，各自独立实现：

    主站列表(tab02) / 策略实验室(tab05) / 评测工具(tab04) / App模拟器 /
    tab03 API字段字典 / tab07 监控看板 / 对外 api-integration-guide.md

只做其中一处不会报错、页面也不会崩，只是"在别的地方看不见"——和本项目反复
踩的"手写副本必腐化""投影缺列"是同一族问题：**坏了不报错，只是静默地缺**。
而且用户提需求时往往只描述一个场景（"标题后加tag"），真实期望是这个能力在
所有相关界面都在（他后半句"和我一开始说的加分调节器"说明加分项的可调性
从一开始就在需求里，是我读需求时把它窄化成了后端逻辑）。

**How to apply**：
1. 做任何新增字段/因子/标签前，**先把消费面列成清单**（上面那 7 个是本项目
   的默认候选），逐个判断"这里要不要出现"，明确不需要的也写一句为什么。
2. 新增**可调参数**时，"能配置"必须包含三件事才算完整：配置项落
   strategy_config、实验室有调节控件、改了能实时看到重排结果。只做第一件
   就是死配置（已有专门教训 [[config-must-render-into-prompt]]）。
3. 交付话术不要用"已完成"，用"在 X/Y/Z 三处已验证，A 处不适用因为…"，
   把覆盖面显式讲出来——讲不出来就说明自己也没盘过。
