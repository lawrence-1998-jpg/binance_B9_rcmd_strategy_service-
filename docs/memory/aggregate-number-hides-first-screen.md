2026-08-02 B9 做"交易实体 tag"，回填后报出"1929 条有可交易标的、美股从 32 条
涨到 598 条"，看起来是 18 倍的大胜。但真去查首屏美股 10 条，**0/10 有标签**。

根因：阶梯①（编辑部 ticker 直通）只覆盖 Benzinga/dxFeed，而排序靠前的美股
事件实测来自 CryptoBriefing / Google News / PANews——这些源压根不提供 ticker。
"全库 598 条"是真的，但**用户打开首页看到的恰好全在覆盖不到的那 85% 里**。

**Why**：覆盖率是对全库均匀取的平均值，而用户只看排序最前的十几条。当"有没有
覆盖"与"排得高不高"两件事由**不同机制**决定时（这次：ticker 来自哪个源 vs
重要性打分），两者的相关性可以接近零甚至负相关，平均值对首屏毫无预测力。
同一天还栽过一次同类：审计报"punch 覆盖率 23.9%"，而首屏 Top3 全部带误读
——也是"整体数字还行、头部全错"。

**How to apply**：
1. 任何"覆盖率/命中率/准确率"类成果，**报全库数字的同时必须报首屏（Top10/
   Top20）实际命中**。两个数差距大就说明有结构性偏差，要么补机制要么如实说明。
2. 发现首屏为 0 时不要急着调参，先查"排在前面的这些是靠什么进来的"——这次
   一查就发现是信源结构差异，解法是补一层零成本的标题匹配，而不是动排序。
3. 别用聚合数字代替看一眼。只报 598 那个数字的话，交付出去老板打开首页
   就会当场看到没有 tag。
