2026-07-26 出过一次真实事故：用户说"策略实验室 也是改成tab的模式 不要一拉到底"
+ "子tab"，这条需求**没落TODO、没记进原始需求留痕文档、没做**，几天后被用户
发现追问。同期一句"记得加一个导航栏"也被我实现成顶部横排 tab（用户想要的是
侧边栏）就直接标完成了。

**Why**: 我对"一次给五六项的大段需求"严格执行了留痕纪律（见
[[task-tracking-discipline]]），但把**短句**当成了对话上下文而不是需求条目——
尤其当它出现在我正忙别的事的时候（当时在回答 pipeline 耗时问题），注意力在
别处就彻底蒸发了。需求的重要性和它的字数无关。

**How to apply**:
1. 判断标准是"这是不是在要求一个结果"，不是"这句话有多长多正式"。是的话先落
   TODO + 留痕，再动手。
2. UI/交互形态类需求（导航、布局、tab形态）完成后要给截图或明确说清做成了
   什么形态（"做成了顶部横排"而不是含糊的"导航栏已实现"），让形态误解当场
   暴露而不是几天后。
3. 需求措辞模糊时（"加个导航栏"可以指顶部也可以指侧边），要么问一句，要么在
   交付说明里写明"我理解成X了"，不能默默挑一个对自己最省事的解释就标完成。
4. 写描述现状的文档前先看代码/页面确认——那次我把没做的 lab.html 子tab 写成
   了已完成状态，给未来的自己埋了错误信息。
