# B9 项目复盘 —— 经验、教训与可复用的降本增效方法论

> 写于 2026-07-26。目的：这份文档不只是 B9 的记录，是后续**所有项目**开工前
> 应该翻一遍的 playbook。每条方法论都标注了它在本项目里的真实出处（可回查
> 验证），没有一条是理论推演。

---

## 一、背景与结果

**项目**：Binance B9 内容推荐模块的新闻数据底座——从全网（RSS/X/搜索引擎/行情
API/日历）召回加密新闻，LLM 结构化打标签，双层去重，真实性校验，五因子重要性
打分，产出生产 API + 6-tab 工作台网站，支撑 Macro Insight 与 Sector Insight
两个推荐场景。

**时间线**：约 36 小时（一个通宵 + 一个白天），Claude Code 多 agent 协作完成。

**关键结果数字**（全部真实测量，非估算）：
- 事件库 1000+ 条结构化事件，321 个活跃信源
- 去重：从实测 48.7% 冗余（944 行中 416 行重复）修到跨轮零重复
- 单事件 LLM 成本：$0.0146 → $0.0093（-36.5%，砍 description_long + 模型分级）
- 单轮 pipeline：约 19 分钟，其中 LLM 结构化占 78%（899s），其余全部环节合计 <6s
- 覆盖率：严谨复测 29.9%（事件级），但 3+ 媒体报道的大事 100% 无漏；缺口的
  77.4% 归因为"信源未接入"而非过滤误杀
- 架构升级后：本地 Claude 预处理桥可再削去大部分 OpenAI 花费（staged 条目约占
  74% 体量，预估月省 $250-350，待真实运行数据确认）

## 二、有效方法论（What worked，按含金量排序）

### 1. 阈值必须实测标定，文档里的数字只是初始猜测
skill 文档写语义去重阈值 0.65，实测（855 条真实事件、28 万配对、13 组人工
标注）应取 0.82——照抄文档会把不同事件误合并。**任何影响数据正确性的阈值，
上线前用真实数据分档标定一次，并把标定方法写回文档。**
（出处：`crawler/dedup.py` 头注、memory `b9-dedup-gap`）

### 2. 先量化成本结构，再动手优化——砍对地方一刀顶十刀
成本焦虑出现时，第一步不是砍功能，是把账拆开：实测 82.4% 的钱在 output token，
而 output token 的大头是 description_long 双语长文。于是"只留中文 + 按重要性
分档限长"一项改动就省 36.5%；而当时正在纠结的"内容标签 +30%"其实只值 $103/月。
**没有成本分解就优化 = 蒙眼砍价值。**
（出处：run 11/12 对比，`docs/OPEN_QUESTIONS.md` #1）

### 3. 两层漏斗：便宜的粗筛挡在贵的精判前面
本项目四处复用同一模式，全部有效：
- TF-IDF 字面粗去重 → embedding 语义精去重（省 LLM 调用）
- embedding+关键词预筛（0.6 门槛）→ LLM 板块相关性精判（LLM 调用量降 41 倍）
- 互动量/粉丝数结构过滤 → X 内容进入 LLM
- gpt-5.4-nano 处理模板化条目 → gpt-5.4 只碰需要判断力的内容
**注意分级依据是"任务歧义度"，不是"来源权威度"——低权威内容恰恰最需要判断力
甄别谣言，降级它们反而放大误判。**

### 4. 白嫖算力接入的正确姿势：pull + 缓存 + 完整兜底
本地 Claude Max 闲置额度替代 OpenAI 计费，架构是"Mac 闲时拉任务→本地算→回传
缓存；VM 用时查缓存，miss 就走原路径"。三条硬规则让它零风险：
① 不可靠资源只能做加速层，绝不做依赖项（Mac 关机 = 全 miss = 行为与从前一致）
② 口径一致性用 hash 闸门机械保证（prompt 变更旧缓存自动失效），不靠人记得
③ 两条路径共用同一套后处理代码，只跳过 API 调用那一步，杜绝形状漂移
（出处：`api/enrich_bridge.py`、`scripts/local_enrich_worker.py`）

### 5. 频率与成本的解耦：抓取和处理不必同频
"降成本→降频率→高频源滚屏丢数据"的死结，解法不是折中频率，是把便宜的环节
（抓取存档，2h/次）和贵的环节（LLM 处理，12h/次）拆开。Triple-A 被盗事件漏召
的根因排查直接催生了这个架构。**遇到"A 和 B 绑在一个开关上很难受"，先问能不能
拆成两个开关。**（出处：`crawler/staging.py`）

### 6. 结构性防刷优于枚举式防刷
X 召回被内容农场污染时，不去枚举垃圾话术正则（打不完），而是加"单账号单轮
≤3条"的结构约束——正经新闻源不会一轮对同一账号产出两位数条目。**对抗性场景
优先找行为不变量，不追内容特征。**（出处：`crawler/x_search.py` MAX_ITEMS_PER_AUTHOR）

### 7. 数据反直觉时，先怀疑测量本身
覆盖率初测 91.9%，复测 29.9%——初测的关键词重合把"同主题不同事件"算成命中，
且当时库里的大量重复行让匹配虚高。**好消息坏消息都要过"测量方法是否偏袒结论"
这一关，尤其是好消息。**（出处：`docs/coverage-test-report-20260726.md`）

### 8. 多 agent 并行的工程纪律
- 按文件边界切分任务，声明"你只许碰 X/Y/Z"
- 热点文件（server.py）不让任何 agent 碰，各自交付"需要加的两行"，中央统一应用
- SSH 连接必须复用（ControlMaster），否则并行 agent 打爆 sshd MaxStartups，
  表现酷似服务器宕机（真实误诊过 25 分钟）
- agent 交付报告必须含真实运行证据，"应该没问题"四个字等于没测

### 9. 异步决策留痕：OPEN_QUESTIONS 模式
执行中遇到的权衡点不打断工作，写进 `OPEN_QUESTIONS.md`（现状 + 我的倾向判断 +
留给用户拍板），用户醒来批量 review。整晚推进没有一次因等确认而阻塞，事后
用户逐条批注即可。**适合任何"执行者和决策者不同时在线"的协作。**

### 10. 模型分级不只用在产品里，更要用在「谁写代码、谁审代码」上

本项目最贵的一次模型调用不是产品功能，是**用最强模型审查便宜模型写出来的代码**。
真实结果：15 个并行 agent、160 万 token、20 分钟墙钟，查出 48 条问题，其中
**4 个 HIGH 全部是生产级数据正确性缺陷**，而这 4 个里有 3 个出自 Sonnet agent
（或我自己）当天早些时候写的代码——它们通过了当时的功能验证，因为它们不是
"功能不对"，是"边界条件下会丢数据"：

- staging 在 LLM 处理前就标记已消费 → pipeline 中途崩溃即整批永久丢失
- LLM 全面故障时 enriched 为空，pipeline 以 success 收尾 → 批次静默蒸发
- 行情信号 URL 静态 + 存档表永久去重 → 同一信号第二次触发起永远进不来
- 策略实验室对已折扣的 authority 二次折扣 → rumor 类事件全部算错

**方法论**：便宜模型执行、贵模型审查，是比"全程用贵模型"性价比高得多的组合。
执行阶段的错误大多能被功能测试发现；**只有跨模块的复合因果错误需要更强的推理
才能看见**，而这类错误恰恰最贵——它们静默、且直接损坏数据。

### 11. 对抗验证：让验证者去「推翻」，而不是「确认」

审查结论不能直接采信。本轮 10 条高优先级发现全部进第二轮验证，prompt 明确写
"你的任务是设法**推翻**它"，结果：

- **1 条被成功推翻**（证据与当前代码不符）——省掉一次基于错误前提的修改
- 验证者还**补出了审查者漏掉的加重因素**：行情信号那条，审查者列了 4 个静态
  锚点调用点，验证者查出实际有 7 个，其中冷却期最短、本该最高频重播的
  liquidation 信号被吞得最狠

**关键在措辞**：写"验证一下这个发现对不对"会得到附和；写"设法推翻它，只有
证据链完整才判成立"才会得到真正的复核。

### 12. 多 agent 编排的四条工程约束（实测有效）

1. **按文件边界切分**，每个 agent 明确"你只许读 X/Y/Z"——避免重复劳动与结论打架
2. **热点文件不给任何 agent**（本项目是 `api/server.py`），让它们各自交付"需要
   加的两行"，由主线程统一应用
3. **强制结构化输出 schema**，省掉解析层，也逼 agent 把证据落到 file+line 粒度
4. **写明排除项**——本轮 prompt 里写了"禁止提安全加固建议（用户已明确不做）"，
   实测 48 条发现里**零条安全噪音**。不写的话这类建议会淹没真问题

另外：主线程在 review 并行期间同步做架构实现，20 分钟墙钟里没有空等。

### 13. 「有兜底」必须用故障注入证明，不能靠代码里有 try/except 就宣称

本地 Claude 预处理桥上线时，声称"Mac 关机不影响 VM"。这句话的证明方式不是指着
try/except 说"你看有兜底"，而是**真的把三种故障注进去跑**：

- 缓存为空（Mac 从未开机）→ 走 OpenAI，正常产出
- 传入已关闭的数据库连接（缓存层故障）→ 不抛异常，退化为全部未命中
- 三种脏数据形态（缺字段/None/非 dict）→ 全部被拒，该条落回 OpenAI

三条都用真实条目 + 真实 API 调用跑过才算数。**"应该没问题"和"注入故障后实测
没问题"之间，隔着一整个生产事故。**

## 三、踩坑全录（每条都真实付过学费）

| # | 坑 | 教训 |
|---|---|---|
| 1 | sshd MaxStartups 被并行 agent 打满，Connection refused 误诊为宕机 | 并行自动化必须复用连接；"服务器挂了"先查自己的连接风暴 |
| 2 | 加 embedding BLOB 列后 API 500 半小时 | 改 schema 必须同步重启读它的服务 |
| 3 | `stage_timings` 列：写入代码上了，建列迁移忘了，try/except 静默吞错 | **迁移与写入代码必须成对提交**；静默兜底要配日志告警，否则错误消失得无影无踪 |
| 4 | UsageTracker 用 Lock 自死锁，所有历史成本数据全是 0 还没人发现 | 可重入调用链用 RLock；"监控数据全是 0"本身就是监控要报的警 |
| 5 | Google News RSS 默认相关性排序，返回 50-130 天前的旧闻 | 第三方接口的默认排序/窗口行为必须实测，不能想当然 |
| 6 | 币安 API 对美国 IP 451 | 云上跑的东西先确认数据源的地域策略 |
| 7 | `python3 api/server.py` 直跑时 sys.path 不含项目根，跨包 import 全炸 | Flask 多 blueprint 项目在入口显式 insert 项目根（通用坑） |
| 8 | "侧边导航栏"被理解成顶部 tab 直接标完成；"策略实验室改子tab"一句话需求整条蒸发 | **短需求与长需求一视同仁落 TODO**；UI 需求交付必须附形态截图；模糊需求要么问要么写明自己的解释 |
| 9 | 设计 brief 把"没做的子tab"写成了已完成 | 现状类文档写之前先看代码，禁止照"应该的样子"写 |
| 10 | header 毛玻璃 + 内部无限动画 = 每帧重算高斯模糊，全页闪烁 | backdrop-filter 容器内禁放无限动画；整屏 fixed 元素做合成层提升 |
| 11 | 给后端补鉴权，忘了前端三个 fetch 还没带 token，当场 Unauthorized 回归 | 改鉴权是双端改动，交付前把调用方全 grep 一遍 |
| 12 | launchd 指向 Desktop 下的脚本，TCC 拒绝执行 | macOS 定时任务的脚本放非保护目录（~/.b9 之类） |
| 13 | Mac 系统 python3 不认 `dict \| None` 运行时注解 | 面向"别人机器"的脚本 `from __future__ import annotations` 保平安 |
| 14 | X 的 $30 账单与"配额内固定费用"的代码注释矛盾，尚未对账 | 成本假设要和真实账单核对，账单才是事实 |
| 15 | `pgrep -f run_pipeline` 的监控脚本自己命令行里就含这个字符串，永远匹配到自己 | **同一天踩了两次**：第一次误判"pipeline 还在跑"，第二次遗留的监控进程让诊断出现假阳性。用 `[r]un_pipeline` 或匹配 PID，且用完就清理后台监控 |
| 16 | 独立 `claude` CLI headless 调用报 Not logged in（钥匙串凭据 ACL 属于桌面应用） | 要给自动化用的 CLI，先在 Terminal 手工 `/login` 一次并选"始终允许"钥匙串——只点"允许"的话下次后台跑还是失败 |
| 17 | X API 实为**按拉回推文条数计费**（$0.0021/条），代码注释却写"配额内固定费用"，广撒网两天烧穿 credit 402 停摆 | **按量计费的第三方，接入前必须实证计费维度**（条/请求/层级），限流要设计在计费维度上；94% 的钱曾花在当场丢弃的内容上 |
| 18 | GCP 防火墙只放行 8080 且 VM 服务账号无权改规则，Let's Encrypt 无法验证 80/443 | 云上要 HTTPS 先查防火墙权限；封死时 Cloudflare quick tunnel（纯出站）是零权限解法，代价是子域名随机且重启会变 |
| 19 | 时区切换（UTC→UTC+8）牵动 cron 表达/MySQL NOW()/日志/前端标签/文档五处 | 切展示与运行层，**存储层历史数据不回填**（回填会污染时间窗比较基准），换算 cron 时保持实际触发时刻不变 |

## 四、降本增效 checklist（新项目开工时过一遍）

1. **算钱先于省钱**：接入用量追踪（应用层记 usage，别指望平台 API），跑一轮真实
   负载，拿到成本分解表再谈优化。
2. **贵操作前面必须有便宜的漏斗**，分级依据是任务歧义度。
3. **output token 通常是大头**：长文本字段按重要性分档限长、砍掉无消费方的字段
   （本项目 description_long_en 全程零下游消费，白产了几天）。
4. **闲置资源（本地算力/订阅额度）用 pull+缓存+兜底接入**，永不成为依赖项。
5. **抓取/计算/交付各自独立定频**，别让最贵环节的频率绑架全链路。
6. **阈值实测标定**，标定脚本和结论写回文档。
7. **需求进 TODO 才算存在**，不分长短；原始 prompt 原文留痕。
8. **交付即验证**：真实数据跑通 + 关键数字 + 截图（UI），拒绝"应该没问题"。
9. **schema 改动三件套**：迁移文件 + 写入代码 + 重启依赖服务，一个 commit 里。
10. **静默兜底必须配告警日志**，否则故障以"数据是 0"的形态永远潜伏。
11. **多 agent 并行按文件边界切分**，热点文件中央收口，连接类资源复用。
12. **决策点异步留痕**（OPEN_QUESTIONS 模式），执行不阻塞，决策不遗漏。
13. **贵模型审便宜模型的产出**：执行用便宜的，审查用最强的。跨模块复合错误只有
    强推理才看得见，而这类错误最贵（静默、损数据）。
14. **兜底声明必须故障注入验证**，"代码里有 try/except"不构成证据。
15. **审查结论必须对抗验证**（prompt 写"设法推翻"），并给 agent 写明排除项。
16. **按量计费的第三方先实证计费维度再设计限流**——账单截图才是事实，文档和
    直觉都可能错；限流闸门必须落在计费维度上（B9 的 X 事故：闸门设在请求数上，
    计费却按条数）。

## 五、架构决策记录（ADR-lite，为什么是现在这个样子）

- **双层去重（指纹 + embedding）**：LLM 措辞不稳定 → 指纹管"明确同一事件"，
  embedding 管"换了说法的同一事件"，跨轮归并靠指纹先行、语义兜底。
- **staging 解耦**：见方法论 #5。
- **enrich bridge**：见方法论 #4。embedding 刻意不走本地——它便宜（$0.002/轮）
  且 0.82 阈值绑定该向量空间，换模型 = 全部重标定，得不偿失。
- **blueprint 各自独立实现鉴权/连库**：牺牲 DRY 换取多 agent 并行开发时零耦合
  （代价是 6 份重复代码，已知技术债，等停止高频迭代后统一收口）。
- **验证框架零 LLM**：真实性校验全部用客观信号（独立信源数/权威分层/时间
  一致性/矛盾检测），因为它跑在每一轮、每一条上，LLM 化会让成本随库存线性涨。
