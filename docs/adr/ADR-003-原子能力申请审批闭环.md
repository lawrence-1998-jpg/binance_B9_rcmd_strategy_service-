# ADR-003：策略实验室「新增原子能力」——申请 → 审批 → Claude Code 开发落地

**Status:** Accepted（2026-08-06 上线）
**Deciders:** Lawrence（产品与审批口径）· Claude Code（架构与实现）

## Context

策略迭代的需求（新标签、保量策略、RAG 语料）此前只能通过口头/聊天传给开发，
没有留痕、没有审批、没有状态。要一个入口让同事自助提交，Lawrence 审批，
批准后落地，全程可见。

硬约束（用户原话）："绝对不要把线上搞崩了"。生产每 30 分钟一轮，老板随时会看。

## Decision

**申请单模式，本期不做自动生效。** 三类申请统一走一张表的状态机
（pending → approved / rejected → applied），批准的产物是一份**变更单**
（既定落地路径 + 预计改动文件 + 成本估算 + 测试回滚方式），由 Claude Code
按正常开发流程落地（需求理解 → 代码开发 → 测试通过 → 上线）。
拒绝**必填原因**，状态与原因对所有人可见。

### 关键取舍

| 决策点 | 选择 | 放弃的方案与原因 |
|---|---|---|
| 落地方式 | 变更单 + 人工开发 | 批准即自动改配置——排序是主路径，自动生效面大且难审计；用户明确本期不要 |
| 审批鉴权 | 独立 approver secret（`API_TOKEN_APPROVER`），手输、fail-closed | 复用页面 token——它由服务端注入进 HTML，**打开网页就拿得到**，等于人人能批。顺手把存量的 `strategy-config/deploy`、`/rollback` 一并收进 approver 档（此前正是这个漏洞的活例子） |
| 新标签的成本口径 | 变更单固定写入「独立标签计算通道」路径 | 直接改主 enrich prompt——`PROMPT_VERSION_HASH` 一变缓存全失效，每加一个标签全库重算 ~$90 |
| 通知 | 站内待办角标 + monitor 计数 + Claude Code 会话主动查 | 邮件——Gmail 连接器未授权，不能让上线阻塞在外部授权上；列为二期 |

## 实现

- **数据**：`config/migrations/022_capability_requests.sql`，单表 + JSON payload（纯新增）
- **API**：`api/capability_tools.py`（提交/列表/详情走普通档；approve/reject/mark-applied
  走 `api/auth.py::require_approver`）。approver 档六份鉴权复制之外单列一个共享模块，
  刻意不做第七份复制
- **前端**：`web/index.html` 实验室第 3 子 tab。表单按类切换；审批弹窗 `type=password`
  手输 secret、请求完即清；全部 document 级事件委托（#98 教训）
- **变更单**：批准时按 kind 生成。label 类含按当前窗口条数的成本估算；
  rag 类如实标注检索链路零基础

## Consequences

**变容易的**：需求有了单一入口与全程留痕；"谁批的、为什么拒"可追溯；
Claude Code 拿到的是结构化需求 + 既定架构路径，不用每次重新对齐。

**变难的 / 债**：
- 各 blueprint 的普通档鉴权仍是六份复制（本期只避免了第七份，未合并）
- 审批通知依赖人进页面或 Claude Code 会话，没有推送；邮件通知二期
- rag 描述模式的语料自动生成在批准后由 Claude Code 执行（VM 连不通公司网关），
  桥接自动化二期

**要重访的**：出现第一个批准的 label 单时，按变更单落地独立标签计算通道
（`label_values` 表 + bridge 派活扩展）——那是本 ADR 预写的架构，落地时验证它。
