# ADR-001：排序因子扩展、处理优先级队列与新闻类型体系

**状态**：Accepted（Lawrence 2026-07-29 逐项确认）
**日期**：2026-07-29
**决策人**：Lawrence（产品）/ Claude（工程）
**关联**：[PRD-03](../prd/PRD-03-热度氛围与排序因子扩展.md)

---

## Context

首屏缺少 CNBC 那种市场大事的热度感。实测数据把根因定位为**三段式问题**，
而非召回量问题（301 条权威源已抓回仅 8 条被处理；us_stock 已有 207 条但 84%
是 C/D 档个股噪音；日韩宏观 S/A 占比 20-30% 证明打分逻辑本身没问题）。

需要在**不破坏既有口径**的前提下引入 4 个新排序信号、一套处理优先级、
以及一个对外的新闻类型体系。约束：

- `importance_score` 是策略实验室/去重/历史分析共同依赖的口径，**不可被
  今天的情绪污染**（否则跨天不可比，WORKLOG #61 已立此规矩）
- 系统里已有三套分类（`news_type` / `market_scope` / `sectors`），
  **不能再加第四套**
- 新因子极易与既有 M/H/A 重复计分，必须显式划清边界

---

## Decision

### D1：评分模型改为「基础因子加权 × 加分项倍率」两段式

```
BaseScore  = Σ wᵢ·Fᵢ        (7 个基础因子，权重归一化到 1.0)
FinalScore = BaseScore × (1 + bonus_sentiment + bonus_reversal)   (加分项合计封顶 +50%)
```

**为什么不把加分项做成第 8、第 9 个权重因子**：加分项的语义是「在既有排序上
按当下市场状态做有界扰动」，它依赖 `mood_score` 这个**每天都在变**的全局量。
做成加权项会让不同日期算出的分不可比；做成外层倍率则 BaseScore 保持跨天可比，
倍率部分随时可关（k=0 即退化回原排序）。这也是 Lawrence 要求「正常因子和加分项
稍微分开」在数学上的落点。

### D2：`importance_score` 落库口径 = BaseScore，加分项只在查询时应用

沿用 WORKLOG #61 已确立的分离原则。库里存的是稳定分，展示排序时再乘倍率。

### D3：新闻类型体系 = 扩充 `market_scope`，不新建分类

新增枚举值 `social_signal`，对外正名为「新闻类型」。

**social_signal 的边界（Lawrence 确认）**：地缘冲突、自然灾害、社会事件，
**且必须有对市场的传导路径**——纯社会新闻（明星八卦、体育、无市场影响的
本地事件）不收，由 LOW-VALUE FILTER 判 D 档。

**为什么复用而非新建**：Lawrence 要的「独立」本意是**独立于加密板块**，
`market_scope` 已满足这一点，6 个枚举里 5 个与他列举的完全一致。真正缺的是
**展示**（藏在下拉里、非加密事件在板块列显示"未标注"）。新建第四套只会制造
「该用哪个」的长期困惑。

### D4：处理优先级用 staging 表的 `priority` 列，而非过滤

Lawrence 明确要保留 dxFeed 大底池（个股大盘都拉）。**过滤不可逆，优先级可逆**
——个股新闻今天没价值不代表以后做个股页时没价值。

### D5：冲击力因子砍掉与 M/广度重复的成分

`Impact = 0.65·数值幅度 + 0.35·权威共振`。Lawrence 原本列的第三项
「对社会经济重大影响」已被 M（影响面）+ 新增广度因子覆盖两遍，若再单列即
三重计分。

## Options Considered（仅列真正有分歧的两处）

### 新闻类型体系

| | 方案A：扩充 market_scope | 方案B：新建 category |
|---|---|---|
| 复杂度 | 低（加枚举 + 展示层） | 中（新列 + 迁移 + 双写 + 下游改造） |
| 长期维护 | 三套分类 | **四套分类，含两套高度重叠** |
| 数据连续性 | 存量 2610 条直接可用 | 存量需回填或留空 |

→ **采纳 A**（Lawrence 确认）

### 加分项作用位置

| | 查询时倍率（采纳） | 写回 importance_score |
|---|---|---|
| 跨天可比性 | ✅ 保持 | ❌ 破坏 |
| 关闭成本 | 改一个参数 | 需重算全库 |
| 实验室调参 | 实时生效 | 需重跑 pipeline |

## Consequences

**变容易**
- 新增排序信号只需在 `scoring.py` 加一个 `compute_*` 并在实验室注册
- 加分项可随时关掉验证其真实贡献（k=0 即 A/B 对照组）
- 非加密内容终于有了自己的展示标签，不再显示"未标注"

**变难 / 需注意**
- LLM schema 增加 `breadth_level` 必填字段 → **`PROMPT_VERSION_HASH` 变更 →
  存量缓存字段校验失败需重算**（已知代价，见 WORKLOG #62 的教训）
- 基础因子从 5 个变 7 个，历史 `importance_score` 与新分**不可直接比较**，
  做前后对比必须用同一版本重算
- 优先级队列引入**低优先内容饥饿**的可能，需监控最老未消费条目年龄

**需要复核的时点**
- 加分项封顶 +50% 是否过强 —— 上线后用实验室两版对比
- 权威共振与 H 因子的信源数成分是否仍有残余重复 —— 观察一周
