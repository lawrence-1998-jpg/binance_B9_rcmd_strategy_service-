## 零、一句话说清这个项目在干什么

**给 Binance App 的 B9 内容推荐模块造一套新闻数据底座**：全网抓取加密货币 / 美股 /
高相关行业（科技）的新闻 → 用 AI 结构化成标准事件（双语标题、摘要、板块标签、
可信度）→ 去重与真实性校验 → 落 MySQL → 打包成 API 供下游消费。

产品端要解决的两个线上病根（都有截图实证，见 `materials/screenshots/`）：
- **按时间强排**：不重要的人事新闻排第一，BitMEX 关停这种大事排第五
- **没有去重**：K25.ai 融资一条新闻并列出现 3 次

## 二、执行中的关键成果

### 成果 1：去重重构 —— 修掉 48.7% 冗余

事件库 855 行里 **416 行是同事件重复**，单个事件最多占 8 行。三个叠加根因：

| 根因 | 修复 |
|---|---|
| 事件 ID 用 LLM 改写后的标题做 hash，每轮措辞变了 ID 就变，`ON DUPLICATE KEY` 形同虚设 | 改由 LLM 输出的规范化三元组（主体/动作/日期）派生指纹 |
| 聚合层用 **TF-IDF 词频**冒充文档写的 embedding，对同义改写完全无效 | 换成 `text-embedding-3-small` 256 维真向量 |
| 只在单轮内去重，cron 每轮抓取窗口重叠但跨轮完全不设防（量最大的漏口） | 新增写库前的跨轮归并 |

**实测效果**：同等输入下事件数 484 → 349（多折叠 27.9%），表行数只净增 82
（349 个事件中 267 个并入既有行，旧代码这 267 条会全部变成重复行）。

### 成果 2：语义阈值实测标定 —— 文档写的 0.65 是错的

在 855 条真实事件、28 万配对上分档抽样，发现 cosine 0.65 会把"油价破 100 美元"
和"特斯拉周跌 18%"判成同一事件。人工标注 13 组配对："应合并"最低 0.859、
"应分开"最高 0.761，中间有 0.098 的干净空隙。**改为 0.82**。

经验教训：以后调任何语义阈值都要在真实数据上分档标定，不要照抄文档数字。

### 成果 3：欠召根因定位 —— 不是信源不够，是信号类型缺失

对照 6 个未接入的主流平台，新闻覆盖率 **91.9%**（漏的几乎全是生活理财文）。
但库里 **行情异动类只占 3.9%、宏观美股类只占 4.7%**。

原因：**没有任何媒体会把"BTC 24h 跌 5%""某币爆仓 2 亿"写成新闻**。这类信号
必须主动从行情 API 生成事件，靠加新闻源补不上。这直接决定了行情信号模块的
优先级高于单纯加信源。
