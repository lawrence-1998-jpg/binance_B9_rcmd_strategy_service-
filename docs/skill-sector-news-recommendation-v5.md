# Skill：板块相关新闻推荐 · 完整排序方案（v5）

> 模块定位：给定板块（如 MEME 币）+ 一批候选内容，AI 对每条内容**打标签 → 打分 → 超重去重 → 适度混排**，最终召回与该板块最相关的 3 条内容。
> 版本：v5.1 · 五因子 · 相关性硬门+外层乘子 · 连续打分 · 强去重 · 线上 badcase 驱动的标签细化 · 宁缺毋滥 · M 分先查市值
> 输出体验："看板块 → 抓最相关且不重复的信号"

## ★ 首要原则：宁缺毋滥，不硬出 3 条（v5 新增，优先级高于一切排序目标）

> **如果没有相关内容，就不要出。不需要硬出三条。不出 / 出 1~2 条都是合法输出。**

1. "召回 Top 3"是**上限**而非任务指标：通过相关性硬门（Rel ≥ 0.5）、体裁门、去重后存活几条就出几条，最多 3 条。
2. 禁止为了凑满 3 条而：①降低硬门阈值；②用"对 X 板块来说"改写把不相关内容硬揰进来（BC-1.4）；③把同一事件的改写变体当两条出（DC-2）；④用 ROUNDUP/PROMO 兜底。
3. 出 0 条时输出 `recommended: []` 并给出 `empty_reason`（候选池中无 Rel≥0.5 内容 / 全部被去重折叠 / 全部体裁不合格），前端降级为不展示该板块新闻模块或展示占位文案。
4. 产品依据：线上评测表明，硬凑 3 条的代价是 70% badcase 率；对推荐模块而言，错推的信任损失远大于少推的体验损失。

## 〇、打分公式（本 skill 的核心）

**LaTeX 版**（配套 PNG：fusion-recommended.png）：
- 硬门：若 Rel < 0.5 → Score = 0
- 打分：Score = Rel^1.5 × ( 0.25·T + 0.25·H + 0.20·A + 0.30·M )

**字符版（无公式环境时用）：**
```
前置硬门：若 相关性 Rel < 0.5  →  Score = 0（直接淘汰）
打分公式：Score = (Rel ^ 1.5) × (0.25*时效T + 0.25*热度H + 0.20*权威A + 0.30*影响面M)
后置去重：MMR 强去重，同一事件只留一条，再取 Top 3
```

权重记忆：影响面 0.30 > 时效 0.25 = 热度 0.25 > 权威 0.20，内层合计 = 1.0。相关性不在内层，作为外层乘子 + 硬门双重把关。

## 一、因子总览（深化版）

| 因子 | 角色 | 打分方式 | 数据来源 | 核心作用 | 常见误判 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **相关性 Rel** | 🔑硬门+外层乘子 | 连续 0~1，含主角度 Focus | 实体链接 + 语义相似 + 币安白名单 | 决定内容"配不配"进这个板块 | 顺带提及误判高分、同名币误绑 |
| **时效 T** | 内层 0.25 | 连续 0~1，指数衰减 e^(-λΔt) | 真实发布时间戳 | 新鲜度，越新越有信号价值 | 旧闻被转发误判为新事件 |
| **热度 H** | 内层 0.25 | 连续 0~1，log 压缩 | 社交互动 + 全网报道量（独立信源） | 传播广度，代表市场关注度 | 水军/机器人刷量伪热度 |
| **权威 A** | 内层 0.20 | 连续 0~1，信源分级×验证 | 媒体分层库 + 官方域名校验 | 可信度，防谣言噪音 | 被"权威词汇"诱导、匿名源伪装 |
| **影响面 M** | 内层 0.30 | 连续 0~1，价格冲击×范围×情绪强度 | 历史/实时波动 + 事件类型 | 值不值得看，对钱包的实际影响 | 泛科技事件误关联为利好 |

### 因子设计的底层逻辑（补充深度说明）

**为什么相关性用"硬门 + 外层乘子"双重把关？**
- 参考搜索到的工业界共识：排序系统应"先硬过滤，再软排序"（hard constraint + soft scoring 两阶段）。板块推荐场景，相关性是"准入资格"而非"加分项"。
- 硬门（Rel<0.5 淘汰）解决"要不要进"；外层乘子（Rel^1.5）解决"进了排多前"。
- 指数 1.5 是"锐化"：让 0.6 相关的内容（0.6^1.5≈0.46）明显弱于 0.9 相关（0.9^1.5≈0.85），拉开梯度。

**为什么权威只给 0.20（低于其它）？**
- 参考 NewsGuard（9 准则 100 分）、MBFC 方法论：权威更适合做"可信度过滤/降权"，而非主排序动力。
- 在加密场景，很多高价值信号首发于链上监测账号/KOL（权威中等），若权威权重过高会压制这些及时信号。所以权威权重适中，主要用于"砍谣言"，而非"抬官媒"。

**为什么影响面最高（0.30）？**
- 用户看板块新闻的核心诉求是"这事对我持仓/该板块价格有没有影响"。影响面直接对应决策价值，是最该主导排序的因子。

## 二、因子详解（连续打分 + 深度定义 + 多正反例）

> 每个因子：内涵定义 → 连续打分曲线（非纯离散）→ 多个正例/反例 → 归因诊断 → 规避策略 → 输出 JSON。

---

### 🔑 因子 1：相关性 Relevance（重中之重）

**内涵定义**：
内容与目标板块 t 的**直接强相关程度**。相关性不是"有没有提到"，而是"这条内容是不是在讲这个板块"。核心判据是**主角度（Focus）**——板块/其核心资产是否是新闻的**主语、核心议题、标题对象**。只有"板块是主角"才配高分；顺带提及、蹭热点、背景补充一律压制。

**连续打分曲线（0~1 连续，非离散档位）：**
相关性由三个子信号连续合成：
```
Rel = clip( 0.5*EntityMatch + 0.3*Semantic + 0.2*Focus_bonus , 0, 1 )
```
- **EntityMatch（实体命中强度，连续）**：目标板块核心实体在内容中的命中程度。标题命中=1.0，正文首段命中=0.7，正文中段=0.4，仅文末/从句=0.15。
- **Semantic（语义相似度，连续）**：内容整体语义向量与板块主题向量的余弦相似度（0~1），即使没点名代币，主题高度相关也算（如"政治 meme 币监管"话题 vs MEME 板块）。
- **Focus_bonus（主角度加成，连续）**：
  ```
  Focus = 板块核心实体提及次数 / 全文实体总提及次数
  Focus_bonus = Focus × (1 + 0.5*标题命中)
  ```
- 三者加权后 clip 到 [0,1]，得到连续相关性分。

**连续分到语义档位的映射（供理解，实际用连续值）：**
- 0.85~1.0：板块是唯一/核心主角
- 0.6~0.85：板块强相关但涉及多板块，或主角度中等
- 0.3~0.6：间接相关、部分主角度（**多数会被硬门 0.5 拦截**）
- 0~0.3：顺带提及、背景补充、同名误绑（淘汰）

**输出 JSON：**
```json
{
  "relevance_score": 0.92,
  "target_sector": "MEME",
  "matched_entities": ["TRUMP", "WLFI"],
  "entity_match": 1.0,
  "semantic_sim": 0.88,
  "focus_ratio": 0.85,
  "is_primary_subject": true,
  "reason": "标题即 TRUMP 币立法，板块为唯一主角，语义高度相关。"
}
```

#### 正例（Good Cases）

**GC-1.1（板块即标题主角）** 板块=MEME
输入：`美国国会提案限制现任总统发行个人 meme 币，TRUMP 币应声下跌 18%`
输出：`relevance_score: 0.95`（entity_match=1.0 标题命中，focus=0.9，语义=0.9）
理由：板块核心资产是新闻主语和标题对象。

**GC-1.2（板块整体趋势）** 板块=MEME
输入：`分析：本轮政治 meme 币集体退潮，TRUMP、WLFI、MAGA 普跌，市场情绪转冷`
输出：`relevance_score: 0.82`（多个板块代币，主角度高但非单一）
理由：整条在讲 meme 板块趋势，强相关但涉及多标的。

**GC-1.3（语义相关无直接点名）** 板块=MEME
输入：`SEC 拟出台新规，将名人发行的社区代币纳入证券监管范畴`
输出：`relevance_score: 0.68`（未点名具体 meme 币，但语义高度相关）
理由：主题是 meme 币监管，语义命中，虽无 Ticker 但强相关。

**GC-1.4（机制型板块的正确主角）** 板块=Launchpool
输入：`币安 Launchpool 上线第 95 期项目 XYZ，支持 BNB/FDUSD 挖矿`
输出：`relevance_score: 0.95`
理由：机制型板块（Launchpool/Megadrop/Launchpad/种子/最新上币）的"主角"= 该机制本身的新项目/规则/收益变化，或成分项目自身的重大事件；而非任意"收益类叙事"新闻（参见 BC-1.7）。

#### 反例（Bad Cases）

**BC-1.1（顺带提及误判高分）** 板块=MEME
输入：`特朗普就伊朗核问题发表强硬讲话，市场避险升温；此前其发行的 TRUMP 币曾引发争议`
错误输出：`relevance_score: 0.9`（命中 "TRUMP"）
正确输出：`relevance_score: 0.25`（focus_ratio≈0.15，实体仅在文末从句）
归因：LLM 命中实体词即给高分，忽略新闻主角是伊朗核问题，TRUMP 币是背景补充。
规避：强制先判定"新闻主语/核心议题"；板块实体仅出现在背景/从句/文末，relevance 封顶 0.3；focus_ratio<0.3 直接压制。

**BC-1.2（同名 meme 币误绑）** 板块=MEME
输入：`苹果公司发布 M5 芯片，性能提升 30%`
错误输出：`relevance_score: 0.8, ticker: APPLE`（误绑链上同名 $APPLE meme 币）
正确输出：`relevance_score: 0.0`
归因：把 Web2 巨头与 DEX 同名 meme 代币混淆。
规避：结合币安现货/合约 API 白名单 + 全网市值 Top200 过滤；Apple/Tesla 等词除非正文含合约地址(CA)或 DEX 交易对，否则标 TRADFI/NONE，Rel=0。

**BC-1.3（跨板块误判）** 板块=MEME
输入：`以太坊 Pectra 升级主网上线，Gas 费预计下降 40%`
错误输出：`relevance_score: 0.6`（都是加密新闻）
正确输出：`relevance_score: 0.1`
归因：把"同属加密行业"误当"板块相关"。ETH 基础设施升级和 meme 板块无直接关系。
规避：相关性判定必须锚定**目标板块**，不是"是否加密新闻"。跨板块内容 Rel 压低。

**BC-1.4（视角改写硬揰相关 —— 线上高频 badcase，v5 新增）** 板块=游戏
输入：`散户红利消退，预测市场迎来 AI 军备竞赛`，总结被写成"市场关注点在往 AI 方向转，这会分走游戏赛道的注意力，**对游戏板块来说**不是直接利空…"
错误输出：`relevance_score: 0.7`（被自己生成的"对游戏板块来说"话术诱导）
正确输出：`relevance_score: 0.15`
归因：相关性必须对**原始内容**打分，而不是对"改写后的总结"打分。给任意新闻加一句"对 X 板块来说…"并不改变新闻主角。线上游戏板块 3 条全是 AI/meme 新闻被这样硬揰进来，相关性仅 1/10。
规避：**铁律——先对原文打 Rel，后写 summary**；若相关性需要依赖"对板块影响的推论"才能成立（原文中板块实体/成分币零命中、语义不命中），则 Rel 封顶 0.2；禁止在 summary 中用"对 X 板块来说"把不相关内容强行关联到板块。

**BC-1.5（汇总/盘点无主体，"无效废话"类，v5 新增）** 板块=bStocks
输入：`昨夜今晨重要资讯（7月22日-7月23日）`
错误输出：`relevance_score: 0.6`（汇总里提到过板块代币）
正确输出：`relevance_score: 0.1`，`content_genre: ROUNDUP`，硬性淘汰
归因：汇总/早报/盘点/周报类内容没有单一事件主体，Focus 分散在十几个实体上，对任何单一板块都是"无效废话"。线上 bstock 板块因此拿到 0/10。
规避：引入**内容体裁标签 content_genre**（见补充定义 A）；判定为 ROUNDUP（标题含"昨夜今晨/早报/晚报/一周回顾/重要资讯/大事盘点"或正文为多事件列表）→ Rel 强制 ≤0.2，相当于被硬门淘汰。

**BC-1.6（传统市场情绪二级外推，v5 新增）** 板块=bStocks
输入：`全球最大资管研判：芯片股抛售过头了`
错误输出：`relevance_score: 0.65`（"芯片股情绪修复 → 相关 bStocks 代币可能受关注"）
正确输出：`relevance_score: 0.35`（被硬门 0.5 拦截）
归因：新闻主角是传统美股大盘，到达板块需要"芯片股情绪修复 → 带动对应代币化股票"两级以上传导，属间接情绪关联。
规避：引入**传导链长度 transmission_hops** 子信号：板块/成分币是直接主体 = 0 跳，不限；新闻直接论述板块底层标的（如 bStocks 对应的**单一**正股本身出财报/并购等重大事件，且该正股对应代币在成分币内）= 1 跳，Rel 封顶 0.55；需要宏观/情绪传导才能关联 ≥ 2 跳，Rel 封顶 0.4。

**BC-1.7（机制型板块被"收益叙事"泛化，v5 新增）** 板块=Launchpool
输入：`Pendle 公布 H2 路线图：加码 RWA 与机构市场，Boros 将聚焦链上利率衍生品`
错误输出：`relevance_score: 0.7`（"收益类产品叙事对 Launchpool 相关收益叙事有支持"）
正确输出：`relevance_score: 0.45`（若 PENDLE 是 Launchpool 历史成分项目且事件重大，可到 0.55；但"叙事支持"推论本身不能抬分）
归因：Launchpool/Megadrop/Launchpad 等是**平台机制型板块**，相关性边界与赛道型板块不同，不能用"题材/叙事相近"泛化。
规避：按**板块类型化相关性边界**（见补充定义 B）判定：①机制新项目/规则/收益变化 = 高相关；②成分项目自身重大事件 = 中高相关；③仅"题材/叙事相近" = 低相关。

#### 补充定义 A：内容体裁标签 content_genre（v5 新增）

每条候选内容先打体裁标签，体裁直接限制 Rel 上限，从源头屏蔽"无效废话"：

| genre | 定义与判別特征 | Rel 上限 |
| :--- | :--- | :--- |
| EVENT（事件） | 单一主体 + 单一动作 + 可验证事实（上线/融资/监管/黑客/升级/合作） | 1.0 |
| DATA（数据） | 链上数据/资金流/产业报告，有具体数字和明确主体 | 1.0 |
| ANALYSIS（分析/观点） | 有明确论题、明确主体的深度分析 | 0.85 |
| ROUNDUP（汇总/盘点） | 早报/晚报/一周回顾/多事件列表，无单一主体 | **0.2（硬性淘汰）** |
| PROMO（宣发/软文） | 项目方自夸、无实质信息的合作通稿、喊单 | 0.3 |
| PRICE_NOISE（盘面碎话） | 纯报价、"突破整数关口"类无增量信息 | 0.4 |

#### 补充定义 B：板块类型化相关性边界（v5 新增）

币安 Sector Insight 的 20 个板块（bStocks、Megadrop、Launchpool、种子、基础架构、DeFi、MEME、BSC、一层/二层网络、Solana、游戏、RWA、AI、tCommodities、Launchpad、NFT、支付、粉丝代币、观察、最新上币）分三类，"板块是主角"的锚点不同：

| 板块类型 | 板块举例 | "板块是主角"的定义 | 典型陷阱（对应 badcase） |
| :--- | :--- | :--- | :--- |
| 赛道型 | MEME、AI、游戏、DeFi、NFT、RWA、支付、基础架构、粉丝代币 | 成分币或赛道主题是事件主体（项目升级/赛道监管/板块普涨普跌） | 把"同属加密"当相关（BC-1.3）；视角改写（BC-1.4） |
| 公链生态型 | Solana、BSC、一层/二层网络 | 链本身（升级/宕机/生态数据）或链上头部生态项目与该链强绑定的重大事件；仅"部署在该链"而事件与链无关的项目新闻降档（Rel≤0.4） | LayerZero×Keeta 发银行代币被推给 Solana（主角是 LayerZero） |
| 平台机制型 | Launchpool、Megadrop、Launchpad、种子、最新上币、观察、bStocks、tCommodities | 机制本身（新期项目/规则/收益/抵押资产扩容）或成分项目（含对应正股/商品）自身的重大事件 | "叙事相近"泛化（BC-1.7）；传统市场情绪二级外推（BC-1.6） |

#### 补充定义 C：ticker 输出校验（v5 新增，防 ticker 误绑）

线上 badcase：Coinbase×Mubadala 新闻尾部标 (KAITO)；游戏板块新闻标 (USDC, NVDA)。v5 规则：
1. `related_tickers` 只允许输出**在原文中作为事件主体或直接受体**的代币；"可能受影响"的联想代币不得进入 ticker 列表。
2. 进入板块推荐时，若 `related_tickers ∩ 板块成分币白名单 = 空` 且语义不命中板块主题 → Rel 强制 ≤0.3。
3. ticker 必须通过币安现货/合约白名单消歧；未收录资产标 `UNLISTED:` 前缀，禁止冗充同名主流资产（呼应 BC-1.2）。

### 因子 2：时效性 Timeliness

**内涵定义**：
内容的新鲜度与首发性。新闻的信号价值随时间**指数衰减**——加密市场尤其快，一条 15 分钟前的突发和 5 小时前的同一事件，交易价值天差地别。时效还隐含"首发性"：二次编译/转载的时效低于首发。

**连续打分曲线（指数衰减，非离散）：**
```
T = exp( -λ × Δt_hours )
```
- Δt = 当前时间 − 真实发布时间（小时）
- λ 按内容类型动态取值（分级衰减）：
  - 突发快讯/监管/黑客：λ=0.5（半衰期≈1.4h，衰减快）
  - 常规新闻：λ=0.23（半衰期≈3h）
  - 深度分析/研报：λ=0.06（半衰期≈11h，衰减慢，长效价值）
- 首发系数：二次转载/编译 T 再乘 0.7。

**连续值参考点（突发类 λ=0.5）：**
- 0 分钟：T=1.0；30 分钟：T≈0.78；1 小时：T≈0.61；2 小时：T≈0.37；4 小时：T≈0.14；>6 小时：T<0.05

**输出 JSON：**
```json
{"timeliness_score": 0.78, "published_ago_min": 30, "content_type": "BREAKING", "lambda": 0.5, "is_first_report": true}
```

#### 正例

**GC-2.1（突发首发）**：`[3 分钟前] SEC 突然对某头部 meme 币发起证券调查` → T=0.98，content_type=BREAKING。
**GC-2.2（深度研报慢衰减）**：`[4 小时前] Binance Research：政治 meme 币生命周期分析报告` → T=0.79（λ=0.06 慢衰减，深度内容长效）。合理，研报 4 小时仍有价值。

#### 反例

**BC-2.1（旧闻当新闻）**：`（6 小时前发布，现被多号转发）某 meme 币上周宣布 DEX 上线`
错误：T=0.8（被"上线"语义诱导）；正确：T=0.05（按真实时间戳）。
归因：忽略真实发布时间戳，被内容文本语义误导。
规避：时效**必须以真实发布时间戳为唯一依据**，禁止从正文语义推断新鲜度；>4h 突发类强制 T<0.15。

**BC-2.2（转载当首发）**：某小号转载 2 小时前律动的原文，标注为"刚刚"
错误：T=0.9；正确：T≈0.37×0.7=0.26（按原始发布时间 + 转载系数）。
归因：把转载时间当首发时间。
规避：溯源到事件首次出现时间（配合去重的 event_cluster 首发时间戳），转载乘 0.7。

### 因子 3：热度 Hotness

**内涵定义**：
内容在社交平台和全网的**真实传播广度**，代表市场关注度。核心是"多少**独立**信源/用户在讨论"，而非单一账号的转发量。必须**去水军**——机器人刷量、单一群组集中爆发不算真热度。

**连续打分曲线（log 压缩 + 归一化）：**
```
raw = α*分享 + β*全网独立报道数 + η*评论 + μ*点击
H = normalize( log(1 + raw) )     # log 防止头部爆款碾压
```
- 权重：分享 α > 全网独立报道 β > 评论 η > 点击 μ（分享和多源报道最能代表真实热度）
- **全网独立报道数**：多少家**不同**媒体在报道该事件（去重后），这是最抗操纵的信号
- log 压缩 + min-max/分位数归一化到 0~1

**连续值参考：**
- 20+ 家独立媒体同报 + 高社交讨论：H≈0.9~1.0
- 5~10 家报道：H≈0.5~0.7
- 单一来源、零转发：H≈0.1~0.2

**输出 JSON：**
```json
{"hotness_score": 0.88, "independent_sources": 23, "share_count": 4200, "social_volume": "HIGH", "bot_suspected": false}
```

#### 正例

**GC-3.1（全网刷屏真热度）**：`TRUMP 币暴跌被 CoinDesk、律动、金十等 23 家媒体同步报道，Twitter 话题激增` → H=0.95，independent_sources=23。
**GC-3.2（中等热度）**：`某 meme 币社区活动，5 家垂直媒体报道，社交有一定讨论` → H=0.55。合理体现中等关注。

#### 反例

**BC-3.1（机器人刷量）**：`某新 meme 币在电报群被大量相同话术转发，评论区高度雷同`
错误：H=0.9（被转发量诱导）；正确：H=0.25（检测到刷量特征）。
归因：把水军/机器人刷量误判为真实热度。
规避：只统计**独立信源/独立账号**；同质化话术、单一群组集中爆发、账号注册时间雷同→判定刷量，H 封顶 0.3。

**BC-3.2（单一大号伪装广度）**：某 100 万粉 KOL 单条推文转发过万，但无其它媒体跟进
错误：H=0.85；正确：H≈0.45。
归因：把单一账号的粉丝量误当全网热度。
规避：热度核心是**独立信源数量**，单账号影响力单独计入（且降权），不等同全网广度；无多源跟进的单条内容热度封顶 0.5。

### 因子 4：权威性 Authority

**内涵定义**：
信源的**可信度与真实性**，主要用于"砍谣言、降噪音"，而非"抬官媒"。权威分级参考 NewsGuard（透明度/更正机制/所有权披露等 9 准则）和 MBFC（factual reporting 权重最高）的方法论，落到加密场景做本地化分层。核心：**看事实可靠性和信源透明度，而非粉丝数**。

**连续打分曲线（信源基分 × 验证系数，连续）：**
```
A = SourceBase(s) × VerifyFactor(c)
```
- **SourceBase 信源基分（连续，分层锚点）：**
  - 1.0：币安官方公告、SEC/美联储官网、彭博/路透
  - 0.8：CoinDesk、CoinTelegraph、律动、PANews、The Block、项目方官方 X
  - 0.5：链上监测账号（Lookonchain/慢雾）、认证行业 KOL
  - 0.25：普通认证自媒体
  - 0.1：匿名社区、无源自媒体
  - （锚点之间可连续插值，如有更正机制/署名一致性的媒体上浮）
- **VerifyFactor 验证系数（连续 0.2~1.0）：**
  - 多源交叉验证 + 官方域名/链上证据：1.0
  - 单源但信源可靠：0.8
  - 涉及监管决议但无官方域名佐证：0.2（强制降权）

**输出 JSON：**
```json
{"authority_score": 1.0, "source_base": 1.0, "verify_factor": 1.0, "source_level": "S", "is_official_verified": true}
```

#### 正例

**GC-4.1（官方源）**：`[Binance Announcement] 币安将上线 meme 板块新代币 $XYZ` → A=1.0，source_level=S。
**GC-4.2（链上监测中等权威）**：`Lookonchain 监测：某巨鲸地址 1 小时前买入 500 万美元 TRUMP` → A≈0.5×0.9=0.45。合理，链上账号权威中等但有链上证据佐证。

#### 反例

**BC-4.1（权威词汇诱导）**：`某 X 匿名账号附截图："SEC 已批准某 meme 币 ETF，今晚生效！"`
错误：A=0.8（被 "SEC/ETF" 诱导）；正确：A=0.15。
归因：被"权威机构名词"诱导，忽略"匿名账号"低权威源 + 无官方域名。
规避：提及监管决议但来源未附官方域名（sec.gov）或 S 级媒体前缀 → 权威分强制 ≤0.2。

**BC-4.2（高粉≠高权威）**：某 200 万粉营销号发布无署名无来源的"内部消息"
错误：A=0.7（被粉丝量诱导）；正确：A≈0.15。
归因：把受众规模当可信度（搜索方法论明确指出应 downweight raw audience size）。
规避：权威只看信源等级 + 事实透明度 + 验证，**粉丝数不计入**权威分。

### 因子 5：市场影响面 Market Impact

**内涵定义**：
内容对加密市场（尤其目标板块）**价格、流动性、清算风险**的实际冲击力。参考事件研究法（event study）：用异常收益（Abnormal Return）、波动率变化、流动性变化衡量。核心问题："这条新闻会不会真的让钱包里的钱变多变少"。

**★ v5.1 强制要求：先查市值，再打 M 分（基于 Balance Coin badcase）**
打 M 分前**必须先查询事件主体（币）的市值与直接影响的市场规模**，不得凭事件类型（黑客/监管/崩盘）默认给高分：
1. **查询动作为必选步骤**：通过 CoinMarketCap / CoinGecko / 币安行情 API 查询主体资产的流通市值、TVL、受影响资金额（被盗金额/清算金额/解锁金额），写入 `market_cap_usd` 与 `affected_capital_usd` 字段；查不到市值的未收录资产按微型币处理。
2. **市值分层封顶 ScopeFactor**（以直接受影响资产为准）：
   | 主体市值 / 受影响资金 | ScopeFactor 上限 |
   | :--- | :---: |
   | 板块级/大盘级事件（波及多数成分币） | 1.0 |
   | 主流币（市值 ≥ $10B） | 0.8 |
   | 中型币（$1B ~ $10B） | 0.6 |
   | 小币（$100M ~ $1B） | 0.4 |
   | 微型币（< $100M）或受影响资金 < $10M | **0.2** |
3. **市值封顶优先于事件类型锚点**："巨额黑客/监管制裁 → M≈1.0" 这类锚点只对市值/受影响资金达标的主体生效；微型币即使被黑客归零，对板块和绝大多数用户的钱包没有实质影响，M 不得超过 0.3（除非事件暴露的是**板块级共性风险**且 summary 明确论述传导路径，此时按风险预警类另行评估，上限 0.5）。

**连续打分曲线（三要素连乘，连续）：**
```
M = PriceImpact × ScopeFactor × SentimentStrength
```
- **PriceImpact（价格冲击，连续 0~1）**：事件关联资产的（预期或已发生）异常收益/波动幅度。参考历史同类事件或实时价格反应。黑客/监管/宏观超预期→高；日常观点→低。
- **ScopeFactor（影响范围，连续，受市值分层封顶）**：整个板块/大盘=1.0，多个代币=0.7，单一主流币=0.5，长尾单币=0.2；**必须先查询主体市值与受影响资金规模，按上方分层表封顶，市值封顶优先于事件类型锚点**。
- **SentimentStrength（情绪强度，连续）**：情绪极性的强度（|利多/利空|），纯中性事件影响弱。利空对持仓用户价值高（风险预警）。

**连续值锚点：**
- 1.0：巨额黑客、监管制裁/下架、宏观超预期、板块级普跌普涨
- 0.6：项目重要升级、大额融资、知名 KOL 清仓
- 0.2：行业日常观点、无实质动作合作
- 0.0：对该板块价格无实质影响

**输出 JSON：**
```json
{"impact_score": 0.9, "price_impact": 0.95, "scope_factor": 1.0, "sentiment_strength": 0.95, "impact_type": "HIGH", "affected_scope": "MEME_SECTOR", "direction": "BEARISH", "market_cap_usd": 8500000000, "affected_capital_usd": 1200000000, "cap_tier": "SECTOR_LEVEL"}
```

#### 正例

**GC-5.1（板块级冲击）**：`美国立法限制总统发币，整个政治 meme 板块普跌 15%+` → M=0.9（price_impact高、scope=板块、情绪强）。
**GC-5.2（中等影响）**：`某中型 meme 币宣布登陆二线交易所` → M≈0.35（单币、影响有限）。合理体现中等冲击。

#### 反例

**BC-5.1（泛科技误关联）**：`腾讯混元负责人离职创业，聚焦世界模型`
错误：M=0.7（误当 Web3 AI 板块利好）；正确：M=0.05。
归因：大模型泛化过度，把 Web2 科技人事变动误认为影响 crypto 价格。
规避：除非明确提及代币经济学/发币计划/与加密协议结合，否则传统科技巨头人事/技术动态冲击分最高 0.1。

**BC-5.2（长尾币夸大冲击）**：`某市值 50 万美元的微型 meme 币暴涨 300%`
错误：M=0.9（涨幅大）；正确：M≈0.2（scope_factor 低，长尾币影响面小）。
归因：只看涨跌幅，忽略影响范围。微型币暴涨对板块整体和多数用户无实质意义。
规避：ScopeFactor 对长尾/微型市值币强制降权（≤0.2），涨跌幅大但影响面小的不给高分。

**BC-5.3（安全事件未查市值虚高 M —— 评测实际 badcase，v5.1 新增）**：板块=基础架构
输入：`BNB Chain 稳定币 Balance Coin 遭预言机漏洞攻击，价格崩至 0.001 美元`
错误输出：`M=0.75`（"预言机攻击+稳定币崩盘"事件类型锚点直接给高分）
正确输出：`M≈0.25`（查询后：Balance Coin 市值/TVL 仅百万美元量级，属微型资产，ScopeFactor 封顶 0.2；作为预言机安全的板块级风险预警可适当上浮，但不超过 0.3）
归因：模型被"黑客/崩盘"等高冲击事件词诱导，跳过了"受影响资金到底有多少"的量级核查；一个几百万市值的微型稳定币归零，对板块价格和用户钱包的实际冲击接近于零。
规避：执行 v5.1 强制要求——先查 market_cap_usd / affected_capital_usd，再按市值分层封顶 ScopeFactor；事件类型锚点不得越过市值封顶。

## 三、超重去重（Heavy De-duplication）— 独立关键环节

> Lawrence 特别强调：**只要是同一事件，就必须只留一条。** 这是本 skill 的硬性要求，独立成章。

### 去重的三层机制

**第 1 层：事件指纹（Event Fingerprint）**
对每条内容生成事件指纹 = 核心实体集合 + 事件动作 + 关键数字。
```
fingerprint = { 主体实体, 事件类型, 关键数值(金额/涨跌幅/时间) }
例：{TRUMP, 立法限制发币, -18%} 
```
指纹完全一致 → 直接判定同一事件。

**第 2 层：语义向量聚类（Embedding Clustering）**
参考搜索到的事件去重方法（cosine 阈值 0.62~0.8 + 时间窗）：
```
1. 对每条内容(标题+首段+实体)生成 embedding 向量
2. 两两计算余弦相似度 cosine_sim
3. cosine_sim ≥ 0.75 → 判定同一事件（阈值可调，偏高保精度）
4. 传递闭包/DBSCAN 聚类：A~B 相似、B~C 相似 → A/B/C 同簇
5. 叠加时间窗约束：同簇内容需在 1~3 天窗口内
```

**第 3 层：跨语言/跨源归并**
中英文报道、不同媒体编译同一事件 → 归入同一 event_cluster_id。

### 同簇内"只留一条"的选择规则
一个 event_cluster 内，**只保留 1 条**，选择优先级：
```
1. 权威性 A 最高的（官方 > 头部媒体 > 自媒体）
2. 权威相同则选时效 T 最高的（首发 > 转载）
3. 再相同则选内容最完整的（summary 信息量最大）
其余全部折叠为子卡片（不进入 Top 3 排序）
```

### 去重输出 JSON
```json
{
  "event_cluster_id": "EV_20260723_TRUMP_LAW",
  "cluster_size": 5,
  "representative": "律动: 美国立法限制总统发币，TRUMP 跌 18%",
  "folded": ["MarsBit: 特朗普币立法...", "金十: TRUMP 下跌...", "..."],
  "dedup_method": "fingerprint+embedding(0.82)",
  "selection_reason": "权威最高(律动0.8)+首发时间最早"
}
```

### 去重反例（必须防住）
**DC-1（同事件多编译误留多条）**：律动、MarsBit、金十报道同一 TRUMP 立法事件
错误：三条都进 Top 3，占满全部位置；正确：归为 1 簇，只留权威最高的律动那条。
归因：仅靠标题词序差异，LLM 误判为独立事件。
规避：embedding 相似度 ≥0.75 强制归簇，**覆盖 AI 的独立判断**，同簇只出 1 条。

**DC-2（标点/同义改写变体 —— 线上最高频 badcase，v5 新增）**：
线上实例：Launchpool 板块第 1、3 条仅差一个冒号 vs 逗号（"Pendle 公布 H2 路线图：加码 RWA…" vs "Pendle 公布 H2 路线图，加码 RWA…"）；Solana 板块"LayerZero 和 Keeta 合作" vs "LayerZero 和 Keeta 达成合作"；AI 板块"Kaito AI：已与 X 公司达成数据合作协议" vs "Kaito AI 与 X 公司签订数据协议"；infrastructure 板块 Ondo×FINRA 事件 3 条全重。
错误：当作独立新闻同时展示。
归因：去重只比字面重合度，标点/词序/同义词（合作=签订=达成合作）的微小差异即可逃逸。
规避：去重前先做**标题归一化**：去标点、去信源前缀（"BlockBeats 消息，""ChainCatcher 消息，"）、同义动词归一（签订/达成/宣布合作 → 合作；获授权/获批准 → 获批）；归一化后提取《主体，动作，宾语》三元组，三元组一致 → **无条件同簇**，不依赖 embedding 阈值。

**DC-3（summary 自曝重复仍照常展示，v5 新增）**：
线上实例：AI 板块第 2 条 summary 写着"**同样是合作类消息**"、infrastructure 板块第 2 条写着"**这条新闻和上一条主题接近**"、第 3 条写着"**同类消息连续出现**"——模型已经意识到重复，却仍然输出了重复条目。
错误：把"发现重复"写进解读文案，而不是执行去重。
规避：新增**去重自检断言（self-check assertion）**：输出前对 Top3 两两检查归一化标题相似度与事件三元组；若 summary 草稿中出现"同类消息/再次出现/和上一条接近"等表述 → 触发回退，删除重复条并从候选池补位；无可补位时**宁可只出 2 条，也不出重复条**。

## 四、完整工作流

**输入**：板块名（如 MEME）+ 候选内容集合 {c1...cN}
**输出**：与板块最相关、互不重复的 **Top 3** 内容

```
输入：板块名 t + 候选内容 {c1, c2, ..., cN}
        │
        ▼
【Step 1】实体 & 情绪 & 体裁提取（逐条）
  - 抽取实体：代币Ticker/项目/人物/机构/地区
  - 打体裁标签 content_genre（EVENT/DATA/ANALYSIS/ROUNDUP/PROMO/PRICE_NOISE），ROUNDUP 直接淘汰
  - 判定主语/核心议题是否为板块 t（算 Focus 主角度 + 传导链长度 transmission_hops）
  - 按板块类型（赛道型/公链生态型/平台机制型）选择相关性锚点（补充定义 B）
  - 情绪提取：极性(利多/利空/中性) + 强度
  - 币安API白名单 + Top200市值 做实体消歧（防同名误绑）；ticker 输出过校验层（补充定义 C）
        │
        ▼
【Step 2】标签生成并记录（逐条 → 结构化 JSON）
  - 相关性：relevance_score + entity_match + semantic + focus_ratio
  - 时效：timeliness_score + content_type + 真实发布时间
  - 热度：hotness_score + independent_sources + bot_suspected
  - 权威：authority_score + source_level + verify_factor
  - 影响面：impact_score + price_impact + scope + direction（先查 market_cap_usd / affected_capital_usd，市值分层封顶 ScopeFactor）
  - 内容 summary（一句话）+ 事件指纹 fingerprint
        │
        ▼
【Step 3】硬门 + 打分（逐条）
  - 硬门：Rel < 0.5 → Score=0，直接淘汰
  - 打分：Score = Rel^1.5 × (0.25*T + 0.25*H + 0.20*A + 0.30*M)
        │
        ▼
【Step 4】★超重去重（关键，必须彻底）
  - 标题归一化（去标点/去信源前缀/同义动词归一）→ 事件三元组一致无条件同簇（DC-2）
  - 事件指纹匹配 + Embedding 聚类(cosine≥0.75) + 时间窗
  - 传递闭包成簇 → 每簇只留 1 条（权威>时效>完整度）
  - 其余折叠子卡片，不参与后续排序
  - 输出前去重自检断言：summary 中出现"同类消息/再次出现"→回退重去重（DC-3）
        │
        ▼
【Step 5】适度混排 + 召回最多 Top 3（宁缺毋滥：存活 <3 条则只出存活条数，0 条输出空结果+empty_reason）
  在 Score 排序基础上做整体体验校准：
  - 多样性：Top3 必须来自 ≥2 个不同事件簇（去重已保证）
  - 丰富度：优先覆盖不同子话题（价格/监管/生态/观点）
  - 重要性保底：至少 1 条高影响面(M≥0.7)
  - 有用性 & 观点优先：有实质信息 > 纯情绪宣发
  - 相关性红线：Rel<0.5 绝不进 Top3（硬门已保证）
        │
        ▼
输出：Top 3（含 summary、各因子标签、Score、入选理由、被去重折叠的条目）
```

### 输出内容规范（v5 新增，对齐线上卡片样式：标题 + 总结 + 相关 ticker）

1. **标题**：完整重写为可独立理解的一句话（≤30 字），包含主体+动作+关键数字；**禁止直接截断原文**（线上 badcase："Ondo Finance 宣布其在 SEC 注册的经…"）；去掉"XX 消息，"类信源前缀。
2. **总结**：2~3 句，回答"这事对该板块意味着什么"：第一句事实定性，第二句对板块价格/情绪/资金的影响方向，可选第三句风险提示。禁止：①"对 X 板块来说"式硬揰（BC-1.4）；②"同类消息再次出现"式自曝重复（DC-3）；③空泛表述（"需要继续观察"不能单独成句）。
3. **related_tickers**：只列事件主体/直接受体代币，且必须通过补充定义 C 校验；与板块成分币无交集时需重新审视 Rel。

## 五、关键设计原则（Cheat Sheet）

1. **相关性双重把关**：硬门（Rel<0.5 淘汰）+ 外层乘子（Rel^1.5 锐化）。
2. **只有"板块是主角"才给高相关分**：Focus 主角度判定，顺带提及/同名误绑/跨板块一律压制；相关性对原文打分，"对 X 板块来说"式改写不能抬分。
3. **体裁先行**：ROUNDUP/PROMO/PRICE_NOISE 从源头限制 Rel 上限，汇总盘点类直接淘汰。
4. **板块类型化相关性**：赛道型/公链生态型/平台机制型各有"主角"锚点，机制型板块禁止"叙事相近"泛化，传导链 ≥2 跳 Rel 封顶 0.4。
5. **所有因子连续打分**：指数衰减、log 压缩、连乘合成，不是离散档位。
6. **权威主要用于降噪**：权重 0.20，看事实透明度不看粉丝数。
7. **影响面主导排序，但必须先查市值**：权重 0.30，看价格冲击×范围×情绪强度；打分前必须查询主体市值与受影响资金规模（CMC/CoinGecko/币安行情），微型币（<$100M）即使黑客归零 M 也封顶 0.3，事件类型锚点不得越过市值封顶。
8. **超重去重是硬要求**：标题归一化+指纹+向量+时间窗，同一事件只留 1 条；自检断言兼底，宁缺毋重。
9. **ticker 输出校验**：只列事件主体/直接受体，与成分币白名单交叉验证。
10. **最终混排过体验校准**：多样性、丰富度、重要性、有用性、观点；标题完整不截断。
11. **宁缺毋滥**：3 条是上限不是 KPI；无相关内容不出，出 0/1/2 条都合法；禁止为凑数降门槛、硬揰、重复充数。

## 附：公式字符版（便于复制，无乱码）
```
硬门：若 Rel < 0.5 → Score = 0
打分：Score = (Rel^1.5) × (0.25×时效 + 0.25×热度 + 0.20×权威 + 0.30×影响面)
去重：事件指纹 + Embedding(cosine≥0.75) + 时间窗 → 同簇只留1条
召回：去重后按 Score 排序，过体验校准，取 Top 3
```
