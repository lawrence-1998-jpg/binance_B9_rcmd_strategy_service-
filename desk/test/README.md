# 案头的行为测试

    cd desk
    npm test                  # 跑全套（会自己先构建、起服务）
    npm test -- pend flow2    # 只跑指定的几条

**31 个套件 / 337 条断言**，外加 8 个只出测量值、不出断言的探针。

## 为什么这些东西在仓库里

以前它们只存在于一次会话的临时目录。也就是说每一次「全绿」除了那次会话
**谁都复现不了** —— 包括仓库的主人和下一个来干活的人。
一套没人能重跑的测试，等于一句没人能核对的承诺。

## 几条自己踩出来的规矩

**`✓0` 不叫通过，叫没说话。** 探针类脚本只打印测量值、一条断言都不出，
而它们印出来的 `✓0` 跟真绿长得一模一样，被算进过「全绿 N 条」。
现在单独标「探针，没有断言」，并且不计入总数。

**脚本崩了和断言失败必须分开。** 早先那个一行 `for` 循环只数 ✓/✗ 的行数，
脚本中途崩掉照样报「✗0」。`run-all.sh` 认退出码，崩了单独标「💥」并打尾部日志。

**被测的 dist 必须是干净的。** `migrate` / `swupdate` 为了测升级路径会把 dist
换成别的版本。它俩一旦中途崩了，后面每一条套件测的都是错东西 —— 曾经因此
五个套件一起变红，而它们单独跑全是绿的，差一点就去改了没坏的代码。
现在每跑完一条就比对一次，动过就还原，还原不成直接停。

**每条新检查都要先证明它会红。** 加一条检查之后，把对应的代码改坏一次，
确认它真的报警，再改回来。不这么做的话，写出一条永远不会红的检查太容易了 ——
比如曾经有一条私人照片扫描，只认 `jpg/heic`，而仓库里一张都没有，
它扫了 0 个文件报了个绿。

毒化的时候注意：这个项目开了 `noUnusedLocals`，很多「改坏一次」的写法会让
**构建直接挂掉**，测试根本没跑，而只数 `✗` 行的验证脚本会打印一片空白，
看起来像「没问题」。要么挑一个仍然能编译的改法（把比较符反过来、把常数
改掉），要么让验证脚本在拿不到结果时自己喊出来。

**动过 UI 就拍一张看看。** 这套断言问不出两类问题，而它们都真的发生过：

- *「这东西看起来像不像能点」* —— `.chip` 和 `.btn.quiet` 的默认底色都是
  `--well`，放进底色也是 `--well` 的容器（`.fade-offer` / `.conf-box`）里就
  跟底融成一片，读起来是几行粗体字。**同一个陷阱咬过两次**，两次都是
  380 多条断言全绿、截图才发现。规矩写在 base.css 里了：坐在 `--well` 上的
  控件，底色改 `--card`。
- *「这个数看着对不对」* —— 「这 7 天你动了 8 天」印出来过。当时 11 条断言
  全绿，因为用例里的日子太少凑不满窗口。补不变量断言（天数不能超过窗口）
  之前，只有眼睛能发现。

三次都是同一个形状：**测试验的是「有没有按我写的规则跑」，不是「跑出来的
东西是不是人话」。** 后者只能看。

## 环境

- `playwright` 的版本在 `package.json` 里**钉死**（不带 `^`）：它必须跟机器上
  装的浏览器对上，浮动版本会直接起不来浏览器。
- `DESK_URL=...` 可以指着一个已经跑起来的地址，跳过自动构建和起服务。
- `DESK_PORT=8766` 换端口。
- 截图落在 `test/shots/`（不进版本库；CI 里测试挂了会作为 artifact 传上来）。

## 不在默认那批里的

- **`migrate`** —— 测「装着旧版的手机能不能升到新版」，需要两个历史版本的
  构建产物当基线（`/tmp/old-dist`、`/tmp/new-dist`）。缺基线时它**直接报错**，
  不会悄悄跳过。要跑就先照 `migrate.mjs` 顶部的说明把基线建好：
  `git worktree` 检出 fonts 自托管之前那个提交，构建，放到 `/tmp/old-dist`。
