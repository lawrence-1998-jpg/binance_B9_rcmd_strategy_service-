五因子重要性打分
影响面 / 时效 / 热度 / 权威 / 质量加权，输出 0–1 连续分 + S/A/B/C/D 分级，下游直接按分排序。

重要性打分模型 · Macro Insight v1

Score = 0.35·M + 0.20·T + 0.15·H + 0.15·A + 0.15·Q

0.35
T时效性
0.20

0.15

0.15
因子口径：M 为事件对价格与资金流的潜在影响；T 按 24 小时半衰期衰减； H = 0.6×log 归一(社交互动) + 0.4×min(信源数/8, 1)；A 为信源权威分级； Q 区分深度分析 > 快讯 > 价格播报。无硬门限，保底供给。

Dedup

去重管线 · 项目最大的一处重构

重构前实测 48.7% 冗余
四层管线
1
标题归一化 — 去标点、统一大小写与全半角后精确比对，拦同源重复推送
2
事件三元组指纹 — LLM 输出「主体 / 动作 / 日期」，sha256 派生稳定 ID
3
embedding 语义聚类 — 256 维真向量，cosine ≥ 0.82 并簇
4
跨轮归并 — 写库前与历史比对，命中则合并信源而非新增行

API

REST API 接入说明

Base URL
—

HTTP / JSON，UTF-8。全部端点均为 GET，幂等无副作用。 响应体统一为 {"data": [...], "meta": {...}}（详情端点直接返回对象）。

鉴权 · 两种方式
① 请求头（程序化调用推荐）
Authorization: Bearer ***REMOVED***
② URL 参数（浏览器直接点开）
?token=***REMOVED***
方式 ② 是为非技术同事加的 —— 浏览器地址栏发不出自定义请求头。代价是 token 会进浏览器历史与访问日志； 当前 API 本身即 HTTP 明文 + 单一静态 token，安全模型是「仅内部可信网络使用」。 生产化时需连同 HTTPS 与分级 token 一并改造。

数据更新节奏

        

          Pipeline 每天 UTC 00:00 / 12:00 各跑一轮，单轮耗时约 15–20 分钟。
          建议下游按 time_get_data 增量拉取，
          或直接 sort=date 取最新。
        

        

          同一事件跨轮会原地更新（信源合并、分数刷新），id 保持稳定 ——
          下游可安全地以 id 作为主键做 upsert，不会产生重复条目。
