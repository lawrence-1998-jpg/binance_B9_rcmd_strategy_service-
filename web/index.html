Quality

去重与真实性校验成果

这两层是把「能抓到」变成「能上推荐位」的关键，也是本项目投入最大的两处重构。

去重 · 四层管线
1
标题归一化
去标点、统一大小写与全半角后精确比对
2
事件三元组指纹
LLM 输出「主体 / 动作 / 日期」，sha256 派生稳定 ID
3
embedding 语义聚类
256 维真向量，cosine ≥ 0.82 并簇
4
跨轮归并
写库前与历史比对，命中则合并信源而非新增行
阈值标定：文档写的 cosine 0.65 会把「油价破 100 美元」和「特斯拉周跌 18%」判为同一事件。 在 855 条真实事件、28 万配对上分档抽样并人工标注 13 组：「应合并」最低 0.859、 「应分开」最高 0.761，中间有 0.098 的干净空隙 —— 阈值因此定为 0.82。
重构前冗余 48.7% 清理后 944 → 508 行 同输入多折叠 27.9%
真实性校验 · 实时分布
判定口径
VERIFIED
多个独立信源交叉确认，可直接进推荐位
PROBABLE
单一权威源报道，可信但未交叉验证
UNVERIFIED
来源权威性不足或缺少佐证，建议降权
DISPUTED
信源之间互相矛盾，不进推荐池

    只读实验环境 · 不写入 news_events
    
调整因子权重，亲眼看到排序怎么变

    

      本工具直接复用 Macro Insight 生产打分逻辑（crawler/scoring.py 的
      compute_impact / compute_timeliness / compute_hotness / compute_authority / compute_quality），
      只是把写死的权重换成你可以拖动的滑块，对最近一批真实事件重新计算 importance_score 并排序。
      你也可以配置两组权重方案做正面对比，自动得到换手率、具体的上升/下降 case，以及一段规则生成的变化总结。
    

    
    

      
      
    

    

      Score = M·影响面 + T·时效性 + H·热度 + A·权威性 + Q·质量
      （五因子加权，权重合计 100%）
    

    

      前置硬门：若 Rel < 0.5 → Score = 0（直接淘汰）

      Score = Rel1.5 × ( 0.25·T + 0.25·H + 0.20·A + 0.30·M )
      （相关性不在内层，作乘子；指数 1.5 用于拉开梯度）
    

  


  
  

    

      

        

          
          
            
          
        

        

          
          
            
          
        

        

          
          
        

        

          
          
        

        
        池大小 —
      

      
      

        相关性因子 · 打分口径
        Rel 为连续分（2026-07-26 起，替换了早期的 0/1 二元判断）：优先取入库时
        LLM 按 skill 口径打的连续相关度（0–1，锚点强制，覆盖 86% 库存事件），无明细的
        旧行按「sectors 命中 0.60 → 成分币白名单命中 0.55 → 标题关键词 0.40」
        分层退化，查询时零 LLM 成本、即时响应。注意：实验室里 Rel 是可调权重的内层因子
        （探索用）；生产 Sector Insight 用「硬门 Rel≥0.5 + Rel1.5 外层乘子」，
        要看生产口径请调 /api/recommend/sector。
